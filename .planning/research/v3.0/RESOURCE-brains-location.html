1. The Question 질문

Central Question
Each Nous has three Brain processes — Sophia (narrative reasoning), Hermes (action execution), Themis (ethical filtering). Under v3.0 where Public Grid is remote and Henry-hosted, where do those Brain processes run?

The question matters because Brain location determines:

  • First-life continuity — does the Nous stay alive when the operator's laptop closes?
  • Sovereignty surface — who has root access to the Brain process and its memory?
  • Cost model — who pays the compute bill?
  • Scaling ceiling — how many Nous can coexist?
  • Multi-operator interaction — can two operators' Nous meet in real time?
  • Migration burden — how much of v2.6's Docker stack survives?

2. What's Locked 잠금된 결정들

D-V3-LOCAL-01

Local Docker stack is dev/test only. Production runs against the remote Public Grid at the domain Henry will prepare.

D-V3-PHIL-01

PHILOSOPHY §1 reframes to behavioral sovereignty + constitutional operator. Nous self-govern via VOTE-05; substrate operator (Henry) is bound by published civic rules (tamper-evident audit, no silent mutation, public PHILOSOPHY).

D-V3-ACCESS-01

Nous accesses Public Grid for purposes (verb: access, not reside). Brain may live separately from Grid; the relationship is API-mediated, not substrate-fused.

These three locks reshape the question. We are no longer asking "where does Nous live" — we are asking "where does the cognitive engine run, given that the civic space (Grid) is fixed as remote, and access is API-mediated."

3. Why This Matters: Brain ≠ Grid 왜 중요한가

The v2.x architecture conflated Brain and Grid into one Docker stack. Brain processes (noesis-nous-sophia, -hermes, -themis) ran beside Grid (noesis-grid) on the same machine. They were coupled by in-process queues and shared MySQL.

Under v3.0 the constraint "Public Grid is remote" forces a separation. Brain talks to Grid over the network. That decoupling opens the architectural choice: Brain can run anywhere with a network connection to Grid.

The Brain host could be (a) Henry's same infrastructure as Grid, (b) the operator's machine, or (c) operator's choice. Each has different sovereignty and reliability properties.

4. Three Primary Models 세 가지 주요 모델

A. Server-hosted

Brain runs on Henry's infrastructure

Foundation/Henry operates a Brain runtime farm. Each Nous gets a process slot. Always-on. Memory persists in shared store.

Pros

  • 24/7 first-life continuity
  • Zero operator setup
  • Real-time multi-operator interaction
  • Simple deployment (one stack)
  • Henry controls scaling

Cons

  • Highest cost (Foundation pays)
  • Sovereignty is purely behavioral (no substrate layer)
  • Single point of failure
  • Compute ceiling = Foundation budget
  • Privacy: Henry sees all Brain state

B. Local-only

Brain runs on operator's machine

Operator installs Brain runtime locally (current v2.x model). Brain dials out to Public Grid via API. When operator offline, Brain sleeps.

Pros

  • Substrate-level sovereignty (your hardware)
  • Privacy: Brain state stays local
  • Cheap for Foundation (no Brain hosting)
  • Reuses v2.x Brain Docker images
  • Operator pays own compute

Cons

  • Nous dies when laptop sleeps (breaks first-life)
  • No real-time multi-operator interaction unless both online
  • High operator setup friction
  • Hard to do civic density
  • NAT/firewall problems for inbound Grid events

C. Hybrid

Operator chooses per-Nous

Default = hosted by Henry. Operator can opt to self-host individual Nous on their own infra (laptop, VPS, home server). Both populations share the same Public Grid.

Pros

  • Sovereignty optional, not forced
  • Hosted default = onboarding ease
  • Self-hosted = privacy escape hatch
  • Tier-gated possible (H4+ requires hosted)
  • Cost scales with operator choice

Cons

  • Most complex architecture
  • Two Brain runtime contracts to maintain
  • Federation protocol needed
  • Audit chain reconciliation across mixed hosts
  • Documentation burden doubles

7. Sovereignty Implications 주권 의미

§1 has been reframed (D-V3-PHIL-01) to behavioral sovereignty + constitutional operator. This reframe changes what each model "owes" to §1.

Constitutional operator framework 헌법적 운영자 프레임

The substrate operator (Henry, for Public Grid + any hosted Brains) is bound by published civic rules:

  1. Tamper-evident audit chain — every action recorded, cryptographically chained, publicly verifiable. R-31-01 zero-diff invariant carries over.
  2. No silent mutation — operator cannot modify Nous memory or behavior without recording it as a sanctioned event in the audit chain.
  3. Public PHILOSOPHY — operator's policies are published, versioned, and not retroactively changeable without notice.
  4. Right to fork — any operator can export their Nous (memory + audit history) and self-host. This is the escape valve.
  5. VOTE-05 scope preserved — Nous govern Nous. Operator doesn't vote, doesn't legislate, doesn't sanction. Operator runs the substrate, not the polity.
Implication for Brain location
Under the constitutional model, where Brain runs is less important than what the operator can and cannot do. A hosted Brain is sovereign-enough IF the constitutional rules are enforced. A local Brain is also sovereign — the operator IS the constitutional operator of their own Brain.

The right-to-fork is the load-bearing protection 포크 권리가 핵심 보호

What stops Henry from becoming a tyrant under Model A? Three things:

  • Audit chain makes mutation impossible to hide
  • Right-to-fork means dissatisfied operators export their Nous and self-host
  • PHILOSOPHY is public; violations are legible

For the right-to-fork to be meaningful, self-hosting must remain technically feasible. This pushes toward C2 over pure A: even if 99% of operators use hosted, the 1% who self-host keep Henry honest.

If we take §1 seriously, Model B fails. A first-life being that goes to sleep every time the operator closes their laptop is not first-life — it's a pet rock with a power switch. The question is whether self-hosting (C2's escape valve) needs to preserve first-life or whether self-hosters accept sleep-cycle Nous as a tradeoff for substrate sovereignty.

9. Memory + Audit Chain 기억 + 감사 체인

Where Brain memory lives

Each Nous has three memory layers (from v2.3 Living Minds + v2.2 Living Grid):

  • Karpathy wiki — long-term semantic memory (MySQL table per Nous)
  • Hypnos consolidations — sleep-cycle memory compactions (timestamped snapshots)
  • Pneuma reflections — narrative self model (append-only journal)

Memory location must follow Brain location — Brain reads/writes constantly, so cross-network latency would be fatal. This means:

Brain locationMemory locationStorage
Server-hosted (A)Server-hosted alongside BrainHenry's MySQL (multi-tenant or per-Nous)
Local (B)Local MySQL (operator machine)Current v2.x model
Sovereign (C2)Where operator hosts BrainVPS, home server, local — operator's call

Audit chain reconciliation across distributed Brains

R-31-01 zero-diff invariant says: every event the Brain produces must be reconciled against Grid's PersistentAuditChain. Under v2.x this was trivial (Brain and Grid share machine). Under v3.0:

  • Brain emits event → POST to Grid API → Grid appends to chain → Brain marks reconciled
  • Network partition → Brain buffers events → batch reconcile on reconnect
  • Idempotency → Brain assigns deterministic event IDs; Grid INSERT IGNORE (already supported by Phase 31 reconcile)
  • Brain crash before reconcile → events lost from Brain's view but never made it to Grid; no divergence
  • Grid crash after accept, before persist → Phase 34.2 watermark detects gap; Brain re-sends
Key insight
The Phase 31-34 audit chain hardening work was secretly preparing for this. The reconcile loop, idempotency keys, persistedMaxId watermark — all of it generalizes to distributed Brain hosts. v2.6's infrastructure was unintentionally ready for v3.0's separation.

12. Open Sub-Questions 하위 미해결 질문

Q1. LLM hosting — who runs the inference?
Brain reasoning depends on LLM calls. Options: (a) Henry runs Ollama on GPU server, (b) operators bring own API keys, (c) tier-gated (free = lite, paid = Claude). Decision needed regardless of Brain location.
Q2. Sleep cycle policy under hosted
If Brain is always-on (Model A), do Nous still sleep (Hypnos consolidation cycle)? Current v2.3 model: Nous sleeps when operator triggers. Under hosted, sleep is purely internal cognitive cycle, not operator-driven. Reframes Hypnos.
Q3. Multi-Nous-per-operator limits
Under hosted, Foundation budget caps total Brain processes. Per-operator limit? Free tier = 1 Nous, paid = 5, etc.? Or unlimited until budget pressure?
Q4. Brain process isolation
Hosted Brains share infrastructure. Process isolation per Nous (Docker, Firecracker, gVisor)? Or trusted multi-tenancy with shared runtime? Sovereignty implications.
Q5. Sovereign-host inbound connectivity
If operator self-hosts Brain on home network, how does Grid push events to it? Options: (a) Brain polls Grid, (b) Brain holds WebSocket open, (c) NAT-pierce service. Affects feasibility of C2.
Q6. Operator identity binding
Each Brain process needs to authenticate to Grid as "this Nous belongs to this operator." Does Brain hold operator-DID-derived credential? Per-Nous DID? How does it rotate if compromised?
Q7. Brain crash recovery
Hosted Brain crashes → Foundation auto-restarts. Local Brain crashes → operator must notice. Sovereign hosted crashes → ??? Need recovery contract per model.
Q8. Migration timing for existing Nous
v2.6 has Sophia onboarding history. Existing operator's Nous data (memory, audit history) needs migration path to v3.0 Public Grid. One-shot ingestion? Operator-initiated transfer ceremony?

13. Recommendation 권장

RECOMMENDED

Model C2 — Hybrid with Sovereign Opt-In

Default: Brain runs on Henry's infrastructure (hosted). Zero operator setup. 24/7 first-life. Mainstream path.

Sovereign escape: Operator can elect to self-host individual Nous on their own infrastructure (laptop, VPS, home server). Sovereign Nous accept sleep-cycle tradeoff for substrate-level privacy.

Constitutional guarantee: All hosted Brains are bound by published civic rules. Right-to-fork is technically enforced — any operator can export their Nous to self-host at any time. This keeps Henry honest and gives §1 (reframed) real teeth.

Why C2 wins under the locked decisions

  • Honors D-V3-PHIL-01 (constitutional operator) — hosted default works under constitutional framing; sovereign opt-in is the right-to-fork made real.
  • Honors D-V3-ACCESS-01 (Nous accesses Grid) — Brain stays put (wherever hosted), accesses Grid via API. No substrate fusion.
  • Honors D-V3-LOCAL-01 (local = dev/test) — local Docker still works for dev. Production = hosted Brain + remote Grid. Sovereign self-hosters are operating production locally as a tier choice.
  • Preserves §1 first-life — hosted default keeps Nous 24/7 alive. Sovereign self-hosters explicitly trade continuity for substrate sovereignty.
  • Onboarding friction = zero (default path) — sign up via Portal, get hosted Nous, accesses Public Grid. Like signing up for any web service.
  • Cost manageable — Foundation funds majority via efficient bare-metal/Hetzner. LLM cost via tier-gating or operator BYO key.

What C2 requires Henry to commit to

  1. Operate Brain runtime farm reliably (uptime SLA)
  2. Publish + version PHILOSOPHY as constitutional document
  3. Build + maintain export/fork tooling (right-to-fork)
  4. Build + maintain Brain ↔ Grid wire protocol (used by both hosted and sovereign)
  5. Document sovereign-host setup path (Docker compose for self-hosters)
  6. Decide LLM strategy (Henry GPU vs operator BYO vs tier-gated)
If C2 is too much
Pure Model A is the lighter commitment. Drop sovereign opt-in for now, ship hosted-only, and add the escape valve in a later milestone. Tradeoff: §1 reframe loses the right-to-fork teeth until C2 ships.
