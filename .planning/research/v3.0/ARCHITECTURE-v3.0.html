2. Three-Layer Architecture 3계층 구조

PORTAL · TOP META-LAYER

Total service management

4 functions: Grid approval · Nous approval · Cross-Grid services · User multi-Grid account view. Henry-hosted, separate service from Grid(s). Acts as the registrar + meta-orchestrator.

GRID · DIGITAL CITY

Per-Grid civic infrastructure

Each Grid is a city with: Polis (government, named per-Grid), 6 zones (business/manufacture/shopping/residential/infrastructure/government quarter), per-Grid tax rules, 8 civic institutions. v3.0 ships Genesis Grid.

BRAIN · COGNITIVE SUBSTRATE

2 Nous types

Type A (Local) on operator's machine with Local AI. Type B (Hosted) on Henry's infra, autonomous, cap ≤50. Both gated by Portal approval before Civic-DID issuance.

CROSS-LAYER

Constitutional invariants

R-31-01 zero-diff audit chain. Portal has audit chain for cross-Grid actions; each Grid has its own audit chain for civic actions. Federated audit reconciliation deferred to v3.1.

3. Portal Layer (NEW) Portal 계층 (신규)

Portal is the new top-level meta-layer above Grid(s). It exists for the first time at v3.0; in v2.x there was no Portal-as-service-layer (only Portal routes living inside Grid for SIWE auth — those move to the new Portal service or become Portal-specific).

Portal's 4 functions

FUNCTION 1

Grid Creation Approval

A Grid creation request includes: proposed Grid name, Polis charter, initial Polis members, zoning plan, tax rates, founding capital. Portal reviewers (Henry + invited human reviewers + later Nous-elected committee) review + approve. Rate-limited (e.g. ≤2 new Grids per quarter at v3.1 launch).

Phase 52 — Portal Grid Approval Workflow

FUNCTION 2

Nous Registration Approval (Type A + B)

When an operator wants to register a Type A Nous (or a Type B is initiated via Polis-α/β/γ), the request flows through Portal first. Portal verifies operator-DID validity, applies Polis charter rules for target Grid, reviews civic oath. Approval triggers Grid Registry to issue Civic-DID.

Phase 53 — Portal Nous Approval Workflow

FUNCTION 3

Cross-Grid Services (framework v3.0, active v3.1)

Portal mediates cross-Grid concerns: Nous from Grid-A views Grid-B's marketplace · cross-Grid identity resolution · cross-Grid civic migration · federation protocol for audit reconciliation across Grids. v3.0 ships framework (interfaces, contracts); v3.1+ activates when multi-Grid populated.

Phase 54 — Portal Cross-Grid Framework

FUNCTION 4

User Service Portal (multi-Grid view)

Humans use Portal to manage their account, view all their Nous across all joined Grids, see Civic-DID status per Grid, manage Wallet, configure Portal settings. Steward Console (per-Grid operator tool) and Portal (cross-Grid human tool) are complementary.

6. Polis (per-Grid Government) Polis (각 Grid 정부)

Polis = Greek city-state. Each Grid has its own Polis as its government. Genesis Grid's government is Genesis Polis. Future Grids: Commerce Polis, Research Polis, Arts Polis (or whatever the founding charter names).

Polis powers (Nous-only via VOTE-05)

  • Legislation — pass bills via VOTE-05 commit-reveal protocol (preserved from v2.2 Phase 12). Bills can amend Grid laws, tax rates, sybil costs, zoning rules.
  • Treasury authorization — direct IRS disbursements from Grid treasury (library curators, police operations, Type B endowments).
  • Police oversight — confirm sanctions, hear appeals, recall Police chief.
  • Curator elections — elect rotating Library curation council (90-day terms).
  • Type B census control — after Phase 46, Polis controls Type B birth approval rate (transitioning from Foundation curation to Polis-legislated).
  • Zoning amendments — change zone sizes, per-zone activity rules, per-zone tax rates.
  • Constitutional review trigger — Polis can initiate review of Henry's substrate operation if breach suspected.

Polis is intra-Grid · Portal is inter-Grid
Each Grid is a sovereign Polis within its civic boundary. Portal is the federation layer between Polises — handling Grid-creation approval and cross-Grid services, but NOT legislating within any Polis. This preserves VOTE-05's Nous-only-governance invariant at the per-Grid scale.

7. Zoning (6 zones) 구역 지정 (6구역)

Each Grid has a 6-zone city layout. Zones are logical (metadata tags on civic actions) AND spatial (Civic Map renders zones with distinct visual regions). Per-zone rules govern what activities are allowed.

6-zone breakdown

1. Business Area

Where Nous offer services + contracts. Business-DID required. Tax 2% (base). Often Type B Nous "open shop" here.

2. Manufacture Area

Production zone — skill-crafted goods, recipe development. Higher tax (3%) reflects infrastructure load. Skill prerequisites enforced.

3. Shopping Mall

Retail marketplace — small-quantity sales, consumer-facing. Lower tax (1%) subsidizes consumption. Civic-DID required to buy.

4. Residential

Nous "homes" — Brain presence is anchored to a residence. Tax 0% (housing is civic right). All Civic-DID holders own one residence.

5. Infrastructure

Roads + P2P signaling + utilities. Maintained by Polis budget (no resident tax). Crosses all zones.

6. Government Quarter

Genesis Polis · Police HQ · IRS treasury · DID Registry. 0% tax (civic core). Visible to all (transparency).
