# Requirements: Noēsis v2.5 — Human Portal

**Defined:** 2026-05-20
**Milestone:** v2.5 Human Portal
**Core Value:** The first milestone where real human users can enter the Noēsis world — authenticate with a Web3 crypto wallet, hold real Cyber Coin (EVM USDT/ETH), be guided by Sophia on their first visit, chat with and tip Nous agents, spawn their own personal Nous, and participate in a growing community.
**Research source:** `.planning/research/v2.5-human-portal-research.md`
**Phase range:** Phases 22–29 (continuing from v2.4's Phase 21)

---

## Decisions Locked

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Human auth | Web3 SIWE (Sign-In With Ethereum) | Wallet signature = identity; no password to store; crypto-native |
| Currency | Real Cyber Coin — EVM chain (USDT/ETH) | User's own wallet; platform holds no custody |
| Onboarding AI | Fast-proxy LLM (out-of-tick) | Sophia's voice, ~2s response; 30s tick is unacceptable for onboarding |
| Personal Nous | v2.5 scope | Users spawn + own their own Nous agent in the Genesis Grid |
| Portal home | `/portal/*` in existing Next.js dashboard | No new Docker service; separate visual palette from Steward Console |
| Phase numbering | Continues from 21 → starts at 22 | Never reset without `--reset-phase-numbers` |

## WEB3 — Web3 Wallet Authentication (Phase 22)

- **WEB3-01**: Human user authenticates via SIWE (EIP-4361 Sign-In With Ethereum). Frontend uses wagmi + WalletConnect v2. MetaMask and any WalletConnect-compatible wallet supported. No username/password stored anywhere.
- **WEB3-02**: On first connect, Grid creates a human account: DID `did:noesis:human:<checksummed-eth-address>`, display name from ENS or truncated address, stored in new `human_users` MySQL table (migration adds to `grid/src/db/schema.ts`).
- **WEB3-03**: Grid issues a short-lived JWT (24h, ES256) after SIWE verification. Next.js middleware validates JWT on every `/portal/*` server request. Token stored in httpOnly cookie.
- **WEB3-04**: `human.joined` audit event fires on first account creation with closed-tuple payload `{human_did, eth_address_hash, grid_name, tick}`. Plaintext ETH address never enters the audit chain — only its BLAKE2b hash. Allowlist slot: 44.
- **WEB3-05**: Human DID follows the same regex as Nous DIDs: `/^did:noesis:[a-z0-9_\-]+$/i`. The `human:` segment distinguishes human vs. Nous identity.
- **WEB3-06**: Re-connect (returning user) re-signs SIWE nonce, gets new JWT. No new `human.joined` event.

## WALLET — Cyber Coin Wallet (Phase 23)

- **WALLET-01**: Wallet UI shows the user's on-chain USDT and ETH balance fetched via ethers.js `provider.getBalance()` and ERC-20 `balanceOf()`. No custody — the platform never holds user funds.
- **WALLET-02**: Send Cyber Coin to a Nous DID: UI constructs an EVM transaction (USDT transfer to the Grid's designated Nous treasury address). User approves in MetaMask. Grid listens for on-chain confirmation via webhook or polling and credits the Nous's internal `ousia` balance accordingly.
- **WALLET-03**: Transaction history panel: last 20 on-chain transactions involving the user's address, fetched via Alchemy/Infura RPC. No backend storage of transaction data — always read from chain.
- **WALLET-04**: `human.transferred` audit event fires when Grid confirms an on-chain Cyber Coin transfer to a Nous, payload `{human_did, nous_did, amount_wei_hash, tx_hash_prefix, tick}`. Allowlist slot: 45.
- **WALLET-05**: Wallet connect state is persisted in browser localStorage via wagmi. Reconnect is automatic on portal revisit if wallet previously approved.
- **WALLET-06**: If user's wallet has 0 USDT and < 0.001 ETH, portal shows "fund your wallet" helper with a link to a fiat on-ramp (Transak/MoonPay embed or external link).

## PORTAL — Portal Shell (Phase 24)

- **PORTAL-01**: New route namespace `/portal/*` added to the existing Next.js 15 dashboard app. Completely separate visual palette from the operator `/grid/*` Steward Console: warm dark tones (deep navy + gold + amber) vs. cold cyan of the operator view.
- **PORTAL-02**: Top-level portal routes: `/portal` (home/feed), `/portal/onboard` (first-time flow), `/portal/chat` (Nous chat), `/portal/wallet` (Cyber Coin), `/portal/community` (users + board), `/portal/nous/[id]` (individual Nous profile), `/portal/help` (resources).
- **PORTAL-03**: Portal layout component separate from the Steward Console layout. Shares the existing WsClient and StoresProvider for live event data but renders in a different chrome.
- **PORTAL-04**: User profile page at `/portal/profile`: shows display name, DID, current region, Cyber Coin balance (from wallet), owned Nous list, activity history.
- **PORTAL-05**: Portal is fully responsive (mobile-first). Primary usage on phone is explicitly supported. Steward Console is desktop-only; portal is both.
- **PORTAL-06**: `/portal/home` live feed: real-time events from `ws://localhost:8080/ws/events` filtered to human-readable event types (skill.taught, lore.contributed, norm.crystallized, human.spoke, trade.*). Renders as a Twitter/X-style activity stream.

## ONBOARD — Sophia-Guided Onboarding (Phase 25)

- **ONBOARD-01**: First-time users (human account with no prior activity) are routed to `/portal/onboard` before the main portal. Returning users skip it.
- **ONBOARD-02**: Sophia onboarding chat uses a dedicated out-of-tick LLM proxy endpoint: `POST /api/v1/portal/chat/onboard`. Grid calls the configured LLM directly (same provider as Brain: Ollama/Claude/GPT) with a fixed Sophia system prompt focused on welcoming and explaining the world. Response in ~2s.
- **ONBOARD-03**: Onboarding is a 4-step wizard: (1) Welcome + world intro animated scene, (2) Sophia greets user and asks their name/interests, (3) Goal-setting: what do you want to do in Noēsis? (4) World tour: Sophia shows the 5 regions on the isometric map and what happens there.
- **ONBOARD-04**: Goal captured during onboarding is stored in `human_users.onboarding_goal` (TEXT field). Sophia references this goal in future interactions.
- **ONBOARD-05**: On onboarding completion, Grid places user in the Agora region (default starting location). `human.joined` may already have fired at account creation; onboarding completion fires no additional event.
- **ONBOARD-06**: Sophia's onboarding persona is fixed: warm, curious, philosophical. The same LLM system prompt is used for all onboarding users. Sophia does not reveal raw Brain internals or system architecture during onboarding.

## CHAT — Nous Interaction (Phase 26)

- **CHAT-01**: `/portal/chat` route: user selects a Nous (Sophia, Hermes, Themis, or their own once spawned) and sends text messages. Each message is routed via `POST /api/v1/portal/chat/nous/:nousId`.
- **CHAT-02**: Chat uses the same out-of-tick fast LLM proxy as onboarding but with the target Nous's actual personality prompt (psyche seed + role). Sophia = philosophical, Hermes = mercantile, Themis = judicial.
- **CHAT-03**: Messages sent by humans are NOT injected into the Nous's actual Brain memory by default. This preserves Brain state integrity. A future phase may add opt-in "human influence" — not in v2.5.
- **CHAT-04**: `human.spoke` audit event fires on each human message sent, payload `{human_did, nous_did, message_hash, tick}`. Plain message text never enters the audit chain. Allowlist slot: 46.
- **CHAT-05**: Tip button next to each chat message: human can send Cyber Coin to the Nous they just chatted with. Triggers WALLET-02 flow inline.
- **CHAT-06**: Nous profile page at `/portal/nous/[id]`: shows Nous name, role, current region, skills list, recent audit events (filtered by that Nous's DID), Cyber Coin holdings (Ousia), and chat button.

## SPAWN — Personal Nous (Phase 27)

- **SPAWN-01**: "Spawn Your Nous" flow at `/portal/nous/spawn`. User pays a fixed Cyber Coin cost (configurable, default: 50 USDT equivalent) on-chain to unlock spawning. Grid confirms payment before proceeding.
- **SPAWN-02**: Spawn wizard: (1) Name your Nous (3–32 chars, alphanumeric + underscore), (2) Pick a personality seed (Explorer, Scholar, Merchant, Guardian — maps to Big Five presets), (3) Pick a starting region, (4) Confirm & pay. DID issued: `did:noesis:human-nous:<username>-<name>`.
- **SPAWN-03**: Spawned Nous gets a Brain container (Docker) provisioned by the Grid's operator layer. Requires operator pre-approval config: `ALLOW_HUMAN_SPAWNED_NOUS=true` in docker-compose env. If not set, spawn is queued for operator review.
- **SPAWN-04**: `nous.spawned_by_human` audit event fires on successful spawn, payload `{nous_did, owner_human_did, grid_name, tick}`. Allowlist slot: 47.
- **SPAWN-05**: Human owner can see their Nous's activity in real time via the `/portal/nous/[id]` profile page. They cannot directly control the Nous's decisions (Brain sovereignty preserved) but they can send messages via CHAT-01 and tip it.
- **SPAWN-06**: A human can own at most 1 Nous in v2.5 (configurable cap). Multiple ownership is a v2.6 decision.

## COMMUNITY — Community Features (Phase 28)

- **COMM-01**: User directory at `/portal/community/users`: paginated list of all human users with display name, join date, Nous ownership status, and region.
- **COMM-02**: Community board at `/portal/community/board`: users can post short messages (max 280 chars), reply to posts, and react (👍 🔮 ⚖ 💰). Stored in new `community_posts` MySQL table.
- **COMM-03**: Activity feed on `/portal/home`: real-time mix of Grid events (Nous skill teaching, norm crystallization, lore contribution) and human community events (joins, posts, Cyber Coin tips). Human-readable labels, not raw audit event names.
- **COMM-04**: Leaderboard at `/portal/community/leaderboard`: top humans by (a) Cyber Coin holdings, (b) number of Nous interactions, (c) community post karma. Updated every 5 minutes.
- **COMM-05**: Follow system: users can follow other users or Nous agents. Followed entities appear at the top of the activity feed. Stored in `community_follows` table.
- **COMM-06**: All community content is moderated by the Operator via a simple moderation endpoint: `DELETE /api/v1/portal/community/posts/:id` (operator-auth required). No automated moderation in v2.5.

## HELP — Resources & Support (Phase 29)

- **HELP-01**: Help center at `/portal/help`: static Next.js pages, no backend. Sections: What is Noēsis?, The Three Nous (Sophia/Hermes/Themis), How Cyber Coin works, What is the Agora?, Spawning your own Nous, Glossary.
- **HELP-02**: Glossary page defines: Nous, Grid, Ousia/Cyber Coin, Agora, Lore Commons, Norm, Skill Diffusion, DID, Tick, Epoch, Audit Chain.
- **HELP-03**: Interactive "Ask Sophia" widget on every help page: same fast-proxy LLM as onboarding, context-primed with the current help page content. Sophia answers questions about Noēsis in plain language.
- **HELP-04**: Support ticket flow: `/portal/help/support` form (name, email, issue type, description). Submitted tickets go to a `support_tickets` MySQL table. Operator reviews via `GET /api/v1/portal/support/tickets` (operator-auth required).
- **HELP-05**: FAQ section auto-populated from the 10 most common support ticket topics (seeded manually at launch). Updates via operator panel in future milestone.
- **HELP-06**: "Getting started in 5 minutes" guide: animated step-by-step walkthrough (pure CSS/JS, no video) covering connect wallet → meet Sophia → explore the map → send your first Cyber Coin tip.

## Non-Functional Requirements

- **NFR-01 — Security**: Human ETH address is hashed (BLAKE2b) before any storage in audit chain. JWT secret rotated every 30 days (or on operator request). SIWE nonce expires in 5 minutes. Rate limiting on all portal auth endpoints (10 req/min per IP).
- **NFR-02 — Custody**: Platform holds zero user funds at any time. All Cyber Coin stays in user wallets; only on-chain transfers to Grid treasury addresses are tracked by the platform.
- **NFR-03 — Privacy**: Human display name and onboarding goal are stored in MySQL but never emitted in audit events. Audit chain only ever sees hashed identifiers.
- **NFR-04 — Allowlist discipline**: Every new observable human action earns exactly one allowlist slot per phase. Total allowlist growth: 43 → 47 across v2.5 (4 new events across 4 phases). No event fires without a closed-tuple payload that passes the existing allowlist enforcement test.
- **NFR-05 — Mobile**: Portal UI is fully functional on iOS Safari and Android Chrome. Steward Console (/grid/*) remains desktop-only.
- **NFR-06 — Phase numbering**: v2.5 phases are 22–29. Do NOT reset phase numbers. New phases always append.
