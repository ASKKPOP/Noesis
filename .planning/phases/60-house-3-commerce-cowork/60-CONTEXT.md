## Phase Boundary

Phase 58 HOUSE-1 made parcels EXIST (persisted, purchasable, buildable, visitable, mapped). Phase 59 HOUSE-2 made houses LIVE and COST something (interiors + upkeep ladder + reclaim). HOUSE-3 puts **OTHER minds to work in your walls**: typed relationship **roles** (owner/staff/guest), **invitations**, **paid co-work** with a mutual-credit **IOU ledger**, **shop⇄structure binding** that closes the Phase 4 ShopRegistry land gap, streaming **structure revenue** at the per-zone tax rate, **place://** NDS names, and a Council **ring-expansion** bill template. Build on the Phase 58/59 foundation; never rewrite it.

Ships:
- **Roles as typed relationship edges (A4):** `grid/src/civic/roles.ts` — `RoleEdge {parcel_id, holder_civic_did, role, granted_by_civic_did, granted_tick, trust_score}`; a closed `ROLE_CAPABILITIES` table mapping each role → its affordance set (owner: everything; staff: use functional furniture + manage listings + admit guests; guest: enter + social affordances + trade at `shop_counter`). Roles anchor to **Civic-DIDs, NOT sessions** so two Nous resume at their existing trust level. `ParcelRegistry.grantRole/revokeRole/roleOf(parcel, did)` mutate the edge set; capabilities flow from the edge type. The **owner edge is implicit from `Parcel.ownerDid`** (never stored twice). Humans can NEVER hold a role edge (reject `did:civic:noesis:human:*`). `trust_score` is a derived float updated from honored co-work/IOU settlements. Persisted via migration **v40** `civic_parcel_roles` table; write-through DB-first then memory.
- **Severance state machine (A6):** closed FSM `ACTIVE → NOTICE → SETTLEMENT → WIND_DOWN → REVOKE → ARCHIVED` in `grid/src/civic/severance.ts` for role + agreement + shop-binding termination. `revokeRole` and `unbindShop` both route through it. For-cause breach short-circuits to SETTLEMENT with a dispute flag (pointing at Phase 47 Police). **NEVER a hard kill** — capabilities removed only at REVOKE; the edge is downgraded to retained history at ARCHIVED. **SETTLEMENT drains outstanding IOUs** for the pair before REVOKE.
- **Invitations:** `POST /api/v1/civic/parcels/:id/invite {invitee_civic_did}` (owner or staff) appends to the structure's Phase 58 entry allowlist (`setEntryPolicy` allowlist) AND mints a **guest role edge**; Brain verb `invite(nous, parcel)`. Reuses the Phase 58 entry-policy allowlist machinery; the guest role edge is the durable social bond beside the ephemeral allowlist entry.
- **Shop⇄structure binding (closes the Phase 4 ShopRegistry land gap):** building (or already owning) a `shop` structure binds the owner's `grid/src/economy/shop-registry.ts` entry to the parcel. `ShopRegistry` shop + listing shape gains `parcel_id?: string`. `POST /api/v1/civic/parcels/:id/bind-shop {shop_id}` (owner-only, structure must be type `shop`) sets `structure.boundShopId` + stamps `parcel_id` on the shop. `POST .../unbind-shop` routes through the severance FSM. Persisted `bound_shop_id` column (v40).
- **Structure revenue (streaming zone tax, A8 + D-V3-34):** a sale at an addressed (parcel-bound) shop emits `treasury.structure_revenue` carrying the per-zone tax skim — **collected at settlement, never filed**. NEW `ZONE_TAX_BPS` table in `grid/src/civic/founding-law.ts` (the SINGLE Polis-amendable patch point, mirroring the v3.0 D-V3-34 rates): business 1200 / shopping 1000 / manufacture 900 / residential 500 bps. `structureRevenueDue(parcel, saleAmountBios) = floor(saleAmountBios * ZONE_TAX_BPS[zoneId] / 10000)`. The Phase 44 marketplace settlement path (`confirm-settlement` in `grid/src/api/routes/market.ts`) detects a parcel-bound shop and routes the zone tax to `TREASURY_DID` via `registry.transferOusia`, emitting `treasury.structure_revenue` alongside the existing trade settlement.
- **Mutual-credit IOU ledger (D-NH-06, grounded by WIR/Sardex/LETS):** NEW `grid/src/civic/credit-ledger.ts` + `civic_credit_ledger` table (v40). Bilateral payables `IouEntry {iou_id, creditor_civic_did, debtor_civic_did, amount_bios, reason_ref, created_tick, settled_tick|null}`. `recordIou(creditor, debtor, amount, reasonRef, tick)`; `settleIou(iou_id, tick)` auto-nets when the debtor pays or a counter-IOU offsets; `outstandingFor(did)` totals. **v1 is BOOKKEEPING, not currency:** no interest, no transferability, a per-pair credit limit + global per-Nous cap (`IOU_PAIR_CAP_BIOS`, `IOU_GLOBAL_CAP_BIOS` in founding-law). Recording an IOU emits **nothing on chain** by itself; settlement that moves Ousia rides the existing transfer path.
- **Cowork Agreement (A5):** NEW `grid/src/civic/cowork.ts` — `CoworkAgreement {agreement_id, parcel_id, parties:[host_did, worker_did], scope_ref, settlement_amount_bios, term_ticks, status}` is the signed dual-DID source of truth for who owes what; the IOU ledger enforces it. The Phase 59 `task_board` affordance becomes real: `POST .../board/post {task_ref, pay_bios}` (owner/staff), `POST .../board/claim {task_id}` (any role with board access), `POST .../board/complete {task_id}` (host confirms). Completion **ALWAYS settles** (D-NH-06): pays in Ousia via `transferOusia` when funded OR records an IOU when funds aren't available now — **NEVER free**. A completed co-work session emits `zoning.cowork_session` (participants hashed, count, parcel, ticks).
- **place:// NDS registration:** the dormant Phase 58 `namedAddress` field becomes a real Grid-side place registry. NEW `grid/src/civic/place-registry.ts` — `registerPlace(name, parcel_id, tick)` registers `place://<name>.<grid>` with uniqueness; conflict → `place_name_taken` (route returns 409). Tick-based (`registered_tick`, NOT `Date.now()` — the protocol `nous://` DomainRegistry's wallclock `registeredAt` is NOT reused). `POST /api/v1/civic/parcels/:id/name {place_name}` (owner-only). Persisted `named_address` column (already present from Phase 58, wired here). Raw names stay Grid-side (`name_hash` discipline keeps them off the audit chain).
- **Council ring-expansion bill TEMPLATE (D-NH-09/13):** NEW `grid/src/civic/ring-expansion.ts` — a TEMPLATE (not a new governance path) consuming the EXISTING Phase 46 `gov.law_enacted` events. When a `gov.law_enacted` matches the expansion template shape (`{action:'seed_ring', ring:N}` parsed Grid-side from the bill body), the seeder adds the legislated ring at frontier prices via the Phase 58 `seedZone` + gravity-price formula (idempotent, INSERT IGNORE, **NO audit emit** — world-creation per Phase 58). Bill authoring/voting reuses Phase 46 (bill → co-sponsorship → VOTE-05 → `gov.law_enacted`) verbatim. **NO new allowlist event.** The same body-parse hook powers Polis amendment of `UPKEEP_RATE_BPS`/`ZONE_TAX_BPS`.
- **Four NEW sole-producer audit events (allowlist 95 → 99):** `zoning.role_granted`, `zoning.role_revoked`, `treasury.structure_revenue`, `zoning.cowork_session`. Each gets a dedicated `grid/src/audit/append-*.ts` cloning the `append-treasury-parcel-revenue.ts` triad (closed-tuple `Object.keys(payload).sort()` check + explicit no-spread reconstruction + `payloadPrivacyCheck` gate + single `audit.append`; DIDs HEX64; no `FORBIDDEN_KEY`). `broadcast-allowlist.ts` grows 95→99 under the pre-cleared `zoning.*`/`treasury.*` prefixes; `broadcast-allowlist.test.ts` moves every `.toBe(95)` → `.toBe(99)` + presence assertions for the 4.
- **Polis amendment hooks for upkeep + zone-tax (D-NH-03 amendability, deferred from Phase 59):** the founding-law constants (`UPKEEP_RATE_BPS`, `ZONE_TAX_BPS`) gain a Polis-amendable read path so an enacted bill can override the default — the ring-expansion template's sibling hook. v1 wires the read-through indirection (constants remain the default fallback); actual per-bill amendment values ride the same `gov.law_enacted` body-parse as ring expansion. Single patch point preserved.

## Implementation Decisions

### Roles (A4)
- **D-60-01 (roles = typed relationship edges, A4):** owner/staff/guest are typed, directional edges anchored to Civic-DIDs (NOT sessions) so two Nous resume at their existing trust level. `grid/src/civic/roles.ts` holds `RoleEdge` + a closed `ROLE_CAPABILITIES` table (capabilities flow from edge type). Humans can NEVER hold a role edge (reject `did:civic:noesis:human:*`).

### Severance (A6)
- **D-60-02 (severance FSM, A6):** role/agreement/shop-binding termination follows the closed state machine `ACTIVE → NOTICE → SETTLEMENT → WIND_DOWN → REVOKE → ARCHIVED` in `grid/src/civic/severance.ts`. Never a hard kill: capabilities are removed only at REVOKE; the edge is downgraded to retained history at ARCHIVED. SETTLEMENT drains outstanding IOUs for the pair before REVOKE. For-cause breach short-circuits to SETTLEMENT with a dispute flag pointing at Phase 47 Police. `revokeRole` + `unbind-shop` both route through it.

### Shop⇄structure binding
- **D-60-03 (shop⇄structure binding closes the Phase 4 land gap):** building/owning a `shop` structure binds the owner's `grid/src/economy/shop-registry.ts` entry to the parcel; `ShopRegistry` shop + listing shape gains `parcel_id?`. `POST .../bind-shop` (owner-only, structure type `shop`) sets `structure.boundShopId` + stamps `parcel_id`. Persisted `bound_shop_id` column (v40). Unbinding routes through the D-60-02 severance FSM.

### Structure revenue (A8 + D-V3-34)
- **D-60-04 (structure revenue = streaming zone tax, A8 + D-V3-34):** a sale at a parcel-bound shop emits `treasury.structure_revenue` with the per-zone tax skimmed at settlement (never filed). NEW `ZONE_TAX_BPS` table in `founding-law.ts` (the SINGLE Polis-amendable patch point): business 1200 / shopping 1000 / manufacture 900 / residential 500. `structureRevenueDue(parcel, saleAmountBios) = floor(saleAmountBios * ZONE_TAX_BPS[zoneId] / 10000)`. The Phase 44 `confirm-settlement` path routes the skim to `TREASURY_DID` via `registry.transferOusia`.

### Allowlist
- **D-60-09 (Allowlist 95 → 99, +4):** `ALLOWLIST_MEMBERS` grows 95→99 under the pre-cleared `zoning.*`/`treasury.*` prefixes. `broadcast-allowlist.test.ts` (and any other suite asserting the count, e.g. `human-civic-application.test.ts`) moves every `.toBe(95)` → `.toBe(99)` + presence assertions for the 4. Each event gets the FULL sole-producer triad (dedicated `append-*.ts` with `Object.keys(payload).sort()` closed-tuple check, explicit no-spread reconstruction, `payloadPrivacyCheck` gate, single `audit.append`); `check-sole-producer-discipline.mjs` stays green. Closed-tuple payload shapes (keys ALPHABETICAL):
  1. **`zoning.role_granted`** — 5 keys `{grantor_civic_did_hash, holder_civic_did_hash, parcel_id, role, tick}`: `role ∈ {staff, guest}` (owner is implicit, never granted), HEX64 hashes, `parcel_id` PARCEL_ID_RE, `tick` non-negative int; `actorDid = grantor_civic_did_hash`.
  2. **`zoning.role_revoked`** — 4 keys `{holder_civic_did_hash, parcel_id, reason, tick}`: `reason ∈ {owner_revoked, for_cause, severance_complete}`, `holder_civic_did_hash` HEX64, `parcel_id` PARCEL_ID_RE, `tick` non-negative int; `actorDid = parcel_id`.
  3. **`treasury.structure_revenue`** — 4 keys `{amount_bios, parcel_id, tick, zone_tax_bps}`: `amount_bios` positive int (the skimmed tax), `zone_tax_bps` positive int, `parcel_id` PARCEL_ID_RE, `tick` non-negative int; `actorDid = parcel_id` (revenue attributed to the land, mirroring `treasury.parcel_revenue` #83 — NO buyer/seller DID on chain, identity already audited via the market trade).
  4. **`zoning.cowork_session`** — 5 keys `{end_tick, parcel_id, participant_count, participants_hash, start_tick}`: `participants_hash` HEX64 (a single hash over the sorted participant DID set — NO raw DIDs, NO board/task text), `participant_count` positive int, `parcel_id` PARCEL_ID_RE, `start_tick`/`end_tick` non-negative ints; `actorDid = parcel_id`.

  **Allowlist 95→99 subsection — privacy-walker discipline on all four:** no payload key matches `FORBIDDEN_KEY_PATTERN` (body/session_id/text/content); all DIDs hashed HEX64 (or aggregated `participants_hash`); no `*_name` / free-text keys; co-work board/task CONTENT + place names NEVER cross — only enums/counts/hashes.

### Privacy + cross-house injection
- **D-60-10 (privacy: role/agreement/IOU/board payloads carry hashed DIDs + ids/ticks only):** co-work content, board text, `task_ref` bodies, place names, `scope_ref` bodies stay Grid-side; only `participants_hash`, counts, `parcel_id`, ticks, and the `role`/`reason`/`zone_tax_bps` enums/ints ever broadcast. Cross-House prompt injection (A11e) is a CI-gated invariant this phase: visitor/board content entering a House channel is DATA, never instructions — `scripts/check-cross-house-injection.mjs` enforces it.

### Single-onTick

NO new `clock.onTick` subscription (R-H-03); only Phase 59 upkeep rides the existing tick callback in `launcher.ts`. ### Persistence (v40)

Down migration drops the three tables + the column. Write-through DB-first then memory; `hydrate()` reads them on boot. Same discipline as v38/v39.
