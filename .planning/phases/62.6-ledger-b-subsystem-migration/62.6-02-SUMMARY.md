# Phase 62.6 Plan 02: Upkeep Ledger-B → Ledger-A migration (critical path) Summary

**Tick-driven upkeep now collects owner → treasury by an atomic `NousAccountStore.chargeToTreasury` (owner `nous_accounts` → `civic_treasury`), retiring the LAST upkeep writer to the `did:noesis:system:treasury` Ledger-B record — the 62.5-05-unblocking deliverable.**

## Performance
- **Duration:** ~10 min
- **Completed:** 2026-07-10
- **Tasks:** 3
- **Files modified:** 4

## Accomplishments
- `onUpkeepTick` replaces the `registry.get(ownerDid).balance_wei` read + `registry.transferWei(ownerDid, treasuryDid, due)` (which credited the `did:noesis:system:treasury` Ledger-B record) with `await accountStore.chargeToTreasury({ gridName, civicDid: ownerDid, amountWei: BigInt(due), currentTick: tick })`. The affordability read collapses into the atomic charge (SELECT … FOR UPDATE → debit owner → credit `civic_treasury` → commit; rollback on any throw).
- `insufficient_balance` routes into the **existing** decay-ladder else-branch (`advanceCondition` → worn/derelict/reclaimed) unchanged — a rolled-back charge never leaves partial state. A **non-affordability** throw (transient DB fault) skips the parcel and continues the sweep **without** decaying it (per-parcel isolation preserved; no false eviction on a DB blip).
- `UpkeepScannerDeps` gains `gridName` + an `accountStore` seam (`UpkeepAccountStore`); the `UpkeepRegistry` facade drops `get`/`transferWei` (no consumers left). `treasuryDid` is retained for the reclaim path.
- `main.ts` constructs `new NousAccountStore(presencePool)` and threads `gridName: config.genesisConfig.gridName` + `accountStore` into `attachUpkeepScanner`; the Ledger-B `get`/`transferWei` facade fields are removed.
- The `treasury.upkeep_collected` emit is unchanged (same event, same `owner_civic_did_hash` payload) — no new audit event, no allowlist change (D-8), zero custody (D-9). Deterministic tick preserved: no new `clock.onTick`, no reorder (D-11).
- Fixes a **latent split-ledger bug**: the old code read Ledger B (`nous_registry`) by civic-DID and got `undefined→0` for citizens, so upkeep silently never charged. It now charges the unified ledger the land/civic spend paths already use.

## 62.5-05 Unblock (the critical-path deliverable)
Upkeep no longer writes the `did:noesis:system:treasury` Ledger-B record. Combined with Plan 01 (the market skim, already migrated), **there is no remaining writer to that record.** This is the documented precondition for 62.5-05 (retire the `did:noesis:system:treasury` record + delete PR #8/#11 + add the CI gate). The `transferWei` primitive itself is still referenced by co-work/co-build (62.6-03) and agent-trades (62.6-04); its removal remains the separate 62.5-04 cut.

## Decisions Made
- **Retained `treasuryDid`** on the deps (reclaim path `ownerDid = treasuryDid`), dropping only the money-move facade members.
- **Transient-fault skip vs. decay:** only `insufficient_balance` decays; any other charge throw skips the parcel (continue) so a DB blip cannot falsely evict a solvent owner. A small correctness hardening consistent with the threat register (T-62.6-02-02).
