# Phase 62.6 Plan 04: Agent-trade settlement Ledger-B → Ledger-A migration (D-13 citizens-only) Summary

**Agent-trade settlement now moves money via `NousAccountStore.transfer` between the RESOLVED civic-DIDs of the proposer and counterparty (existence→civic via `CivicDidStore.getByExistenceDid`), enforcing the operator-locked D-13 citizens-only reject — this is the LAST `NousRegistry.transferWei` money site, so 62.5-04 can now fold `nous_registry.balance_wei` and remove `transferWei`.**

## Accomplishments
- **Settle on Ledger A with the D-13 gate.** The `trade_request` settle (previously `this.registry.transferWei(this.nousDid, counterparty, amount)`) now resolves BOTH the proposer existence-DID and the counterparty existence-DID to civic-DIDs via `CivicDidStore.getByExistenceDid`. If EITHER resolves to `null` (a pre-citizen Nous), the trade does NOT settle — `trade.rejected{reason:'not_found', nonce}` (an EXISTING allowlisted reason, no allowlist change). Otherwise `await accountStore.transfer(proposerCivic → counterpartyCivic, BigInt(amount))` moves the money on `nous_accounts`, then `trade.settled{counterparty, amount, nonce}` emits exactly as before.
- **Reviewer balance migrated to the same ledger.** The reviewer's `proposerBalance` is read from the resolved proposer civic-DID's `nous_accounts` balance (awaited before the sync `review()` call — `review()` itself stays synchronous, D-02 determinism). A pre-citizen proposer reads 0. This keeps the pre-commit review gate in sync with the ledger the transfer moves.
- **Store throws mapped to the existing reason enum** — `insufficient_balance→'insufficient'`, `invalid_transfer_self→'self_transfer'`, `invalid_amount→'invalid_amount'`, anything else→`'not_found'`. No new reason strings (R-31-01 zero-diff, D-8).
- **Review-fail branch byte-identical** — on reviewer fail there is NO transfer, NO `trade.settled`, NO `trade.rejected`; `trade.reviewed{fail}` shape unchanged. The bounds check and the `trade.proposed`/`trade.reviewed{pass}` emits are untouched.
- **Dep injection.** `NousRunnerConfig` + `NousRunner` gained optional `accountStore?: NousAccountStore`, `civicDidStore?: CivicDidStore`, `gridName?: string` fields (mirroring the `reviewer?`/`whisperRouter?`/`groupStore?` optional-dep pattern). `main.ts` hoists a `nousAccountStore` (assigned inside `if (dbConn)` from `presencePool`) and injects all three into the seeded `new NousRunner({...})` construction — conditionally spread so DB-less mode stays valid.
- **counterparty/nonce kept as the existence-DID/id** in the `trade.settled` payload (D-10 hash-only boundary — the on-chain identity does not change; only the money store changes). Zero custody (D-9). Deterministic tick — settle stays inside the already-async `executeActions` (D-11).

## D-13 gate behavior (the operator-locked decision)
- BOTH the proposer (`this.nousDid`) and the `counterparty` existence-DIDs are resolved via `getByExistenceDid(gridName, existenceDid)`.
- Either resolves `null` ⇒ `trade.rejected{reason:'not_found', nonce}` (existing reason — no new string, no allowlist change).
- Absent wiring (no `accountStore`/`civicDidStore`/`gridName`) is treated identically to an unresolved counterparty — it NEVER falls back to the Ledger-B `registry.transferWei`.
- Only naturalized citizens (civic-DID holders) move money — the constitutional citizens-only economy.
