# Phase 62.6 Plan 03: Co-work / Co-build Ledger-B → Ledger-A migration Summary

**Co-work and co-build host→worker settlement now moves money via `NousAccountStore.transfer` (Nous→Nous, one atomic transaction on `nous_accounts`), replacing the synchronous `registry.transferWei` dep seam with an async `settleWei` seam — with an `insufficient_balance → recordIou` fallback that preserves the D-NH-06 always-settles-on-completion invariant.**

## Performance
- **Duration:** ~25 min
- **Completed:** 2026-07-10
- **Tasks:** 3
- **Files modified:** 8 (3 source, 5 test — 2 planned test files + 3 collateral e2e/route retargets forced by the async signature change)

## Accomplishments
- **cowork.ts** — `CompleteDeps.transferWei?: (from,to,amount)=>void` replaced by `settleWei?: (fromCivic,toCivic,amountWei)=>Promise<void>`; `completeTask` is now `async` (`Promise<CoworkAgreement>`). The funded branch awaits `settleWei(host,worker,amount)` and, on `insufficient_balance`, falls back to `recordIou(worker, host, amount, agreement_id, end_tick)` (D-NH-06). The `cowork_must_pay` pay-nothing guard, `bumpTrust`, the participants-hash construction, and the status ladder are unchanged.
- **co-build.ts** — same seam swap on `CoBuildDeps`; `completeSubTask` is now `async` (`Promise<SubTaskSettlement>`) with the identical try/catch → IOU-fallback (setting `settlement='iou'`). The `completeNode = completeSubTask` alias stays a valid async alias. `cobuild_must_pay`, `claimSubTask`, `attributionShare`, `isComplete`, `coBuildStaffOf` unchanged.
- **civic-parcels.ts** — the `POST /board/complete` route constructs `new NousAccountStore(services.pool)` (503 if no pool) and wires `settleWei → accountStore.transfer({ gridName, fromDid, toDid, amountWei: BigInt(amt), currentTick: endTick })`; it `await`s the now-async `completeTask` with `funded: true`. The `zoning.cowork_session` emit is byte-for-byte unchanged.
- No `registry.transferWei` call remains in `cowork.ts`, `co-build.ts`, or the board/complete route (grep count = 0 across all three).
- Tests retargeted: `cowork.test.ts` / `co-build.test.ts` use the async `settleWei` spy, `await` the completion fns, add real-`NousAccountStore.transfer` conservation cases (host debited, worker credited on the accounts-pool fake) and an `insufficient_balance → recordIou` IOU-fallback case.

## Invariants held
- **D-NH-06 always-settles:** a funded completion pays via `settleWei`; an underfunded host (`insufficient_balance`, transfer rolled back) falls back to `recordIou` — never a silent no-pay. Proven by a dedicated IOU-fallback test in both cowork and co-build suites.
- **D-8 no new audit events / no allowlist change:** `zoning.cowork_session` emit + payload unchanged; the IOU fallback reuses the existing `recordIou` shape. No new event, no allowlist prefix added.
- **D-9 zero custody:** `NousAccountStore.transfer` is in-DB bookkeeping (`SELECT … FOR UPDATE` → debit → credit → commit); no `transferFrom`, no platform keys.
- **D-11 deterministic tick:** board/complete is request-driven; no `clock.onTick` added (co-work/co-build are explicitly single-onTick-free).
- **D-12 atomicity preserved/improved:** the host debit + worker credit run on one connection inside one `beginTransaction/commit`; a throw rolls back (no partial pay) — a strict non-regression vs the old single in-memory `transferWei`.
- **R-31-01 audit-chain zero-diff:** no event added/removed/reordered; payload shapes preserved.
