## Fixed Issues

### WR-04: IRS-fee math coerced wei `BigInt`→`Number` — precision loss at true-wei magnitudes

**Files modified:** `grid/src/marketplace/marketplace-store.ts`, `grid/test/marketplace-store.test.ts`
**Commit:** `2c4ffbac`
**Applied fix:** Replaced `BigInt(Math.floor(Number(amountWei) * params.irsFeeRate))` with basis-point BigInt math:
`const feeBps = BigInt(Math.round(params.irsFeeRate * 10000)); const irsFee = (amountWei * feeBps) / 10000n;`
`sellerPayout = amountWei - irsFee` stays exact. Verified small-amount behavior is byte-identical to the old floor path (100→2, 101→2, 200→4 at 2%). Added a test at 3e18 wei asserting `sellerPayout + irsFee === amountWei` and `irsFee === amountWei * 200n / 10000n`. tsc clean; 22 marketplace-store tests green.

### WR-05: D-13 reviewer read `proposerBalance` as `Number(bigint)` — precision loss on the gate input

**Files modified:** `grid/src/review/types.ts`, `grid/src/review/checks/balance.ts`, `grid/src/integration/nous-runner.ts`, `grid/test/review/reviewer.pass.test.ts`, `grid/test/review/reviewer.first-fail.test.ts`, `grid/test/review/checks.test.ts`
**Commit:** `79e588ce`
**Applied fix:** Changed `ReviewContext.proposerBalance: number` → `bigint`. The reviewer's balance check now compares `ctx.proposerBalance >= BigInt(Math.trunc(ctx.amount))` — `Math.trunc` keeps a non-integer `amount` from throwing `RangeError` in the (un-try/catch'd) reviewer path (a non-integer is still rejected at the authoritative settle, which is inside a try/catch), and is a no-op for real integer wei. `nous-runner.ts` now assigns the `bigint` from `getBalance` directly (no `Number()` coercion; default `0n`). Blast radius stayed contained (the unrelated `CharterReviewInput` is a different type). Added a boundary test at 2^53 and a 1e18-wei case. tsc clean; 58 review + trade-settlement tests green.

Blast-radius note: this was the borderline judgment call in the task. The ripple was 3 source + 3 test files, all cleanly containable, and the Reviewer contract (`ReviewResult`, failure enum, check ordering) is unchanged — so the fix was applied rather than skipped. Correctness did not regress (all existing review tests pass unchanged in intent).

### WR-06: upkeep scanner swallowed unexpected charge errors with no log

**Files modified:** `grid/src/civic/upkeep-scanner.ts`, `grid/test/civic/upkeep-scanner.test.ts`
**Commit:** `ea82f8c7`
**Applied fix:** On a non-`insufficient_balance` throw from `chargeToTreasury`, the scanner now emits `console.warn('[upkeep] upkeep_charge_failed parcel_id=<id>: <message>')` before `continue` — mirroring the market skim's `skim_charge_failed` observability, which is exactly what would have surfaced CR-01. Used `console.warn` (the logging surface already used by `main.ts` in this wiring context) to avoid inventing a new dependency or changing the `onUpkeepTick(tick, deps)` contract. Added a test asserting the unexpected-error path logs (parcel id + underlying message) and the sweep still continues. The test captures `console.warn` via direct reassignment because vitest's own console interception makes `vi.spyOn(console, 'warn')` unreliable here. tsc clean; 15 upkeep tests green.
