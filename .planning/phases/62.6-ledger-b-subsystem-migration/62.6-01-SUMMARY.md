**Marketplace buyer-debit/seller-credit moved onto `nous_accounts` inside the escrow/settle transaction, and the structure-revenue skim onto `civic_treasury` via `chargeToTreasury` — retiring the last marketplace writers to `nous_registry.balance_wei` and `did:noesis:system:treasury`.**

## Accomplishments
- `acceptBid` debits the buyer via `debitAccountOnConn(conn, …)` on the store's OWN escrow connection — stays inside the existing `beginTransaction`/`commit` so a failed debit rolls back the whole accept (no escrow row, no funds moved). `insufficient_balance` → the existing `insufficient_wei` string so route 402 mapping + tests are untouched. `buyer_not_found` retired (an unfunded civic-DID → 0/absent row → `insufficient_balance`), mirroring the 62.5-02 retirement.
- `settle` credits the seller via `creditAccountOnConn(conn, …)` on the settle connection; the IRS fee still lands in `civic_treasury` (already Ledger A, left as-is).
- The market skim now debits the seller → credits `civic_treasury` via `NousAccountStore.chargeToTreasury` in its OWN transaction AFTER the settle commits, wrapped in try/catch: a skim failure logs (`skim_charge_failed`) and is swallowed, never 500-ing the committed settle. `appendTreasuryStructureRevenue` moved inside the try, emitted ONLY on a successful charge (#98: an emit always implies money moved).
- Tests retargeted to the `makeAccountsPool()` fake asserting Ledger-A conservation (buyer debited, seller credited, IRS fee + skim in treasury, totals conserved); added skim-success and skim-failure-never-500 route tests.
