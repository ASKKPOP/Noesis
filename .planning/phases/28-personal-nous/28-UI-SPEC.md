# Phase 28 — UI Design Contract: Personal Nous

> Visual and interaction contract for `/portal/nous/spawn` (4-step spawn wizard) and
> `/portal/my-nous` (owner hub replacing Phase 27 placeholder).
> Generated by gsd-ui-researcher. Pre-populated from 28-CONTEXT.md, 28-RESEARCH.md, and
> 27-UI-SPEC.md (approved phase predecessor). Verified by gsd-ui-checker.

**Theme:** Portal LIGHT editorial palette (`.portal-theme` CSS class scope, `--vellum` background).
Inherits the same editorial design system as Phases 24–27. All values reference portal CSS custom
properties — no raw hex and no Tailwind color class tokens in component code.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — CSS variables only (`.portal-theme` class scope) |
| Preset | not applicable |
| Component library | none — hand-rolled inline-style React, consistent with Phases 24–27 |
| Icon library | inline SVG (same convention as auth page, PortalSidebar, Phase 27 avatars) |
| Font — serif | Cormorant Garamond (`var(--serif)`) — Nous name (hero card), wizard section headings, owner hub heading |
| Font — sans | Inter Tight (`var(--sans-portal)`) — wizard step UI, buttons, metadata, seed descriptions, labels |
| Font — mono | JetBrains Mono (`var(--mono-portal)`) — DID display, seed badges, tick values, status tags |

Source: 27-UI-SPEC.md Design System (carry-forward, confirmed no shadcn in codebase, no components.json).

All components live inside `PortalShell` (`.portal-theme` is set on the shell root). No additional
theme class needed per component. No shadcn. No Radix. No external component libraries.
`dynamic({ ssr: false })` required for wizard Step 4 (wagmi `useWriteContract` dependency).

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, step indicator pip gaps, badge inner padding vertical |
| sm | 8px | Wizard field label to input gap, seed card inner gap, preset amount gap |
| md | 16px | Wizard step inner padding horizontal, section heading bottom margin, owner hub section gap |
| lg | 24px | Wizard card outer padding, hero card padding (vertical), between-section gap, step-to-step gap |
| xl | 32px | Page-level top/bottom padding, wizard container max-width padding |
| 2xl | 48px | Wizard empty-state vertical padding (center-aligned content in waiting states) |
| 3xl | 64px | Not used in this phase |

Source: 27-UI-SPEC.md Spacing Scale (carry-forward).

Exceptions:
- Personal Nous avatar on owner hub hero card: 80px × 80px (matches Phase 27 HeroCard avatar spec — D-05)
- Step indicator circles: 28px × 28px (non-grid; sized for legibility at wizard progress bar)
- Payment polling pulse dots: 8px × 8px circles (matches Phase 26/27 loading dot spec)
- Touch targets for wizard navigation buttons: min 44px height (WCAG 2.1 AA)
- Seed card minimum touch area: 44px height at minimum (WCAG 2.1 AA)

## Typography

Approved scale: exactly 4 sizes, exactly 2 weights (carry-forward from 27-UI-SPEC.md).

| Role | Font | Size | Weight | Line Height | Usage |
|------|------|------|--------|-------------|-------|
| Display / Hero name | `var(--serif)` | 28px | 600 | 1.1 | Personal Nous name on owner hub hero card |
| Section heading / Wizard step heading | `var(--serif)` | 20px | 600 | 1.2 | Wizard step headings ("Name Your Nous", "Choose a Seed", "Pick a Region", "Confirm & Pay"), owner hub section heading, seed card titles |
| Body / Labels / Buttons | `var(--sans-portal)` | 16px | 400 or 600 | 1.6 | Wizard field labels (sans 400), wizard input text (sans 400), seed description paragraphs (sans 400), CTA buttons (sans 600), "Spawn Your Nous" CTA (sans 600), "Chat with [Name]" button (sans 600) |
| Small labels / Metadata / Badges | `var(--mono-portal)` or `var(--sans-portal)` | 13px | 400 or 600 | 1.3 | DID preview (mono 400), seed type badge (mono 600), spawn date label (sans 400), USDT cost label (sans 400), step number label (mono 400), payment status text (sans 400 italic), error text (sans 400) |

Size-to-role mapping (exhaustive):

- **28px serif 600**: Personal Nous name in owner hub hero card only
- **20px serif 600**: Wizard step headings ("Name Your Nous" etc.), seed card titles (Explorer / Scholar / Merchant / Guardian), owner hub page heading "My Nous"
- **16px**: All interactive and prose elements — wizard `<input>` text + placeholder (sans 400), seed description paragraphs (sans 400), region select option labels (sans 400), wizard navigation buttons "Next" and "Back" (sans 600), "Spawn Your Nous" CTA on empty state (sans 600), "Spawn Nous" confirm button in wizard (sans 600), "Chat with [Name]" on owner hub (sans 600)
- **13px**: Step indicator labels (mono 400), DID preview string (mono 400), seed badge inside chip ("EXPLORER" etc., mono 600), spawn date (sans 400), USDT cost paid (sans 400), payment status update copy (sans 400 italic — "Confirming payment…"), error messages (sans 400), owner-section metadata labels (sans 400), Nous Cyber Coin balance label (sans 400)

Weight mapping:
- **400 (regular)**: All prose, wizard input text, seed descriptions, metadata labels, DID display, payment status updates, error messages
- **600 (semibold)**: Wizard step headings, seed card titles, CTA buttons, "Back" / "Next" navigation, seed badge labels, Nous name on hero card

Typography rules (inherited from 27-UI-SPEC.md):
- Nous name on owner hub hero card uses `var(--serif)` 600 — the single heading with serif in portal context.
- All wizard chrome, all inputs, all buttons, all metadata use `var(--sans-portal)`.
- Mono is reserved for immutable data: DID string, seed badge text, step numbers, tick values.
- Italic is reserved for: payment polling status text ("Confirming payment…"), spawn-not-enabled coming-soon line.

### Destructive Actions

The Spawn Nous flow is irreversible (on-chain payment + DID mint). It is not destructive but requires explicit confirmation:

- MetaMask itself provides the final wallet-signing confirmation layer
- No additional "are you sure?" modal — summary card + explicit confirmation button is sufficient
- The 409 `already_owns_nous` guard prevents accidental double-spawn

No other destructive actions exist in Phase 28.
