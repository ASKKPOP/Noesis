# Phase 38 Plan 01: Brain token manager + Grid brain_tokens store

## Objective

Build the token plumbing that lets Brain authenticate to Grid: Brain produces an EdDSA-signed JWT (existence-key signs, Civic-DID is the subject), and Grid stores the per-Brain Ed25519 public JWK in a new `brain_tokens` MySQL table with a flat revocation flag. This plan ships the foundation; the next plan (38-02) consumes the JWT over HTTPS REST and adds the action endpoint.

Token rotation policy is locked here: TTL = 24h, proactive rotation at 23h, 1h overlap during which both tokens verify against the same public key. Revocation is a single boolean flip per Brain DID.

## Context

The Brain runs on the operator's machine and already has access to a PyNaCl Ed25519 keypair via the Whisper `Keyring` pattern (`brain/src/noesis_brain/whisper/keyring.py`). The existence-DID is the operator's Nous identity key — per user decision (D-38-A4), it doubles as the operator signing key for Phase 38 (no separate human-operator credential is introduced).

Grid already validates Ed25519 JWTs through `tryDid` (`grid/src/api/preHandlers/tryDid.ts`), which uses `jose.jwtVerify`. Today it verifies tokens signed by Grid's own ES256 key pair (`keyPairPromise` from `grid/src/api/portal/auth.ts`). For Brain tokens, we add a parallel path: when the JWT's `iss` looks like a `did:noesis:nous:*` DID, `tryDid` should resolve the public key from `brain_tokens` and call `jwtVerify` against THAT key, then map `sub` → `civic_member` tier. The actual `tryDid` extension lands in Plan 38-02; THIS plan only ships the storage + registration endpoints.

The registration request is signed with the existence-DID Ed25519 key — same trust model as Phase 37 REG-01 (`POST /api/v1/registry/civic-did/request`). The route is public from a `ROUTE_DID_POLICY` perspective because the request body carries its own signature.

**Current Grid migration version is 24** (`business_did_registry`). This plan adds migration **v25 `create_brain_tokens`** with no other schema changes.

**Steps:**

1. Append `"PyJWT[crypto]>=2.8"` and `"websockets>=12.0"` to the `dependencies` list in `pyproject.toml`. Keep alphabetical order if existing entries are alphabetical; otherwise append.
2. Create `brain/src/noesis_brain/wire/__init__.py` (empty).
3. Implement `TokenManager` in `token_manager.py` with this exact public surface:

   ```python
   from dataclasses import dataclass
   from typing import Optional
   import time
   import jwt  # PyJWT
   from nacl.signing import SigningKey

   TOKEN_TTL_SECONDS = 24 * 60 * 60          # 24h
   ROTATE_BEFORE_EXPIRY_SECONDS = 60 * 60    # 1h — rotate at 23h

   @dataclass
   class TokenRecord:
       token: str               # compact JWS string
       issued_at: int           # unix seconds
       expires_at: int          # unix seconds

   class TokenManager:
       def __init__(
           self,
           *,
           existence_did: str,           # iss claim — did:noesis:nous:*
           civic_did: str,               # sub claim — did:civic:noesis:*
           signing_key: SigningKey,      # PyNaCl existence-key
           clock: Optional[callable] = None,  # time.time override for tests
       ) -> None: ...

       def create(self) -> TokenRecord: ...
       def get_valid_token(self) -> str: ...   # rotates if within 1h of expiry
       def _should_rotate(self, record: TokenRecord, now: int) -> bool: ...
       def public_jwk(self) -> dict: ...  # Ed25519 JWK for registration body
   ```

4. Inside `create()`:
   - Build payload: `{"iss": existence_did, "sub": civic_did, "iat": now, "exp": now + TOKEN_TTL_SECONDS, "scope": "brain_wire"}`.
   - Convert PyNaCl `SigningKey` to PEM private key for PyJWT: use `signing_key.encode()` to get the 32-byte seed, then build a cryptography `Ed25519PrivateKey.from_private_bytes(seed)` and call `private_bytes(...)` with PKCS8/PEM encoding. PyJWT accepts the PEM bytes directly with `algorithm="EdDSA"`.
   - Call `jwt.encode(payload, pem_private, algorithm="EdDSA")`.
   - Store the result as `TokenRecord` on the instance (`self._current: TokenRecord | None = None`).
5. Inside `get_valid_token()`:
   - If `self._current is None` → call `create()` first.
   - If `_should_rotate(self._current, now)` is True → call `create()`. The old token stays valid on the Grid side because both were signed by the same Ed25519 key against the same `iat/exp` window; Grid only rejects when `exp` passes OR when the brain_tokens row is revoked.
   - Return `self._current.token`.
6. Inside `_should_rotate(record, now)`: return `now >= record.expires_at - ROTATE_BEFORE_EXPIRY_SECONDS`.
7. Inside `public_jwk()`: derive the Ed25519 verify key via `signing_key.verify_key.encode()`, base64url-encode (no padding) the 32 raw bytes, return `{"kty": "OKP", "crv": "Ed25519", "x": "<b64u>", "alg": "EdDSA"}`.

8. **Write tests** `brain/test/wire/test_token_manager.py`:
   - `test_create_produces_valid_eddsa_jwt`: instantiate with a fresh `SigningKey`, call `create()`, decode the result with `jwt.decode(..., algorithms=["EdDSA"], key=<derived_public_pem>)`, assert `iss`, `sub`, `scope`, and `exp - iat == TOKEN_TTL_SECONDS`.
   - `test_should_rotate_at_23h`: instantiate with `clock=lambda: 1_000_000`, call `create()`, then check `_should_rotate(record, 1_000_000 + 22*3600)` is False and `_should_rotate(record, 1_000_000 + 23*3600)` is True.
   - `test_get_valid_token_rotates_proactively`: use a mutable list-based clock; after 23h, `get_valid_token()` must return a NEW token whose `iat` differs from the first.
   - `test_public_jwk_shape`: assert keys `kty`, `crv`, `x`, `alg` are present and that `x` is 43-char base64url-no-padding.

**Goal:** Grid persists per-Brain Ed25519 public JWKs with a revocation flag.

**Files:**

**Steps:**

1. Add this migration object at the end of the `MIGRATIONS` array in `schema.ts` (mirror the v23/v24 style — `CREATE TABLE IF NOT EXISTS`, InnoDB, utf8mb4):

   ```ts
   {
       version: 25,
       name: 'create_brain_tokens',
       up: `
           CREATE TABLE IF NOT EXISTS brain_tokens (
               grid_name       VARCHAR(63)  NOT NULL,
               brain_did       VARCHAR(255) NOT NULL,
               public_key_jwk  JSON         NOT NULL,
               issued_at       BIGINT       NOT NULL,
               expires_at      BIGINT       NOT NULL,
               revoked         TINYINT(1)   NOT NULL DEFAULT 0,
               revoked_at_tick INT UNSIGNED NULL,
               created_at      TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
               PRIMARY KEY (grid_name, brain_did),
               INDEX idx_revoked (grid_name, revoked)
           ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
       `,
       down: `DROP TABLE IF EXISTS brain_tokens`,
   },
   ```

2. Create `brain-token-store.ts` modeled on `civic-did-store.ts` (use `mysql2/promise` pool, accept `gridName: string` + `pool: Pool` in constructor). Public surface:

   ```ts
   export interface BrainTokenRecord {
       brainDid: string;
       publicKeyJwk: Record<string, unknown>;  // {kty,crv,x,alg}
       issuedAt: number;                       // unix seconds
       expiresAt: number;                      // unix seconds
       revoked: boolean;
   }

   export class BrainTokenStore {
       constructor(opts: { gridName: string; pool: Pool }): ...
       insert(rec: BrainTokenRecord): Promise<void>;   // INSERT IGNORE — re-registration is a no-op
       upsert(rec: BrainTokenRecord): Promise<void>;   // INSERT ... ON DUPLICATE KEY UPDATE (used for rotation)
       getByDid(brainDid: string): Promise<BrainTokenRecord | null>;
       revoke(brainDid: string, atTick: number): Promise<boolean>;  // returns true if a row was updated
       isRevoked(brainDid: string): Promise<boolean>;
   }
   ```

   Implementation notes:
   - `insert`: `INSERT IGNORE INTO brain_tokens (grid_name, brain_did, public_key_jwk, issued_at, expires_at, revoked) VALUES (?, ?, ?, ?, ?, 0)`.
   - `upsert`: same INSERT but with `ON DUPLICATE KEY UPDATE public_key_jwk=VALUES(public_key_jwk), issued_at=VALUES(issued_at), expires_at=VALUES(expires_at), revoked=0, revoked_at_tick=NULL`. This is the rotation path — re-registering a new public key implicitly clears any prior revocation. Document this in a code comment.
   - `getByDid`: `SELECT public_key_jwk, issued_at, expires_at, revoked FROM brain_tokens WHERE grid_name=? AND brain_did=?` — `LIMIT 1`. Parse `public_key_jwk` from MySQL JSON column (mysql2 deserializes it automatically).
   - `revoke`: `UPDATE brain_tokens SET revoked=1, revoked_at_tick=? WHERE grid_name=? AND brain_did=? AND revoked=0`. Returns `affectedRows === 1`.
   - `isRevoked`: `SELECT revoked FROM brain_tokens WHERE grid_name=? AND brain_did=?`. Returns `true` if row exists AND `revoked=1`; returns `false` if not found (no row → unknown brain DID → caller decides what to do).

**Steps:**

1. **Routes** — implement `registerBrainTokenRoutes(app, services)`:

   **`POST /api/v1/brain/token/register`** body:
   ```json
   {
     "brain_did":         "did:noesis:nous:<key>",     // existence-DID
     "civic_did":         "did:civic:noesis:<civicid>", // bound Civic-DID for sub claim
     "public_key_jwk":    {"kty":"OKP","crv":"Ed25519","x":"<b64u>","alg":"EdDSA"},
     "expires_at":        <unix-seconds>,               // issued_at + 24h on the Brain side
     "issued_at":         <unix-seconds>,
     "signature":         "<base64url ed25519 sig>"     // existence-key signs the canonical request
   }
   ```

   Handler steps:
   - Validate shape: every field present and well-typed. Return 400 with `{error:'invalid_request'}` on mismatch.
   - Validate `brain_did` matches `/^did:noesis:nous:[a-z0-9_\-]+$/i` and `civic_did` matches `/^did:civic:noesis:[a-z0-9_\-]+$/i`. Reuse the `ANY_DID_RE` family if convenient but keep these regexes inline so callers can read the intent.
   - Verify `civic_did` exists in `civic_did_registry` with `status='active'` (use `services.civicDidStore.get(civic_did)`); 403 with `{error:'civic_did_not_active'}` if missing/revoked.
   - Verify the signature: canonical message is the UTF-8 of `JSON.stringify({brain_did, civic_did, public_key_jwk, issued_at, expires_at})` with keys in that exact order. The signature is the existence-key signing this exact byte string. To verify: build a `nacl` verify key from the JWK's `x` field (base64url-decoded), call `verify(message, sig)`. Use `@noble/ed25519` or `tweetnacl` if either is already in `grid/package.json`; otherwise use Node's built-in `crypto.verify('ed25519', ...)` (Node 18+ supports `ed25519` directly via raw KeyObject — preferred since it's stdlib). Reject with 401 `{error:'invalid_signature'}` on failure.
   - Call `services.brainTokenStore.upsert({brainDid: brain_did, publicKeyJwk: public_key_jwk, issuedAt: issued_at, expiresAt: expires_at, revoked: false})`.
   - Emit a structured Pino log entry `{event:'brain_token.registered', brain_did, civic_did}` — no audit event (allowlist delta is 0 for Phase 38).
   - Respond 200 `{ok:true, brain_did, expires_at}`.

   **`POST /api/v1/brain/token/revoke`** body:
   ```json
   { "brain_did": "did:noesis:nous:<key>" }
   ```

   This route's ROUTE_DID_POLICY entry is `government_only` — per D-V3-18, only a Government session (per court order) may revoke a Brain token. The handler simply:
   - Reads `services.currentTick()` (existing helper used by Phase 37 routes) — fallback to `0` if absent in test wiring.
   - Calls `services.brainTokenStore.revoke(brain_did, currentTick)`.
   - Returns 200 `{ok:true, brain_did, revoked:true}` if a row was updated; 404 `{error:'unknown_brain_did'}` otherwise.
   - Pino log `{event:'brain_token.revoked', brain_did, tick}`.
