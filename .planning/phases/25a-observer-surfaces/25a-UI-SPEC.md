## Spacing Scale

Declared values (all multiples of 4px — matches existing codebase usage):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Dot gap in `Dot` component, label margin-bottom on compact forms |
| sm | 8px | Nav link padding-block, badge gap, compact row padding |
| md | 16px | Default table cell padding, card section padding inline, sidebar padding |
| lg | 20px | Card padding (steward-card inner sections), form group padding |
| xl | 24px | Page section gaps, stat card padding, sidebar logo area |
| 2xl | 28px | Margin below page h1, section spacer between cards |
| 3xl | 32px | Main content padding, grid gap between stat cards |

Exceptions:
- Firehose rows: 8px top/bottom padding (`sm` token), 16px inline — uses the canonical `xs` = 8px token; density achieved through line-height (16px), not sub-grid padding
- Drive bar container height: 8px (xs × 2) — fixed visual element
- Card header `::before` accent stripe: 3px — existing steward-card pattern, not a spacing token

## Surface Contracts

### Surface 1: /firehose

**Route:** `steward/src/app/firehose/page.tsx` (new)
**StewardShell props:** `title="Live Firehose"`, `breadcrumb="Steward · Firehose"`

#### Layout

```
StewardShell
  [header] Live Firehose          [connection status pill]
  [status bar] "N events · WebSocket connected · auto-scroll ON"
  [firehose viewport — fills remaining viewport height, overflow-y scroll]
    [row] [family-dot] [timestamp] [event-type badge] [actor-DID truncated]
    [row] ...
  [pause indicator — fixed bottom of viewport, hidden when auto-scrolling]
```

#### Row Anatomy

Single-line row. No expand. No filters. Density is the design goal.

| Slot | Content | Style |
|------|---------|-------|
| Family dot | 6px circle | Color from event-family color table above |
| Timestamp | `HH:MM:SS.mmm` (24h, milliseconds) | 10px mono, `var(--muted)`, fixed width 80px, right-padded |
| Event-type badge | `event_type` string | 10px mono, rounded 3px, badge-tint bg + badge-text color per family; padding 2px 6px |
| Actor DID | Truncated: first 8 chars + `…` + last 6 chars | 11px mono, `var(--muted)` |

Row height: 32px total (8px padding-top + 16px line-height + 8px padding-bottom). At 1440p with
52px header + 32px status bar, approximately 45 rows visible at once.

Row left-border: 3px solid, family color (matches the left-border pattern of `.steward-nav-link.active` but applied per-row).

Row hover: `background: rgba(0,0,0,0.03)` — subtle, does not fight the left-border color.

Accessibility: each row must have `role="row"` or be a `<tr>` in a `<tbody>` (recommended — use `<table>` for keyboard traversal). Screen-reader label: `aria-label` on the family dot span = `"{family} event"`. The event-type badge is readable text; no additional ARIA needed.

#### Auto-scroll behavior

- Default: auto-scroll to newest row (`.scrollTop = .scrollHeight` on each new event)
- Pause trigger: `onMouseEnter` on the viewport container
- Resume trigger: `onMouseLeave`
- Paused state indicator: fixed pill at bottom of viewport — `background: rgba(184,84,47,0.12)`, `border: 1px solid var(--terracotta)`, text "Paused — hover to resume" in 10px mono `var(--terracotta)`. Fades in/out with CSS transition 150ms.
- Pause does NOT stop the WebSocket — events continue buffering in state. On resume, render up to 200 buffered rows; drop older ones (client-side ring buffer, capacity 200).

#### Connection status pill

Displayed in top-right of the StewardShell header area (inject via a sticky banner below the
header, not inside the header chrome which belongs to StewardShell).

| State | Text | Style |
|-------|------|-------|
| Connecting | "Connecting…" | `var(--muted)` |
| Connected | "Connected" | `#2d7a2d` with green dot |
| Disconnected | "Disconnected — retrying in Xs" | `var(--terracotta)` with orange dot |

Reconnect strategy (Claude's Discretion — specified here for executor): exponential backoff,
initial 1s, doubles each attempt, capped at 30s. Display countdown in disconnected pill.

#### Empty / error states

| Condition | Display |
|-----------|---------|
| No events yet (connected) | Row area empty; status bar shows "0 events · waiting…" |
| WebSocket disconnected | Overlay inside viewport: centered, `var(--muted)`, 13px sans, "Connection lost. Reconnecting in Xs." No blocking modal. |
| Grid unreachable | Same overlay: "Could not connect to Grid. Retrying…" |

### Surface 2: Cognitive Inspector (inline on /nous/[id])

**Mount point:** `steward/src/app/nous/[id]/page.tsx` — add after the existing "Brain State" card,
before the "Force Telos" card.

**Card title:** "Cognitive Inspector"

**Auth note:** This card is visible only to H3+ operators. For 25a the Steward has no operator-tier

```
steward-card
  [3px terracotta stripe — inherited from .steward-card::before]
  [header] "Cognitive Inspector"      [H3 tier badge — mono 9px muted "H3+"]
```

#### Hashes row

Not returned by the cognitive-snapshot endpoint (hashes travel on the normal audit wire). This row
renders three hash fields from the existing brain-state fetch (`/api/v1/nous/:did/state` — already
fetched by the existing page). Display them in a single row of mono pills:

| Pill | Label | Value |
|------|-------|-------|
| Memory | "mem" | first 12 chars of memory hash |
| Creed | "creed" | first 12 chars of creed hash |
| Skill | "skill" | first 12 chars of skill hash |

Each pill: `background: var(--parchment)`, `border: 1px solid var(--rule)`, `border-radius: 4px`,

Three inline stat cells, side-by-side (flexbox, `gap: 24px`):

| Cell | Label | Value source |
|------|-------|-------------|

Each cell: label in 9px mono uppercase `var(--muted)`, value in 20px serif `var(--ink)` (matches

#### Drive bars section

Label: "Drive Levels" in 10px mono uppercase `var(--muted)`, margin-bottom 12px.

Five horizontal bars, one per drive, in display order: HUNGER · CURIOSITY · SAFETY · BOREDOM · LONELINESS.

Each bar:
```
[drive label 9px mono uppercase muted, width 88px fixed]  [bar track] [value 10px mono muted right-align, width 36px]
```

Bar track: height 8px, `border-radius: 4px`, `background: var(--rule)` (track), inner fill uses
drive-specific color (see below), `width: {level * 100}%` where level is 0.0–1.0 float.

Drive colors (fill of horizontal bar):

| Drive | Fill color | Rationale |
|-------|-----------|-----------|
| HUNGER | `#b8542f` (terracotta) | Physical need; urgent/warm |
| CURIOSITY | `#3a7a5a` (sage) | Intellectual; calm growth |
| SAFETY | `#3a4a7a` (indigo) | Security; cool, stable |
| BOREDOM | `#8a8479` (muted gray) | Neutral flatness |
| LONELINESS | `#6a4a7a` (mauve) | Social; quiet purple |

All five drives always render (if `drive_levels` key is missing for a drive, fill is 0 and label
shows "—" in value slot).

Accessibility: each bar row must have `role="meter"`, `aria-valuenow={level*100}`,
`aria-valuemin="0"`, `aria-valuemax="100"`, `aria-label="{DriveName} drive level"`.

#### Skill titles section

Label: "Top Skills" in 10px mono uppercase `var(--muted)`, margin-bottom 8px.

K=10 skill titles rendered as a flat list (no chips/tags — plain text list for density).
Each item: 13px sans `var(--ink)`, 4px padding-block, no border. If title exceeds 60 characters,
truncate with `…` and show full title in `title` attribute.

If `skill_titles_topk` is empty: "No skills recorded." in 12px mono `var(--muted)`.

#### Sleep + creed metadata row

Two inline cells (flexbox, `gap: 24px`, `margin-top: 16px`):

| Cell | Label | Value |
|------|-------|-------|
| Last sleep | "Last Sleep Tick" | `last_sleep_tick` — numeric, formatted with `toLocaleString()`. If 0, show "Never". |
| Creed violations | rendered in counts row above; not duplicated here |

#### Loading + error states

| State | Treatment |
|-------|-----------|
| Loading cognitive snapshot | Each section shows `…` inline — do not block card render |
| Brain endpoint timeout / 503 | Single inline message in the card body: "Cognitive snapshot unavailable — Brain offline." 12px mono `var(--muted)`. Hashes row still renders from existing brain-state fetch. |
| H3 tier 403 | "H3+ operator tier required to access cognitive snapshot." 12px mono `var(--muted)`. |
| Nous not found / tombstoned | Existing page handles this; card inherits null state |

### Surface 3: Brain Health Metrics (inline on /nous/[id])

**Mount point:** `steward/src/app/nous/[id]/page.tsx` — add after the Cognitive Inspector card,
before the "Force Telos" card.

**Designer's recommendation on placement:** Brain health is per-Nous data (metric families 1–4 are

#### Card structure: four metric cards in a 2×2 grid

```
[section heading] "Brain Health"   [section sub-label: "Derived from audit events — read-only"]
[2-column grid, gap 16px]
  [Card A] Tick Performance
  [Card B] Memory Stores
  [Card C] Drive & Sleep
  [Card D] Coherence
```

Each card is a `steward-stat-card` (parchment background, 3px terracotta stripe, border 1px rule,
border-radius 10px). Cards do NOT use `steward-card` (vellum bg) — stat-card background
distinguishes them visually as metrics, not editable sections.

#### Card A: Tick Performance

| Metric | Value | Format |
|--------|-------|--------|
| Tick latency p50 | `p50` from `GET /api/v1/nous/:did/tick-metrics` | `{N}ms` — mono 20px serif |
| Tick latency p95 | `p95` | `{N}ms` — mono 20px serif |
| Queue depth | `queue_depth` | integer — mono 14px |

Layout: p50 and p95 as two side-by-side large numerics (same pattern as stat strip in Dashboard).

#### Card B: Memory Stores

| Metric | Value | Source event |
|--------|-------|-------------|

| Rule count | `rule_count` | `nous.self_model_revised` count for DID |

Layout: three stat cells stacked vertically, label 9px mono uppercase muted + value 20px serif ink.

#### Card C: Drive & Sleep

| Metric | Value |
|--------|-------|
| Last known drive levels | Most recent `ananke.drive_crossed` per drive (5 drives) |
| Sleep cadence | Average delta between consecutive `nous.sleep.entered` / `nous.sleep.completed` pairs, in ticks |
| Last sleep duration | Last `nous.sleep.completed.tick - nous.sleep.entered.tick` |

but compressed — bar height 6px, no value text, just label + bar). Sleep cadence and last duration

#### Card D: Coherence

| Metric | Value |
|--------|-------|
| Creed violations | Total count of `nous.creed_violation` for this DID |

Layout: single large numeric — 36px serif `var(--ink)`. If count > 0, color the number
`var(--terracotta)` to signal attention. Label: "Creed Violations" 9px mono uppercase muted.

If count = 0: number renders in `var(--ink)` (not muted — zero is a positive state).

#### Brain Health loading / error states

| State | Treatment |
|-------|-----------|
| Loading | Each card shows "…" in metric slots |
| Audit query fails | Card shows "Could not load health metrics." 12px mono muted |
| No data (new Nous) | All counts show 0 — rendered correctly, not as errors |

Panel header: 14px sans `var(--terracotta)`, weight 500. Count badge: existing `.badge` class with

Polling: every 5s (`setInterval`). "Last updated Xs ago" counter updates every second.

Text: "No drift detected. All runtime emissions are allowlisted." This gives operators
positive confirmation, not just absence of content.

Position: Drift Alert Panel appears ABOVE the static reference table. Operators see runtime health
before the reference list.

## Read-Only Surface Communication

All five surfaces are purely observational. These rules make "this is not a control panel" legible
without adding copy:

1. **No action buttons** on firehose rows, brain health cards, or cognitive inspector fields. The
   only interactive elements are: WebSocket pause (hover-only, no button), drift-alert polling
   (automatic), tab switching on `/humans/[did]`.

2. **Stat-card typography for metrics**: using the 20–36px serif numeral pattern (same as
   Dashboard stats) communicates "this is a reading, not an input." Operators are trained to
   expect forms and buttons in `steward-card` sections, stats in `steward-stat-card` sections.

3. **No hover-to-edit on any field**: all values are plain text or mono pills, never `<input>`-
   adjacent. No underline on hover for values.

4. **Section eyebrows**: each new section (Cognitive Inspector, Brain Health, Allowlist Monitor)
   has a 10px mono uppercase muted eyebrow label, same as the existing breadcrumb pattern. This
   scopes the section as informational metadata.

5. **Firehose page title context**: the StewardShell breadcrumb `"Steward · Firehose"` and page
   h1 `"Live Firehose"` set expectations. No search bar, no filter UI, no column sort — the
   absence of controls communicates read-only status.

## Accessibility Contract

Minimum standard: WCAG 2.1 AA for all five surfaces. Desktop-first; minimum supported viewport
width 1280px. No tablet/portrait-specific layout (Steward Console is operator-facing desktop
tooling; sidebar collapse is out of scope for 25a).

| Requirement | Implementation |
|-------------|---------------|
| Keyboard navigation in firehose | `<table>` with `<tbody>` rows; Tab/Shift-Tab traverses rows. No interactive elements inside rows to focus. |
| Keyboard tab switching on `/humans/[did]` | `role="tablist"` on container, `role="tab"` on each button, `aria-selected` per active tab, `role="tabpanel"` on content area. Arrow keys switch tabs. |
| Screen-reader label for firehose family dot | `aria-label="{family} event"` on the colored dot `<span>`. |
| Drive bar ARIA | `role="meter"` + `aria-valuenow` + `aria-label` per bar (specified in Surface 2 contract above). |
| Drift alert panel | `role="alert"` on the panel when new drift entries arrive (live region). `aria-live="polite"` on count badge. |
| Color not sole differentiator | Firehose event-type badge includes the text of the event type (not color-only). Family dot is decorative (color + `aria-label`). |
| Focus ring | All interactive elements: `outline: 2px solid var(--terracotta)`, `outline-offset: 2px`. No `outline: none` anywhere in new code. |
| Contrast | All family badge text colors verified at design time (see event-family color table). Executor must not adjust colors without contrast check. |
| Skip link | StewardShell already lacks a skip-to-main link; do not add or remove one in 25a (surgical-change rule). |
