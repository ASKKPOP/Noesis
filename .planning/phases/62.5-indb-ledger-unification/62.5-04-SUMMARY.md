# Phase 62.5 Plan 04: Retire Ledger B as money — Summary

Irreversible cut of the money migration: Ledger-B faucet money zeroed via schema v74, `NousRegistry.transferWei` deleted, the operator slash retargeted from an in-memory registry debit to a real fine (nous_accounts → civic_treasury), and the last dead `nous_registry.balance_wei` read removed from the portal. In-DB money now lives exclusively on the civic-keyed Ledger A (`nous_accounts` + `civic_treasury`).

## What shipped (per task)

**Task 1 — One-time data migration (schema v74).** Appended `{ version: 74, name: 'retire_ledger_b_faucet_money' }`: `up` = `UPDATE nous_registry SET balance_wei = 0` (ZERO decision — the residual balances are retired faucet money; Phase 62.6 already moved every legitimate balance to `nous_accounts`). The `balance_wei` column is kept for history (inert). `down` is a documented irreversible no-op (`SELECT 1`) — satisfies the non-empty-down schema invariant. New `test/db/schema-v74.test.ts` asserts version, name, `up` zeroes `balance_wei` (string-match), no-op `down`, and sequential/latest invariants. Commit `98a626bd`.

**Task 2 — Remove `NousRegistry.transferWei`.** Deleted the method (no production callers remained after 62.6). Updated four src doc-comments (registry / credit-ledger / community-store / launcher) to past tense / point at the `nous_accounts` rails — logic unchanged. `NousRecord.balance_wei` field stays (inert, zeroed persistence). Test fallout handled: deleted the method's own unit test; replaced the in-memory transfer callers in `house-3`/`house-4` e2e with a local `moveWei` helper that reproduces the exact debit→credit on the in-memory records (keeping those suites' Ledger-B balance assertions valid); dropped the retired verb from the governance-runner mock; removed the obsolete buyer→treasury `transferWei` assertion in `treasury-seed.test.ts` (the treasury registry record itself is retired in 62.5-05). Commit `d664b6da`.

**Task 3 — Retarget slash-coin to fine→treasury.** The punitive slash now resolves the target existence-DID → civic-DID (`CivicDidStore.getByExistenceDid`), reads its `nous_accounts` balance, computes `fine = min(BigInt(amount), balance)`, and (when `fine > 0n`) calls `NousAccountStore.chargeToTreasury` (debit account → credit `civic_treasury`, atomic). Money moves to the commons — never vanishes — preserving the no-mint/no-burn conservation invariant. Punitive clamp preserved (no 409); a target with no civic-DID / no account / no DB pool moves no money but the sanction still emits. The `operator.slashed` emit is byte-identical — same sole-producer success-only position, same payload including the requested `amount` (no allowlist change / D-8, R-31-01 zero-diff, D-25b-11 reason discipline unchanged). The 410/404/403/400 error ladder is unchanged. Tests replace the registry-balance assertions with Ledger-A conservation checks (account debited + `civic_treasury` credited by `min(amount,balance)`; clamp beyond balance; single emit) via a fake wei-rails pool carrying a `civic_did_registry` mapping. Commit `57f16b07`.

**Task 4 — Portal dead read.** Removed `balance_wei` from `getOwnedNous`'s `SELECT ... FROM nous_registry` column list and from the row type — it was selected but never returned. Zero behavior change (the returned object is identical). Commit `fda3f212`.
