# Phase 34.1: HealthWatchdog Wiring Followups — Verification Report

## Purpose

Phase 34 operator UAT (2026-05-25, 34-VERIFICATION.md) discovered two cross-phase wiring gaps that blocked the ROADMAP §Phase 34 SC #5 60-second recovery SLA from being visually verifiable on Steward `/system`. Phase 34.1 closes both gaps with a single surgical change to `HealthWatchdogDeps`.

## Changes Shipped

### `grid/src/diagnostics/health-watchdog.ts`

Added optional `auditChain` field to `HealthWatchdogDeps`:

```typescript
auditChain?: {
    readonly length: number;
    readonly lastPersistError?: { code: string; at: number } | null;
};
```

`snapshot()` updated to:
1. **FOLLOWUP-34-01:** Read `in_memory_length` from `auditChain.length` when wired (Phase 32 fallback `inMemoryLength = persistedMaxId` preserved when absent for backward compat with legacy tests + no-DB launchers).
2. **FOLLOWUP-34-02:** Merge `auditChain.lastPersistError` (PersistentAuditChain — tick-time failures) with `reconcile.lastPersistError` (replay-time failures), taking the most recent by `.at` timestamp.

### `grid/src/api/server.ts`

Construction site (line 602) updated to pass `services.audit as auditChain`. The cast tolerates both plain `AuditChain` (no `lastPersistError` property) and `PersistentAuditChain` (has it) — duck-typed against the optional getter.

### FOLLOWUP-34-02 — VERIFIED ✓

- `last_persist_error` populated at T+30s with `{code: "ENOTFOUND", at: 1779745251669}` — the FIRST PersistentAuditChain.append failure after MySQL stopped.

## Recovery SLA Note

The post-MySQL-restart "60-second recovery to green" target from ROADMAP §Phase 34 SC #5 was NOT fully verified in this UAT because:

1. **Docker DNS cache** kept the Grid container resolving `mysql` to a stale address for ~2+ minutes after the container restarted.
2. **Reconcile loop cadence** (every 60 ticks; at ~30s/tick that's 30 minutes) is the only thing that would clear `persisted_max_id` divergence after the failures stop.

The recovery SLA is a separate Phase 31/32 concern — it's not blocked by Phase 34.1's card-rendering wiring. Recommendations for a future phase:
- **Phase 31 follow-up**: tighten reconcile cadence to 5 ticks (~2.5 min) for faster recovery
- **Operations**: document that Grid container should be restarted after extended MySQL outages to clear DNS cache, OR switch to `mysql://` with TTL=0 resolver
