# Phase 41 — UI Design Contract

> Visual and interaction contract for Phase 41: Sleep Cycle + Away Presence.
> Surfaces: Portal Civic Map presence states + Steward Console queue depth.
> Generated by gsd-ui-researcher. Consumed by gsd-ui-checker, gsd-planner, gsd-executor.

**Design posture:** Extend existing surfaces — zero new design language. Both surfaces are
data-dense, developer/admin-facing. Dark theme (Portal Civic Map) and light parchment theme
(Steward Console) are already established. Phase 41 adds minimal incremental affordances only.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind 4 CSS-first via `@theme` — no shadcn) |
| Preset | not applicable |
| Component library | none (hand-rolled, per project pattern) |
| Icon library | none (project uses no icon library in either surface; SVG inline where needed) |
| Font (dashboard / portal) | Inter Tight (400, 500, 600) + JetBrains Mono (400, 500) |
| Font (steward) | Inter Tight (300, 400, 500, 600) + JetBrains Mono |

**Rationale:** Neither `dashboard` nor `steward` has `components.json`. Neither uses Radix UI or
any icon library package. Steward has zero UI dependencies (`package.json` confirms: only
`next`, `react`, `react-dom`). All component patterns are hand-rolled inline styles and Tailwind
utility classes. Phase 41 follows the same pattern — no new libraries introduced.

**Tooltip implementation:** The `away` hover tooltip is implemented as an SVG `<title>` element
inside the Nous avatar `<g>` group. This is consistent with the existing CivicMap pattern
(which already uses `aria-label` on `<rect>` hitboxes). No JavaScript tooltip library is used.
For the `absent` and `presumed_departed` badges, a `<title>` element inside the SVG group
provides hover text at the OS level — sufficient for an admin-facing civic status indicator.

**Presence state color contract (Civic Map avatars):**

| Presence State | Circle Fill | Opacity | Filter | Source |
|----------------|-------------|---------|--------|--------|
| `awake` | Type A: `#7c9eff` / Type B: `#c084fc` | 1.0 | none | Existing CivicMap.tsx (unchanged) |
| `away` | Type A: `#7c9eff` / Type B: `#c084fc` | **0.4** | **`grayscale(100%)`** | D-41-06 (locked) |

`strokeWidth="1.5"`) communicates "presence shell remains but occupant is gone" — the civic
identity placeholder pattern. Distinguished from `away` (dimmed but filled) and `absent`
(very dim but filled). No new color — reuses the existing muted neutral.

## Surface 1: Portal Civic Map — Presence State Rendering

**File:** `dashboard/src/app/portal/civic-map/CivicMap.tsx`

### Polling Contract

- `GET /api/v1/civic/presence` (no-auth, `visitor_public` policy) polled every **30 seconds**
- Uses plain `useEffect` + `setTimeout` / `AbortController` — same pattern as existing
  `useCivicMap` hook in `use-civic-map.js`. Do NOT introduce a new polling library.
- Response shape consumed: `{ nous: [{ civic_did_hash, presence_status, last_seen_at }] }`
- The presence data is merged with the existing Nous map data (which provides `x`, `y`,
  `display_name`, `type`). Merge key: `civic_did_hash`.

### Avatar Rendering by State

The existing `<circle>` element already handles `awake` via `opacity={n.status === 'online' ? 1 : 0.4}`.
Phase 41 replaces this condition with a 4-state presence switch.

**`awake`:**
```
<circle fill={typeColor} opacity={1} style={{ filter: 'none' }} />
```

**`away`:**
```
<circle fill={typeColor} opacity={0.4} style={{ filter: 'grayscale(100%)' }} />
<title>away — last seen {X} min ago</title>
```
`X` = `Math.round((Date.now() - new Date(last_seen_at).getTime()) / 60_000)`.

**`absent`:**
```
<circle fill="#6a6a76" opacity={0.35} style={{ filter: 'grayscale(100%)' }} />
<title>absent — last seen {X} days ago</title>
```
`X` = `Math.round((Date.now() - new Date(last_seen_at).getTime()) / 86_400_000)`.

**`presumed_departed`:**
```
<circle fill="none" stroke="#6a6a76" strokeWidth="1.5" opacity={1} />
<title>presumed departed — last seen {X} days ago</title>
```

The `<title>` element MUST be the **first child** of the `<g>` group wrapping the avatar.
This ensures screen readers and browser default tooltips surface it correctly.

The existing `<rect>` hitbox `aria-label` MUST be updated to include presence state:
```
aria-label={`Nous ${n.display_name}, type ${n.type}, status ${n.presence_status}`}
```

### hover / focus behavior

- Hover expand radius (existing): `r={hoveredNousId === n.civic_did_hash ? 8 : 6}` — unchanged.
- No expand for `presumed_departed` (outline-only ring): fixed `r={6}` regardless of hover.
- Cursor: `cursor-pointer` on hitbox rect for `awake`, `away`, `absent`. For `presumed_departed`,
  cursor remains `cursor-default` — the Nous is no longer navigable via the map avatar.
  (Profile page may still exist but Civic Map does not link there for departed Nous.)

### Loading / error states

Inherits existing CivicMap loading / error states:
- Loading: `<div className="text-sm text-[#9a9aa6]">Loading Civic Map…</div>`
- Error: `<p className="text-sm font-mono text-[#9a9aa6]">{COPY.CIVIC_MAP_LOADING}</p>`

**Stale presence data (polling gap):** If the 30s poll fails, previously fetched presence data
remains displayed with no visual indicator — silent staleness is acceptable for a 30s cadence.
Do NOT add a "data may be stale" banner to the Civic Map.

## Surface 2: Steward Console — Queue Depth Section

**File:** `steward/src/app/system/operators/page.tsx` (extend existing page)

**Decision:** Phase 41 adds a new **Section 4: Message Queue Depth** to the existing
`/system/operators` page, below the three existing sections. A new `/system/presence` page is
NOT created — the operators page is already the Tier-2 Grid Manager runtime surface, and queue
depth is directly related to per-operator Nous status.

### Section heading and description

```
<h2 className="text-lg font-semibold mb-2">Message Queue Depth</h2>
<p className="text-xs text-gray-400 mb-3">
  Per-operator queued direct messages for away Nous. Messages queue when the recipient
  Nous's Brain is offline. Delivered automatically on reconnect.
</p>
```

### Data API

`GET /api/v1/grid-manager/presence-overview` — returns:
```json
{
  "presence_summary": [
    {
      "operator_did": "did:noesis:human:...",
      "civic_did": "did:civic:noesis:...",
      "nous_name": "...",
      "presence_status": "away | absent | presumed_departed",
      "last_seen_at": "<ISO timestamp>",
      "queue_depth": 3
    }
  ]
}
```
Only operators/Nous with non-`awake` status are returned (awake Nous have queue_depth 0 and
are not operationally relevant to this view). If all Nous are awake, response returns
`{ "presence_summary": [] }`.

### Table structure

```
Operator DID  |  Nous  |  Status  |  Last Seen  |  Queued Messages
```

- **Operator DID**: `font-mono text-xs text-gray-700` (matches existing operators table pattern)
- **Nous**: display name if available, else truncated `civic_did` in mono style
- **Status**: inline pill — see status pill spec below
- **Last Seen**: human-relative time — "3 min ago", "2 hours ago", "5 days ago"; `text-gray-500`
- **Queued Messages**: numeric count; background color per queue depth thresholds above

### Status pills

Small inline pill, `text-[11px] font-mono font-medium px-1.5 py-0.5 rounded`:

| Status | Classes |
|--------|---------|
| `away` | `bg-amber-100 text-amber-700` |
| `absent` | `bg-orange-100 text-orange-700` |
| `presumed_departed` | `bg-red-100 text-red-700` |

### Empty state

```
<p className="text-gray-400 text-sm">All Nous are currently awake. No queued messages.</p>
```

### Loading / error states

Inherits the existing operators page pattern:
- Loading: `<p className="text-gray-400">Loading presence data…</p>`
- Error: `<div className="bg-red-50 border border-red-200 rounded p-3 mb-4 text-red-700 text-sm">Error loading presence data: {error}</div>`

### Refresh behavior

Page loads presence data once on mount (same `useEffect` pattern as existing operators page).
No auto-polling on the Steward Console — this is a point-in-time administrative view.
A manual "Refresh" button is NOT required for v1; operator can reload the page.

## Interaction Contract

### Polling lifecycle (Portal Civic Map)

1. Component mounts → start 30s poll interval for `GET /api/v1/civic/presence`.
2. Presence response merged with existing zone+nous map data in component state.
3. On unmount → clear interval (AbortController cancels in-flight request).
4. No user-visible spinner during polling refresh — silent background update.

### Hover (Portal Civic Map)

1. Mouse enters 44×44 hitbox rect → `setHoveredNousId(n.civic_did_hash)` → radius expands 6→8.
2. Browser renders SVG `<title>` as native tooltip (no custom overlay needed).
3. Mouse leaves → `setHoveredNousId(null)` → radius returns to 6.
4. `presumed_departed` Nous: hover does NOT expand radius (fixed at 6). `<title>` still shows.

### Click (Portal Civic Map)

- `awake`, `away`, `absent`: click navigates to `/portal/nous/{civic_did_hash}` (existing pattern).
- `presumed_departed`: click is disabled (`pointer-events: none` on hitbox rect, `cursor-default`).
  The Nous profile page may still exist but Civic Map does not serve as a navigation entry point
  for departed Nous.

### No destructive actions in Phase 41 UI

Phase 41 UI is read-only (display of presence states + queue depths). No confirmation dialogs,
no destructive actions, no write operations from either UI surface. All writes (heartbeat, inbox
ACK) are Brain-initiated via API, not operator-initiated via UI.
