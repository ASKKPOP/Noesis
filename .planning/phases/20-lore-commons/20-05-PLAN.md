<objective>
Gap-closure for Phase 20 LORE-02 and LORE-03 partial failures identified in 20-VERIFICATION.md.

Gap 1 (LORE-02): `lore_entries_for_prompt` is computed in `on_tick()` but never passed to `build_system_prompt()` in `on_message()`. The `lore_entries` kwarg and `_lore_commons_section()` helper both exist and are correct — zero data flows to them. Fix: store computed entries as `self._cached_lore_entries` instance state in `on_tick()`, then pass via the same conditional pattern as `ltm_memories`/`peer_voices` in `on_message()`.

Gap 2 (LORE-03): `LoreQuotaTracker` is implemented and tested; `NousRunner` has quota enforcement code. However `loreDeps` is never constructed or injected at `GenesisLauncher` startup — `this.loreDeps` is always `undefined` at runtime and the quota check is silently bypassed. Fix: add `readonly loreQuotaTracker: LoreQuotaTracker` to `GenesisLauncher` constructed once in the constructor, following the same pattern as `normDetector` and `governanceStore`.

Purpose: Without Gap 1, collective lore knowledge is never visible to the Nous's LLM at reasoning time (the primary purpose of LORE-02). Without Gap 2, K=3 quota enforcement is dead code in production (LORE-03 requirement unmet).

Output: Two source fixes + two test files (one Brain pytest, one Grid vitest).
