## Phase Boundary

Phase 58 HOUSE-1 made parcels EXIST (persisted, purchasable, buildable, visitable, mapped). Phase 59 HOUSE-2 made houses LIVE and COST something (interiors + upkeep ladder + reclaim). Phase 60 HOUSE-3 put OTHER minds to work in your walls (typed roles, invitations, paid co-work, mutual-credit IOU ledger, shop⇄structure binding, streaming structure revenue, `place://` NDS names, ring-expansion bill template). HOUSE-4 — the FINAL Nous House phase — makes **blueprints culture**: a build is the execution of a **taught/diffused skill** whose Grid-side payload is a declarative interior-extension recipe. Construction becomes a co-work activity that decomposes into a sub-task **DAG**, paid (D-NH-06) and DAG-weighted by completed sub-tasks (A5 contribution split); and a workshop where a skill is taught becomes a **school** (location-aware diffusion). Build on the Phase 58/59/60 foundation; never rewrite it. This is the Voyager core loop (arXiv:2305.16291): a blueprint is a skill, building is executing it, richer cities emerge from co-build (arXiv:2503.03505 team speed-up).

## Implementation Decisions

### Blueprint skills + storage (D-NH-06 core loop / Voyager Lesson 5)
- **D-61-01 (blueprint = skill whose Grid-side payload is a declarative recipe):** a `blueprint_hash` IS a Phase 18 skill hash; it diffuses via the EXISTING `skill.taught` / `skill.inferred` machinery (ZERO new diffusion code). The Grid-side recipe body — `{objects:[{kind, area}], arrangement (sub-task DAG), material_cost_bios}` — lives in a NEW `civic_blueprints` table (migration v41) keyed by `blueprint_hash`. Recipe `kind`s are restricted to the Phase 59 closed furniture catalog (`furniture.ts`); a non-catalog kind is rejected by the existing validation gate. The `civic_blueprints` row write emits NO chain event (Grid-side recipe storage).

### Build executor (A10 BUILD lifecycle phase)
- **D-61-02 (build executor verifies skill-held via existing skill-event history):** `grid/src/civic/blueprint.ts` `buildFromBlueprint(addr, builderDid, blueprint_hash, tick, deps)` — (1) confirms the builder HOLDS the skill by querying the EXISTING skill-event history (a `skill.taught`/`skill.inferred` with `learner_did === builderDid` for `blueprint_hash` exists in the audit chain — the same lineage query `culture.ts` uses; the Brain attests, the Grid confirms); a builder who does not hold it → `skill_not_held`. (2) Debits `material_cost_bios` from the builder's Ousia → `TREASURY_DID` via `registry.transferOusia` (insufficient → 402). (3) Applies the recipe by replaying `ParcelRegistry.extendInterior` for each recipe object (the executor is the SINGLE caller of the recipe-apply path). The builder is the owner OR a staff Nous in an active co-build session (Phase 60 role edge / Cowork Agreement). Emits `skill.blueprint_executed` once per executed build.

### Co-build sessions (A5 DAG-weighted attribution / arXiv:2503.03505)
- **D-61-03 (co-build = DAG-decomposed paid sub-tasks, DAG-weighted attribution):** `grid/src/civic/co-build.ts` decomposes a recipe into atomic sub-tasks from its `arrangement` DAG (each node = catalog object(s) + dependency edges + a weight). Each sub-task is posted to the Phase 60 co-work board as a Cowork Agreement task carrying pay; completion ALWAYS settles (Ousia when funded, else a Phase 60 IOU — NEVER free, D-NH-06). **Attribution = DAG-weighted**: a participant's share = Σ(completed-node weights) ÷ Σ(all node weights), computed Grid-side from metered completion (A5: objective, not renegotiated). On full completion the executor applies the assembled recipe + emits the single `skill.blueprint_executed`. Sub-task settlement reuses the Phase 60 `zoning.cowork_session` event + IOU/Ousia path — NO new allowlist event.

### Location-aware teaching (structures become schools)
- **D-61-04 (location-aware teaching = present-occupant diffusion selector, no new event):** skill teaching gains an OPTIONAL `parcel_id` context. When a skill is taught inside a `workshop` structure, the learner set is the Nous PRESENT in that structure (the Phase 58 in-memory occupant map). This REUSES the existing Phase 18 `appendSkillTaught` / `appendSkillInferred` producers verbatim — it ONLY selects the learners; the existing `skill.taught` 5-tuple `{learner_did, parent_hash, skill_hash, teacher_did, tick}` is unchanged (NO new payload key; `parcel_id` is a Grid-side selector, off the chain). Humans present are never learners (`did:civic:noesis:human:*` excluded).

Closed-tuple payload shape (keys ALPHABETICAL):
