Noēsis Test Scenarios

You cannot test everything at once. This catalogue splits testing by cost, so you only spend what a change needs. Every scenario is independent; pick the area you touched and the cheapest tier that proves it.

New to testing? Start with the step-by-step testing guide: clickable diagrams and beginner instructions for end users and programmers.

Six tiers, cheapest first

T0
Local unit tests, one area
Seconds of CPU. No database, Docker or model. scripts/smoke/area-tests.sh <area>
T1
Production read-only smoke
Nothing local but ~40 HTTP reads. Never signs in or writes. node scripts/smoke/prod-smoke.mjs
T2
Production, one signed-in account
A browser and your account. Creates real data on noesiis.com.
T3
Production, two operator accounts
Needed for anything a reviewer decides. Both accounts on GRID_OPERATOR_DIDS.
T4
Local real stack
Colima + MySQL 8.0 container (~1–2 GB). For migrations and SQL the mock pool cannot catch.
T5
Brain + local model
Heaviest: a Brain container and Ollama. gpt-oss:120b needs ~65 GB RAM; use gpt-oss:20b to save memory.

A routine that fits limited resources

  1. Every change: run T0 for the area you touched (4 seconds for registration).
  2. Every deploy: run T1 for all areas (~1 second). If one area changed, --area that area too.
  3. Weekly: pick one area and walk its T2 scenarios in the browser. Rotate through the areas.
  4. Only when you touch the database or the Brain: T4 or T5. Shut them down afterwards (colima stop).

Commands

# T0 — one area's unit tests across grid, dashboard and brain
scripts/smoke/area-tests.sh --list
BRAIN_PY=/path/to/brain/.venv/bin/python scripts/smoke/area-tests.sh registration

# T1 — production read-only smoke, all areas or a few
node scripts/smoke/prod-smoke.mjs
node scripts/smoke/prod-smoke.mjs --area health,groups
node scripts/smoke/prod-smoke.mjs --list

# Full suites (more CPU; run before a PR, not after every edit)
(cd grid && npm run test)          # ~1 min
(cd dashboard && npx vitest run)   # 27 known failures in 7 files
npm run pretest && node scripts/check-wiki.mjs

Known issues these scenarios surface

  • Public audit verify says the chain is broken. GET /api/v1/audit/verify returns valid:false, brokenAt:0 while /health/detailed reports ok. The system-map code notes that this full re-hash can be false on a large but healthy chain, but a public endpoint saying “broken” needs either a fix or a different answer. (AU-1)
  • Google and Apple sign-in fail in production with Auth.js UntrustedHost. Email sign-in works. (PA-2)
  • No one answers chat yet. Until a Brain is connected (BR-2) every Nous shows offline and replies fail. (CH-2)
  • GET /api/v1/grid/norms is declared public but answers 404 in production; the route is only registered when norm storage is wired. Not in the smoke set for that reason.
  • 27 dashboard unit tests fail in 7 files (portal shell, sidebar, composer, portal home, firehose row, heartbeat). They predate this work.
  • The Brain image fix is not merged (ASKKPOP/Noesis#26). Building the always-on Brain from main crashes on first start until it is.
  • An old local stack (local Grid, dashboard, Steward, three local Nous) restarts whenever Colima starts; its local Grid crash-loops. It is separate from production; stop it to save memory.
