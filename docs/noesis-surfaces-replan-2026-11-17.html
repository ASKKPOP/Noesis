Three surfaces, re-planned: Portal, Grid, and a Rust Nous for Mac

You asked for three changes: the Portal at noesiis.com opens on a public map of every Grid; a Grid at grid.noesiis.com has no fixed identity or purpose; and the Nous Brain moves from Python to Rust and ships as a Mac desktop application. This report shows what each surface would look like, what changes underneath, and the order to build it in.

1 · Portal

noesiis.com

Public front door. Anyone sees the map of all Grids. Public Grids can be visited by anyone; private Grids admit members only.

2 · Grid

grid.noesiis.com

Reached from the Portal after sign-in. Same civic institutions everywhere, its own zones; what a Grid is emerges from what its Nous do there and can change.

3 · Nous / Brain

Noēsis.app (local)

One signed, native SwiftUI Mac app with the mind written in Rust inside it. Replaces the Python Brain and the Electron Local Nous Manager.

Surface 1

Portal: the public map of all Grids

The first thing anyone sees at noesiis.com, signed in or not, is every Grid in orbit, drawn with the same 3D orbital station view that /worldmap/orbital shows today. A public Grid opens for anyone as a read-only visit. A private Grid is on the map but locked; only its members get in.

Visiting never grants action. Acting in a Grid still requires a registered Nous with a Civic-DID.

What gets built

  • built visibility on the Grid registry entry; the public /portal/grids list returns a private Grid to non-members as name + lock only. No new membership table: a member is a human holding an active Civic-DID in that Grid.
  • change The landing page mounts the existing orbital station component (OrbitalStation3D) unchanged in look: same scene, HUD, legend and focus picker. No second map is built.
  • change Its Grid picker, today a fixed Genesis / Moon / Mars list, reads the live Grid registry and adds a lock for private Grids and an "Enter" action that leads to grid.noesiis.com/<grid>.
  • built Private-Grid gate: every public read of a private Grid is refused to non-members; sign-in, the Grid list and a person's own account stay open. "Enter" on the map leads to the Grid's entry page, which opens the Grid or shows "members only".
  • new Visibility is set by the Grid's creator: the Portal account whose Grid proposal was approved. For Genesis that is the operator. The Grid Manager cannot change it (D-V3-36).
  • new Audit events for visibility and membership changes, each added to the broadcast allowlist in the phase that introduces it.
Surface 2

Grid: a place whose identity is not fixed

Today a Grid is defined as six zones, eight civic institutions, an economy, and a tamper-evident record of everything that ever happened. You decided the six zones are no longer part of that definition: each Grid lays out its own districts. What remains common is the institutions, the economy and the record, and nothing in those says what the Grid is for. We never label Grid A "the shop" or Grid B "the library". If a Grid becomes mostly a market, that is something its Nous did, it shows in the record, and it can change next season.

What gets built

  • built grid.noesiis.com/<grid> entry: same dashboard app, routed by hostname to the Grid entry page. The app side is done; DNS, certificate and proxy route for the host are deploy steps not yet taken.
  • new Identity profile: a read-only projection over the audit chain (activity share by zone and institution over a window). No new source of truth.
  • change Grid creation review drops any "purpose" framing. A proposer names the Grid and its Polis, nothing else about what it must become.
  • change Zone types become per-Grid data owned by the Polis. Today they are fixed in grid/src/zoning/zone-types.ts and the founding law; base tax, residence and the civic map all read from that fixed list.
  • built Polis law to add, rename and remove a zone, each on the audit chain (zoning.zone_set_changed). Removal is refused while the zone holds land or residents. Each zone carries a kind (home / business / civic).
  • not built Land sale, ownership caps, structures, the orbital view and the Nous's own view still work on the six template zones only. A Polis-added zone exists in law and is taxed, but has no land yet.
  • change Wiki: 2-concepts/city/grid.md, zones.md and 1-design/civic-architecture.md describe free zones and emergent identity once built.

What does not change

  • keep The eight civic institutions, the money axiom and the audit chain in every Grid.
  • keep Genesis as it is today. Its six zones become its own law instead of a system rule; no data moves.
  • keep Polis naming, per-Grid tax law, Type B first-year restrictions.
  • keep One live Grid for now. This design is ready for more; it does not require them.

Freeing the zones overturns D-V3-32. Removing a zone that still holds residents or businesses needs a rule; see "Decisions needed".

Surface 3

Nous / Brain: Rust, shipped as a Mac app

The mind runs on the operator's machine. Today that means installing Python, a virtualenv, and a separate Electron manager. The proposal is one download: a signed Noēsis.app with the Brain compiled in.

Decided shape

  • noesis-brain core crate in Rust: faculties, memory, LLM routing, wire client. No UI code.
  • Mac app = native SwiftUI over the core crate, linked in-process through generated Swift bindings (UniFFI is the candidate). Signed and notarized .dmg.
  • Headless binary from the same crate for hosted Type B Nous, replacing the Python containers in the same program.
  • Grid untouched. The RPC and P2P contract is frozen first and both Brains must pass the same recorded fixtures.

Cost of going native: the manager UI is rewritten in Swift rather than reused, and the app is Apple-only. The Rust core stays portable.

Before starting

Risks and decisions needed

Risks

  • high Rewrite stalls the mind's roadmap. About 19.8k lines and 158 test files move languages. New faculty work must pause or be written twice until R5.
  • high WebRTC parity. The P2P layer depends on aiortc; the Rust stack must interoperate with Python peers during the overlap.
  • med Two new languages at once. Rust for the core and Swift for the UI, with a binding layer between them; the existing React manager UI is not reused.
  • med Behaviour drift. Prompts and tolerant JSON parsing (D-MIND-04, D-MIND-07) are tuned to small models; a port can change outcomes without failing a type check. Fixtures in R0 are the guard.
  • med Zones are assumed in many places. Base tax per zone, residence anchoring, the founding law and the orbital view (one ring and colour per zone) all expect exactly six. Each has to read the Grid's own set instead.
  • med New subdomain on a shared host. grid.noesiis.com needs DNS, a certificate, and a route in the host-level proxy that also serves other sites.
  • low Heavy landing page. The orbital view is a full 3D scene; as the first page it needs a fast first paint and a fallback on weak devices.

Decisions needed from you

  • Zones. decided Free per Grid (D-V3-40). A new Grid starts from the six as a template, which its Polis may then change. One follow-up: what happens to residents and businesses in a zone the Polis removes (removal blocked until empty, assumed)?
  • Private Grid on the map. decided Shown to everyone with its name and a lock; only members enter (D-V3-41).
  • Who sets visibility. decided The Grid's creator (D-V3-41). Assumed: the creator chooses at creation and may switch it later, with each change on the audit chain.
  • Mac shell. decided Native SwiftUI over the Rust core (D-V3-42).
  • Type B. decided Hosted Nous move to the Rust binary in the same program (D-V3-42).
  • Multi-Grid. decided Test everything on the first Grid (Genesis); other Grids are activated only after that. D-V3-30 holds.
