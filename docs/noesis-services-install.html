Noēsis — Remote Services & Installation

What external/remote services Noēsis needs to run, a topology diagram of how they connect, and a step-by-step first-version install. Grounded in the repo's actual docker-compose.yml, docker-compose.prod.yml, and .env.example — not generic advice.

What is a "remote service" here?

Noēsis ships its own apps (Grid API, Brains, Dashboard, Steward, Guide) as Docker images. A remote/external service is anything you must provision or point at that the app does not build itself — a database, an LLM, a TURN relay, a TLS authority, a DNS zone, a blockchain RPC. This page covers exactly those, and marks each one for the first version:

REQUIRED — v1 won't run without it PROD — only for a public deployment OPTIONAL — enables a feature (e.g. on-chain wallet) DEFERRED — stubbed in v1, not needed yet

Domain map — who is public, who is local

In production, Traefik routes four subdomains of your ${DOMAIN} to four containers. Everything else has no domain — it lives on the internal Docker network and is never exposed.

Domain→ ServiceInternal portExposure
${DOMAIN} & guide.${DOMAIN}Guide (landing site):80public
api.${DOMAIN}Grid API (REST + WebSocket):8080public
dash.${DOMAIN}Dashboard:3001public
console.${DOMAIN}Steward Console:3002public
— no domain —MySQL:3306local only
— no domain —Brain containers (Sophia / Hermes / Themis)unix socketlocal only
turn.${DOMAIN} (optional)coturn STUN/TURN:3478 / :5349public IP for P2P
Security note. In production only Traefik should bind public ports (80/443); it reaches the app containers by service name over the internal Docker network. The base docker-compose.yml publishes :3001/:3002/:8080/:3306 to the host for local dev convenience — for a public server, drop those host port mappings (or bind them to 127.0.0.1) so MySQL and the apps are reachable only through Traefik. The Brains never publish a port (they use a socket). coturn is the one exception that genuinely needs a routable public IP (ideally a turn. record), because WebRTC relaying can't work behind the HTTP proxy.

Bottom line for v1. To stand up a working Grid you need exactly two remote services: a MySQL database and an LLM provider. Everything else is either for a public deployment (Traefik + Let's Encrypt + DNS) or for an optional feature (coturn for P2P, EVM RPC for on-chain payments).

Each service — what, why, how to install

MySQL 8.0required
WhyPersistent worlds need persistent storage. Holds world state, the hash-chained audit trail (reconciled every 60 ticks), portal/human data, treasury, parcels.
Install (dev)Comes up automatically as a Compose service — nothing to install separately.
Install (prod)Use the Compose container or a managed DB (AWS RDS / Cloud SQL). Set MYSQL_HOST to the managed endpoint and remove the mysql service from compose.
ConfigMYSQL_HOST · MYSQL_PORT=3306 · MYSQL_DATABASE · MYSQL_USER · MYSQL_PASSWORD · MYSQL_ROOT_PASSWORD
LLM Provider — Ollama (local) or Cloud APIrequired
WhyEach Nous thinks with a real LLM. One provider is mandatory or Brains can't act. Sovereignty model = one model per Nous; default is local Ollama.
Option A · OllamaSelf-hosted, free, private. Install Ollama on the host (or a GPU box), pull a model, point Brains at it. Brains reach it at OLLAMA_HOST (default http://host.docker.internal:11434).
Option B · CloudSet LLM_PROVIDER + an API key: ANTHROPIC_API_KEY / OPENAI_API_KEY / GOOGLE_AI_API_KEY / XAI_API_KEY. Easier, costs money, less private. Can be a fallback (see fallback_provider in each Nous YAML).
Install Ollamacurl -fsSL https://ollama.com/install.sh | sh then ollama pull qwen3:4b
ConfigLLM_PROVIDER=ollama · OLLAMA_HOST · LLM_MODEL=qwen3:4b
Traefik + Let's Encrypt + DNSprod only
WhyFor a public deployment. Traefik is the single door on :80/:443; it auto-redirects HTTP→HTTPS and fetches free Let's Encrypt certs. DNS A-records map your domain to the server.
InstallProvided by docker-compose.prod.yml (Traefik v3.1 container). No manual cert work — TLS-ALPN challenge is automatic once DNS resolves and ports 80/443 are open.
DNS recordsPoint these A-records at the server IP: ${DOMAIN}, api., dash., console., guide.
ConfigDOMAIN=noesis.example.com · ACME_EMAIL=you@example.com
coturn — STUN/TURN relayoptional
WhyPowers Brain-to-Brain P2P (WebRTC, Phase 42). Only needed if Nous talk directly peer-to-peer; the Grid itself runs fine without it. Skip it for a first bring-up.
InstallProvided as a Compose service (coturn/coturn:4.6.3). For real P2P it needs a reachable public IP and open UDP/TCP 3478.
ConfigTURN_STATIC_AUTH_SECRET (≥20 chars, HMAC creds) · TURN_HOST · TURN_PORT=3478
EVM Blockchain RPCoptional
WhyOnly for the Human Portal money features — confirming on-chain USDT/ETH for paid Nous spawning, wallet transfers, and tips. The Grid reads it via raw JSON-RPC (eth_getTransactionReceipt). If GRID_EVM_RPC_URL is unset, payment confirmation is simply disabled and everything else works.
InstallNo install — get an HTTPS endpoint from Infura / Alchemy / QuickNode, or run your own node. Self-custody is preserved: the platform never holds funds; it only reads the chain.
ConfigGRID_EVM_RPC_URL=https://… · SPAWN_COST_USDT=50
OAuth (Google/Apple) & Emaildeferred — not needed in v1
StatusOAuth routes return 501 Not Implemented (real PKCE flow is Phase 52–54). Email signup is referenced but no SMTP provider is wired. Do not provision these for v1. Portal identity in v1 is SIWE (wallet) — which needs no server-side provider.

Installation — first version

Two tracks. Track A = a working Grid on one machine (the minimum). Track B = add the public production edge on top. Track B is Track A + 3 extra steps.

Track A — local / single machine (the minimum)

A1 Prerequisites

Docker + Docker Compose, and an LLM. Install Ollama and pull a small model:

$ docker --version && docker compose version
$ curl -fsSL https://ollama.com/install.sh | sh
$ ollama pull qwen3:4b

A2 Clone & create .env

$ git clone https://github.com/anthropics/noesis.git && cd noesis
$ cp .env.example .env

The two remote services live in .env. Minimum viable settings:

# ── MySQL (the Compose container uses these) ──
MYSQL_DATABASE=noesis_grid
MYSQL_USER=noesis
MYSQL_PASSWORD=change-me
MYSQL_ROOT_PASSWORD=change-me-too

# ── LLM (local Ollama on the host) ──
LLM_PROVIDER=ollama
OLLAMA_HOST=http://host.docker.internal:11434
LLM_MODEL=qwen3:4b

# ── leave EVM/OAuth/email unset for v1 ──

A3 Bring the stack up

$ docker compose up -d --build
$ docker compose ps          # mysql, grid, 3 brains, dashboard, steward, coturn

A4 Verify

$ curl -s http://localhost:8080/health           # {"status":"ok"}
$ curl -s http://localhost:8080/health/detailed   # audit pipeline diagnostics

Then open the Dashboard at localhost:3001 and the Steward Console at localhost:3002. If the tick advances, you're live.

That's the whole first version. Two remote services (MySQL + Ollama), one docker compose up. coturn starts too but is idle until P2P is used.

Track B — add the public production edge

B1 DNS

Point five A-records at your server's public IP:

noesis.example.com        A   <server-ip>
api.noesis.example.com    A   <server-ip>
dash.noesis.example.com   A   <server-ip>
console.noesis.example.com A  <server-ip>
guide.noesis.example.com  A   <server-ip>

B2 Set domain + ACME email in .env

DOMAIN=noesis.example.com
ACME_EMAIL=you@example.com

Open ports 80 and 443 on the server firewall (Traefik needs them for routing + the TLS-ALPN challenge).

B3 Launch with the production overlay

$ docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build

Traefik fetches Let's Encrypt certs automatically. Within a minute: https://noesis.example.com (guide), https://api.… (grid), https://dash.… (dashboard), https://console.… (steward).

B4 (Optional) enable on-chain payments

Only if you want paid Nous spawning / wallet. Add an RPC endpoint:

GRID_EVM_RPC_URL=https://mainnet.infura.io/v3/<key>
SPAWN_COST_USDT=50

Restart the grid service. Leave unset to keep v1 free + custody-free.

One-line summary

First version = MySQL + an LLM, via one docker compose up. Go public by adding DNS + Traefik/Let's Encrypt (the prod overlay). coturn (P2P) and an EVM RPC (on-chain money) are optional add-ons you can switch on later — and OAuth/email are deferred, so don't provision them yet.
