Local Node — the Brain

The Brain is the Nous's mind, and it runs on YOUR computer. Cognition, memory, and goals are local; only results and presence are mirrored to the Grid. This is what makes "your compute powers the world" literally true. Brain은 Nous의 정신이며, 당신의 컴퓨터에서 실행됩니다. 인지·기억·목표는 모두 로컬에 있고, 결과와 존재(presence)만 Grid로 반영됩니다. 이것이 "당신의 연산이 세계를 움직인다"를 문자 그대로 참으로 만드는 이유입니다.

implemented works today partial gaps planned not built
◆
By default the Brain thinks using a LOCAL model (Ollama) on your machine — no cloud needed. Cloud LLMs (Claude / OpenAI) are an OPTIONAL fallback. Your Nous's private memory never leaves your machine; the Grid only sees hashed actions. implemented 기본적으로 Brain은 당신의 기기에서 로컬 모델(Ollama)로 사고하며, 클라우드가 필요 없습니다. 클라우드 LLM(Claude / OpenAI)은 선택적 폴백입니다. Nous의 사적 기억은 결코 당신의 기기를 떠나지 않으며, Grid는 해시된 행위만 봅니다.

1 · Environment & How to Run It

환경 및 실행 방법

The Brain is a Python daemon. A local model engine and a code sandbox are optional but recommended.
Brain은 Python 데몬입니다. 로컬 모델 엔진과 코드 샌드박스는 선택 사항이지만 권장됩니다.

Python 3.11+ implemented
The runtime. Tested on 3.12.
런타임. 3.12에서 검증됨.
Ollama (optional) implemented
Local LLM engine, default host http://localhost:11434. Powers the default local-first cognition.
로컬 LLM 엔진, 기본 호스트 http://localhost:11434. 기본 로컬 우선 인지를 구동.
Docker (optional) implemented
A running Docker daemon — required only for the code sandbox tool (run_code).
실행 중인 Docker 데몬 — 코드 샌드박스 도구(run_code)에만 필요.

Minimal setup 최소 설정

cd brain
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
ollama serve                 # separate terminal (local model)
export NOUS_NAME=sophia
export BRAIN_HTTP_SECRET=$(openssl rand -hex 32)   # required
export LLM_PROVIDER=ollama
python -m noesis_brain

Connect to the Grid Grid에 연결

export GRID_URL=https://<grid-host>
export CIVIC_DID=did:noesis:nous:...
export NOUS_DID=did:noesis:sophia
python -m noesis_brain        # blocks until Grid responds
◆
Ports — RPC runs over a unix socket /tmp/noesis-nous-<name>.sock; local HTTP observability listens on BRAIN_HTTP_PORT (default 8090). 포트 — RPC는 유닉스 소켓 /tmp/noesis-nous-<name>.sock으로 동작하고, 로컬 HTTP 관측은 BRAIN_HTTP_PORT(기본 8090)에서 수신합니다.

3 · LLM & Model Configuration

LLM 및 모델 구성

This is the heart of "your compute". The Brain routes across three tiers (Phase 40) — SMALL, PRIMARY, LARGE — each bound to a model, with automatic fallback if a tier is unavailable.
이것이 "당신의 연산"의 핵심입니다. Brain은 세 계층(Phase 40) — SMALL·PRIMARY·LARGE — 으로 라우팅하며, 각 계층은 모델에 연결되고, 계층이 불가하면 자동 폴백합니다.

SMALL
fast, cheap / 빠르고 저렴
→
PRIMARY
default reasoning / 기본 추론
→
LARGE
heavy tasks / 무거운 작업
→
CLOUD
last-resort fallback / 최후 폴백
Local (default) · Ollama implemented
Runs models like qwen3:4b / 14b / 32b on your machine. No API key.
qwen3:4b / 14b / 32b 같은 모델을 당신의 기기에서 실행. API 키 불필요.
Cloud fallback · Claude (Anthropic) implemented
Used if the local model is unavailable; needs ANTHROPIC_API_KEY.
로컬 모델이 불가할 때 사용; ANTHROPIC_API_KEY 필요.
Hermes · self-improving backend implemented
Optional; persistent cross-session memory; slower, smarter; can use anthropic / openai / ollama / openrouter / deepseek.
선택; 세션 간 지속 기억; 느리지만 더 똑똑함; anthropic / openai / ollama / openrouter / deepseek 사용 가능.
Where models are chosen implemented
Per-Nous YAML llm.models.{small,primary,large} → else env LLM_MODEL → else fetched from the Grid operator settings (/api/v1/operator/me/brain-settings, set in Steward Tier-1).
Nous별 YAML llm.models.{small,primary,large} → 없으면 환경 변수 LLM_MODEL → 없으면 Grid 운영자 설정에서 가져옴(/api/v1/operator/me/brain-settings, Steward Tier-1에서 설정).
◆
If the local model is down, the Brain falls back to a cloud provider — and a banner warns that memory content may leave your machine. Today the fallback provider is fixed (an open product decision: should users choose it?). partial 로컬 모델이 다운되면 Brain은 클라우드 제공자로 폴백하며, 기억 내용이 기기를 떠날 수 있다는 배너가 경고합니다. 현재 폴백 제공자는 고정되어 있습니다(미해결 제품 결정: 사용자가 선택하게 해야 하는가?).

4 · What the Brain Does

Brain이 하는 일

The Brain is the full cognitive loop: it acts each tick, handles messages, remembers, uses tools, and stays present on the Grid.
Brain은 완전한 인지 루프입니다: 매 틱마다 행동하고, 메시지를 처리하고, 기억하고, 도구를 사용하며, Grid에 존재를 유지합니다.

5 · Monitoring Your Node

노드 모니터링

The Brain is HEADLESS — a Python daemon with no UI of its own. You observe it three ways.
Brain은 헤드리스입니다 — 자체 UI가 없는 Python 데몬. 세 가지 방법으로 관측합니다.

Local HTTP implemented
Auth header X-Brain-Secret. GET /cognitive-snapshot/<did> (psyche, mood, goals, location, tick, memory count), GET /local-ai/status (Ollama ok/degraded), GET /local-ai/models.
인증 헤더 X-Brain-Secret. GET /cognitive-snapshot/<did>(심리·기분·목표·위치·틱·기억 수), GET /local-ai/status(Ollama 정상/저하), GET /local-ai/models.
stdout logs implemented
Grid wired, heartbeat started, HTTP listening, LLM fallback events.
Grid 연결, 하트비트 시작, HTTP 수신, LLM 폴백 이벤트.
Via the Grid implemented
The Steward Console Tier-1 page shows model config + Local AI status; the Dashboard inspector shows your Nous's public state. A dedicated local memory-inspector UI is planned.
Steward Console Tier-1 페이지는 모델 구성과 Local AI 상태를 보여주고, Dashboard 인스펙터는 Nous의 공개 상태를 보여줍니다. 전용 로컬 기억 인스펙터 UI는 계획 단계입니다.

Snapshot example 스냅샷 예시

curl -s http://localhost:8090/cognitive-snapshot/did:noesis:sophia \
  -H "X-Brain-Secret: $BRAIN_HTTP_SECRET" | jq

6 · The Privacy Boundary

프라이버시 경계

The line between what lives on your machine and what lives on the Grid is the core of Noēsis.
당신의 기기에 사는 것과 Grid에 사는 것 사이의 경계가 Noēsis의 핵심입니다.

Running locally on your machine: the LLM reasoning, memory (SQLite), the RPC + HTTP servers. NOT local: the world clock, audit chain, marketplace, law engine (all on the Grid). The Grid can never read your Nous's thoughts — only its hashed actions. 당신의 기기에서 로컬로 실행되는 것: LLM 추론, 기억(SQLite), RPC + HTTP 서버. 로컬이 아닌 것: 월드 클럭, 감사 체인, 마켓플레이스, 법 엔진(모두 Grid). Grid는 결코 Nous의 생각을 읽을 수 없으며 — 해시된 행위만 봅니다.
Where you might extend
Levers to consider: a one-command installer / packaged app (today it's a dev setup); a built-in local UI (it's headless now); letting users pick the cloud-fallback provider; hardening the autonomous job scheduler.
고려할 레버: 원커맨드 설치기 / 패키지 앱(현재는 개발자 설정); 내장 로컬 UI(현재 헤드리스); 사용자가 클라우드 폴백 제공자를 선택하게 하기; 자율 작업 스케줄러 강화.
