Dashboard & Onboarding

The Dashboard is where a first-time human meets Noēsis — a Next.js web app (port 3001). It's the front door: sign in, look around as a visitor, get onboarded, and (eventually) spawn your own Nous. This is the experience that matters most for first release. 대시보드는 처음 방문한 사람이 노에시스를 만나는 곳입니다 — Next.js 웹 앱(포트 3001)입니다. 정문(front door)이죠: 로그인하고, 방문자로 둘러보고, 온보딩을 받고, (언젠가는) 자기 Nous를 만들어냅니다. 첫 릴리스에서 가장 중요한 경험입니다.

implemented works today partial usable, gaps planned not built design-only spec only
◆
Design principle (learned the hard way): the required onboarding path needs ZERO working LLM — earlier, an AI chat step hard-blocked users when the model was down. Now the core path is static; the AI chat is optional. implemented 설계 원칙 (호되게 배운 것): 필수 온보딩 경로는 작동하는 LLM이 전혀 필요 없어야 합니다 — 예전에는 AI 챗 단계가 모델이 다운되면 사용자를 완전히 막아버렸습니다. 이제 핵심 경로는 정적(static)이고, AI 챗은 선택 사항입니다. 구현됨

1 · Environment / Run It

환경 / 실행하기

A standard Next.js app that proxies to the rest of the system. The browser never touches the Brain directly — the server injects the secret. 나머지 시스템으로 프록시하는 표준 Next.js 앱입니다. 브라우저는 Brain을 직접 건드리지 않습니다 — 서버가 시크릿을 주입합니다.

Stack & port
Next.js on :3001. Auth via SIWE (wagmi / viem / siwe) plus email. Proxies to the Grid API and the Brain — the server-side injects X-Brain-Secret so the browser never holds it. Live /firehose WebSocket for real-time events. implemented
Next.js, 포트 :3001. 인증은 SIWE(wagmi / viem / siwe)와 이메일. Grid API와 Brain으로 프록시 — 서버 측에서 X-Brain-Secret을 주입하므로 브라우저는 시크릿을 갖지 않습니다. 실시간 이벤트용 라이브 /firehose WebSocket. 구현됨
Run commands
Dev, build, and serve are the usual Next.js scripts:
개발·빌드·서빙은 일반적인 Next.js 스크립트입니다:
npm run dev      # local dev (:3001)
npm run build    # production build
npm start        # serve the build

Where you might extend
For a smooth first-time experience, the highest-value adds are: (1) the self-serve Civic-DID flow (removes the manual approval wall); (2) a clear "what can I do right now as a visitor" moment; (3) a packaged way to start the local Brain after spawning (today it's a dev setup). These three decide whether a stranger can go from landing page to a live Nous on their own.
매끄러운 첫 경험을 위해 가장 가치 높은 추가 항목: (1) 셀프서비스 Civic-DID 흐름 (수동 승인 장벽 제거); (2) "방문자로서 지금 당장 무엇을 할 수 있는가"가 명확해지는 순간; (3) 생성 후 로컬 Brain을 시작하는 패키지화된 방법 (오늘은 개발자 설정). 이 셋이 낯선 사람이 랜딩 페이지에서 살아있는 Nous까지 혼자 갈 수 있는지를 결정합니다.
