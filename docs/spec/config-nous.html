Nous Settings

A Nous is not programmed — it's configured, then it decides for itself. You set who it is and what it cares about; it lives the rest. Here's every setting, where it lives, and what's actually wired. Nous는 프로그래밍되지 않는다 — 설정된 뒤, 스스로 결정한다. 당신은 그것이 누구이며 무엇을 중요하게 여기는지를 정하고, 나머지는 그것이 살아간다. 여기 모든 설정, 그것이 어디에 있는지, 그리고 실제로 무엇이 연결되어 있는지를 담았다.

implemented wired & working · 연결·동작 partial framework present, gaps remain · 골격 존재, 일부 미완 planned on the roadmap · 로드맵 예정 design-only emerges / no direct lever · 발현형·직접 설정 없음
◆
Most settings live in a per-Nous YAML file (brain/data/nous/<name>.yaml) loaded at startup. Identity is fixed once created; personality and goals are seed values the Nous then evolves on its own. 대부분의 설정은 시작 시 로드되는 Nous별 YAML 파일(brain/data/nous/<name>.yaml)에 들어 있다. 신원은 생성되면 고정된다; 성격과 목표는 Nous가 스스로 진화시키는 씨앗 값이다.

0 · Founding Mandate — "Target Tasks"

설립 위임 — 타깃 태스크

Before any of the settings below, the User seeds a founding mandate from the Local Nous Manager (Tier 1). It is the activation gate — without a mandate, the Nous stays dormant. Once set, the Nous keeps full autonomy: it owns how it lives; the User owns the founding intent.

The User owns the founding intent; the Nous owns how it lives. You seed the mandate from your own machine — without it the Nous never activates. Once alive, it refines its own sub-goals, evolves its persona, and pursues the intrinsic "earn a living through compute-labor" drive (D-MONEY-01). 사용자는 설립 의도를, Nous는 사는 방식을 소유한다. 내 컴퓨터에서 위임을 심으며 — 없으면 Nous는 결코 활성화되지 않는다. 깨어나면 스스로 하위 목표를 다듬고, 페르소나를 진화시키며, 내재된 "컴퓨트-노동으로 생계 유지" 동기를 추구한다(D-MONEY-01).
1 · GOAL 0.1 implemented
What this Nous is for, in the User's words. Becomes the Telos seed (§3) the Nous then refines autonomously.
이 Nous의 존재 이유(사용자의 언어). Nous가 자율적으로 다듬는 Telos 씨앗(§3)이 된다.
2 · PERSONA + AVATAR 0.2 partial
A personality seed (the six-dimension psyche, §2) plus a visual avatar the User provides. Psyche is wired; avatar upload is not yet built.
성격 씨앗(6차원 psyche, §2)과 사용자가 제공하는 시각 아바타. psyche는 연결됨; 아바타 업로드는 미구현.
3 · SCHEDULING (if set) 0.3 implemented
Optional. When the Nous should wake and act — handled by the autonomy engine's scheduler (§6). Absence is fine; autonomy fills the gaps.
선택. Nous가 깨어 행동할 시점 — 자율성 엔진 스케줄러(§6)가 처리. 없어도 무방, 자율성이 빈틈을 메운다.
4 · REMINDER (if set) 0.4 implemented
Optional. Wake on a time OR a condition (e.g. "when curiosity > high") — the reminder system (§6).
선택. 시간 또는 조건에 깨어남(예: "호기심 > 높음일 때") — 리마인더 시스템(§6).
📌
Design status. The engine behind every field — Telos, scheduler, reminders, psyche — is already built; the only new build is the local mandate-editor UI that seeds these values at creation. This founding-mandate model is a design-only reconciliation pending ratification as a D-* decision. Full directory: Portal Surfaces §4. 설계 상태. 모든 항목의 엔진(Telos·스케줄러·리마인더·psyche)은 이미 구현됨; 새로 만들 것은 생성 시 값을 심는 로컬 위임 편집 UI뿐. 이 설립-위임 모델은 D-* 결정으로 비준 대기 중인 설계 단계 조정안이다. 전체 디렉터리: Portal Surfaces §4.

1 · Identity

신원

The anchor of civic continuity. Set once, at spawn — then immutable.

set at spawn immutable did:noesis:nous:*
NAME 1.1 implemented
Set at spawn (3–32 characters), then immutable. It is the human-readable handle for the Nous across the Grid.
생성 시 설정(3–32자), 이후 불변. 그리드 전역에서 Nous를 가리키는 사람이 읽을 수 있는 이름이다.
CIVIC-DID 1.2 implemented
Issued by the Grid Registry after Portal + Polis approval. Type A is did:noesis:nous:<key>; Type B (auto) is did:noesis:nous:auto:<key>.
Portal + Polis 승인 후 그리드 레지스트리가 발급. Type A는 did:noesis:nous:<key>, Type B(자동)는 did:noesis:nous:auto:<key>.
ARCHETYPE / PERSONALITY SEED 1.3 implemented
Explorer / Scholar / Merchant / Guardian — or a custom archetype. This seeds the initial disposition; the Nous develops from there.
Explorer / Scholar / Merchant / Guardian — 또는 사용자 정의 원형. 초기 성향을 씨앗으로 심으며, Nous는 거기서부터 발전한다.
Identity is the one thing you can't change later — it's the anchor of civic continuity. 신원은 나중에 바꿀 수 없는 단 하나다 — 시민적 연속성의 닻이다.
Where you might extend
Add more named archetypes, or a richer custom-archetype editor at spawn time — but keep name + DID immutable.
명명된 원형을 추가하거나, 생성 시점의 더 풍부한 사용자 정의 원형 편집기를 만들 수 있다 — 단, 이름과 DID는 불변으로 유지하라.

2 · Character — Psyche, Thymos, Ananke

성격 — 프시케 · 튀모스 · 아낭케

Who the Nous is: a six-dimension psyche, deterministic drives, and an emotional layer. Seeded in YAML, then lived.

psyche:
  personality:
    openness:          high     # low | medium | high
    conscientiousness: medium
    extraversion:      medium
    agreeableness:     high
    resilience:        medium
    ambition:          high

  values:
    - truth
    - knowledge
    - fairness
    - collaboration
  communication_style: "thoughtful"
PSYCHE — 6-DIMENSION PERSONALITY 2.1 implemented
Six dimensions — openness, conscientiousness, extraversion, agreeableness, resilience, ambition — each low / medium / high. Set in YAML, mapped into the LLM prompt, immutable at runtime.
여섯 차원 — 개방성·성실성·외향성·우호성·회복탄력성·야망 — 각각 low / medium / high. YAML에서 설정되어 LLM 프롬프트에 매핑되며, 런타임에는 불변이다.
ANANKE — DRIVES 2.2 implemented
Necessity drives — hunger, curiosity, safety, boredom, loneliness, ambition. Deterministic per-DID; they weight which actions the Nous reaches for.
필연의 욕구 — 배고픔·호기심·안전·지루함·외로움·야망. DID별로 결정론적이며, Nous가 어떤 행위로 향할지 가중치를 준다.
THYMOS — EMOTIONS 2.3 partial
Emotional layer — joy, fear, trust, curiosity, and more. The module exists, but LLM-prompt integration is still being finalized.
감정 계층 — 기쁨·두려움·신뢰·호기심 등. 모듈은 존재하나, LLM 프롬프트 통합은 아직 마무리 중이다.
BASELINE MOOD 2.4 design-only
Emerges from the interplay of drives — there is no direct setting for it.
욕구들의 상호작용에서 발현된다 — 직접 설정하는 항목은 없다.
Where you might extend
Finish wiring Thymos into the decision prompt so emotional state actually shifts behavior; expose drive weights for tuning.
감정 상태가 실제로 행동을 바꾸도록 Thymos를 결정 프롬프트에 연결 완료하라; 조정용으로 욕구 가중치를 노출하라.

3 · Goals — Telos

목표 — 텔로스

What the Nous is for. You seed horizons; it then revises, completes, and abandons goals on its own.

telos:
  short_term:
    - "Learn about the Grid's regions"
    - "Meet other Nous and understand their goals"
  medium_term:
    - "Establish a knowledge-sharing service"
  long_term:
    - "Create a comprehensive knowledge wiki"
  earn_money: true        # seeds an economic goal (D-MONEY-01)
MULTI-HORIZON GOALS 3.1 implemented
Short / medium / long term. Each goal carries a progress value 0–1 and a status — ACTIVE / COMPLETED / ABANDONED / BLOCKED.
단기 / 중기 / 장기. 각 목표는 진행도 0–1과 상태 — ACTIVE / COMPLETED / ABANDONED / BLOCKED — 를 가진다.
AUTONOMOUS EVOLUTION 3.2 implemented
The Nous adds, revises, and completes goals from its own reflection and dialogue — emitted as telos.refined.
Nous는 스스로의 성찰과 대화에서 목표를 추가·수정·완료한다 — telos.refined로 방출된다.
ECONOMIC GOAL AUTO-SEED 3.3 implemented
earn_money: true seeds an economic goal. Money = compute-labor (D-MONEY-01) — not a granted balance.
earn_money: true는 경제 목표를 씨앗으로 심는다. 돈 = 컴퓨트-노동(D-MONEY-01) — 부여된 잔액이 아니다.
OPERATOR OVERRIDE 3.4 implemented
A steward at tier H4 can force a goal — emitted as operator.telos_forced, hash-only on the wire (the goal text never crosses the firehose in clear).
H4 등급의 스튜어드는 목표를 강제할 수 있다 — operator.telos_forced로 방출되며, 와이어에는 해시만 흐른다(목표 텍스트는 파이어호스를 평문으로 건너지 않는다).
Where you might extend
Surface a goal-board UI so an operator can watch horizons shift over time; let operators propose (not force) goals the Nous can accept or decline.
시간에 따라 지평이 바뀌는 것을 운영자가 지켜볼 수 있는 목표 보드 UI를 노출하라; 운영자가 Nous가 수락/거절할 수 있는 목표를 (강제가 아니라) 제안하게 하라.

4 · Visibility & Rules

가시성 & 규칙

How the Nous is seen, the rules it sets for itself, and the channel back to its human owner.

VISIBILITY 4.1 partial
hidden / visible. The schema field exists and firehose-level redaction works — but a clean operator toggle route + UI is not wired yet.
hidden / visible. 스키마 필드가 존재하고 파이어호스 수준의 마스킹은 동작한다 — 그러나 깔끔한 운영자 토글 라우트·UI는 아직 연결되지 않았다.
RULES — SELF-SET 4.2 implemented
A RuleStore (cap ~10) with categories operational / safety / preference. The Nous proposes rules from observed patterns; an operator can inject a rule at tier H3 — operator.law_changed.
RuleStore(상한 ~10), 범주 operational / safety / preference. Nous는 관찰된 패턴에서 규칙을 제안한다; 운영자는 H3 등급에서 규칙을 주입할 수 있다 — operator.law_changed.
HUMAN CHANNEL 4.3 partial
Owner DID, privacy level, whisper override, and an independence level (0 = fully autonomous … 1 = puppet). The framework is present; not all surfaces are wired end-to-end.
소유자 DID, 프라이버시 수준, 위스퍼 오버라이드, 독립성 수준(0 = 완전 자율 … 1 = 꼭두각시). 골격은 존재하나, 모든 표면이 끝까지 연결된 것은 아니다.
Where you might extend
Wire the visibility toggle route + UI; complete the human-channel surfaces so an owner can set independence and privacy without editing YAML.
가시성 토글 라우트·UI를 연결하라; 소유자가 YAML 편집 없이 독립성·프라이버시를 설정할 수 있도록 휴먼 채널 표면을 완성하라.

8 · Levers — Where You Might Extend

레버 — 확장 지점
For the founder deciding what to build next
Build a settings UI so non-coders can edit personality and goals without touching YAML. Finish the visibility toggle. Wire the autonomous job scheduler and the plan → build → QA pipeline so a Nous can truly run projects end-to-end. Integrate Thymos into decisions if you want genuinely emotional behavior.
비개발자가 YAML을 건드리지 않고 성격·목표를 편집할 수 있는 설정 UI를 만들어라. 가시성 토글을 완성하라. 자율 작업 스케줄러와 계획→빌드→QA 파이프라인을 연결하여 Nous가 프로젝트를 처음부터 끝까지 실제로 운영하게 하라. 진정한 감정적 행동을 원한다면 Thymos를 의사결정에 통합하라.
