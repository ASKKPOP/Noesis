Steward Console

The Steward Console is the operator's cockpit — a separate web app (port 3002) with three tiers of management. Tier-1 is YOUR tool for your own Nous; Tiers 2–3 are Henry-side. Here's what's wired. 스튜어드 콘솔은 운영자의 조종석입니다 — 세 개의 관리 계층을 가진 별도의 웹 앱(포트 3002)입니다. Tier-1은 당신 자신의 Nous를 위한 당신의 도구이며, Tier 2–3은 Henry 측입니다. 아래는 현재 연결된 것입니다.

implemented works today / 현재 작동 partial gaps / 일부 미완 planned not built / 미구현
◆
This is MANAGEMENT, not governance. Across every tier and every action, an operator can never vote, legislate, or override a Polis (VOTE-05). Every operator action is itself an audit event — tamper-evident (R-31-01). See the agency-scale spec for H1–H5 detail → steward-console.html. 이것은 관리이며 거버넌스가 아닙니다. 모든 계층, 모든 행위에서 운영자는 결코 투표·입법하거나 Polis를 무효화할 수 없습니다(VOTE-05). 모든 운영자 행위는 그 자체로 감사 이벤트이며 변조 증거가 남습니다(R-31-01). H1–H5 세부는 행위성 척도 스펙 참조 → steward-console.html.

1 · Environment & Run It

환경 및 실행

The Console is a Next.js app on port :3002. It has no separate auth layer of its own — it reads the Grid's /health/detailed and operator settings through the Grid API.
콘솔은 포트 :3002에서 실행되는 Next.js 앱입니다. 자체 인증 계층이 없으며, Grid의 /health/detailed와 운영자 설정을 Grid API를 통해 읽습니다.

Next.js · React 19 implemented
A standalone web app served on :3002, distinct from the Grid and the Brain.
Grid·Brain과 구분되는 독립 웹 앱, :3002에서 서빙.
No own auth layer implemented
Reads through the Grid API — operator identity and access flow through the Grid, not the Console.
Grid API를 통해 읽음 — 운영자 신원과 접근은 콘솔이 아닌 Grid를 통함.
Live health source implemented
Polls /health/detailed for allowlist, metrics, and event/frame counters.
허용목록·메트릭·이벤트/프레임 카운터를 위해 /health/detailed 폴링.

Run it 실행

cd steward
npm install
npm run dev      # next dev --port 3002
npm run build    # production build
npm start        # next start --port 3002

2 · The Three Management Tiers (D-V3-36)

세 가지 관리 계층 (D-V3-36)

Management is split into three tiers by audience and authority. Tier-1 is the end user's local tool; Tiers 2–3 are Henry-side operational surfaces. Status is the point here.
관리는 대상과 권한에 따라 세 계층으로 나뉩니다. Tier-1은 최종 사용자의 로컬 도구이며, Tier 2–3은 Henry 측 운영 인터페이스입니다. 여기서 핵심은 구현 상태입니다.

3 · Main Dashboard (/system)

메인 대시보드 (/system)

The /system dashboard reads /health/detailed and surfaces the broadcast allowlist, health metrics, and event/frame counters in one view.
/system 대시보드는 /health/detailed를 읽어 브로드캐스트 허용목록·헬스 메트릭·이벤트/프레임 카운터를 한 화면에 보여줍니다.

Allowlist view implemented
Shows the broadcast allowlist with health metrics alongside.
브로드캐스트 허용목록을 헬스 메트릭과 함께 표시.
Event / frame counters implemented
Live counters driven by the /health/detailed poll.
/health/detailed 폴링으로 구동되는 라이브 카운터.
◆
Minor: the allowlist count shown in the UI is partly hardcoded (the static list snapshot in /system) and may lag the real broadcast allowlist as new events are added. Cosmetic, not a correctness gap. 사소함: UI에 표시되는 허용목록 개수는 일부 하드코딩(/system의 정적 스냅샷)되어 있어, 새 이벤트가 추가되면 실제 브로드캐스트 허용목록보다 뒤처질 수 있습니다. 정확성이 아닌 표시상의 문제입니다.

4 · What an Operator Can / Can't Do

운영자가 할 수 있는 것 / 없는 것
The agency scale — H1 Observer → H5 Sovereign — is the model. Every operator action declares its tier and is audit-logged; the operator can never vote or legislate, at any tier, by design. For the full H1–H5 breakdown see steward-console.html. 행위성 척도 — H1 관찰자 → H5 주권자 — 가 모델입니다. 모든 운영자 행위는 자신의 계층을 선언하고 감사 로그에 남으며, 운영자는 설계상 어떤 계층에서도 결코 투표·입법할 수 없습니다. 전체 H1–H5 분해는 steward-console.html 참조.
