01 — DATA LAYER

RAG doesn't replace the DB — it joins itRAG는 DB를 대체하지 않고 함께 씁니다

The key realization behind question 1: a relational database and a vector store answer different questions. Noesis needs three data shapes, not one. Trying to do all of it in "just RAG" or "just MySQL" is the trap.

질문 1의 핵심: 관계형 DB와 벡터 스토어는 서로 다른 질문에 답합니다. Noesis에는 하나가 아니라 세 가지 데이터 형태가 필요합니다. "RAG만" 또는 "MySQL만"으로 전부 하려는 것이 함정입니다.

STATE
Transactional state — needs a relational DB

World-state, NID registry, ledger, laws, parcels. Requires ACID, joins, constraints. This is the part that must stay SQL. RAG cannot do this.세계 상태·NID 등록부·원장·법·필지. ACID·조인·제약 필요. SQL이어야 하는 부분. RAG로는 불가.

LOG
Event log — append-only

The ordered tick events. Just an append-only table (or Redis Streams at scale). Source of replay & the observer view.순서가 있는 틱 이벤트. 추가 전용 테이블(대규모는 Redis Streams). 재생·관찰 뷰의 원천.

MEMORY
Semantic memory — this is the RAG

Each Nous's experiences as embeddings, retrieved by relevance. This is where vectors / RAG live — and only here. Lives on the edge, with the Nous.각 Nous의 경험을 임베딩으로 저장, 관련성으로 검색. 벡터/RAG가 사는 곳 — 오직 여기. 엣지에 Nous와 함께 상주.

Your edge choice is ideal: SQLite + the sqlite-vec extension gives you relational memory and vector recall in one embedded file, no server, perfect for 1–3 connections. The Nous's whole mind is one portable .db file the owner controls.

엣지 선택은 이상적입니다: SQLite + sqlite-vec 확장으로 관계형 기억과 벡터 검색을 하나의 임베디드 파일에서, 서버 없이, 1~3 연결에 완벽하게. Nous의 마음 전체가 소유자가 통제하는 휴대 가능한 .db 파일 하나입니다.

One caveat on MySQL for vectors. MySQL added a VECTOR type in MySQL 9 (mid-2024), but the current 9.x support is storage + a DISTANCE() function with no native ANN index (HNSW/IVF) — so vector search does a flat scan of every row. Fine for a small early GRID; it will not scale to thousands of Noes. Keep MySQL as the source of truth for state, and treat the vector store as a swappable sidecar (Qdrant / Milvus / pgvector / a MySQL vector plugin). Don't couple your whole memory layer to MySQL's current vector limits.

MySQL 벡터 주의. MySQL 9(2024 중반)에 VECTOR 타입이 추가됐지만, 현재 9.x는 저장 + DISTANCE() 함수뿐이고 네이티브 ANN 인덱스(HNSW/IVF)가 없어 모든 행을 전수 스캔합니다. 초기 소규모 GRID엔 괜찮지만 수천 Nous로는 확장 안 됩니다. MySQL은 상태의 진실 원천으로 유지하고, 벡터 스토어는 교체 가능한 사이드카(Qdrant/Milvus/pgvector/MySQL 벡터 플러그인)로 다루세요.

02 — THE NOUS IS AGENTIC RAG

Why it should — and already does왜 그래야 하고, 이미 그러한가

Question 4 is the right one. The brain loop in v0.1 (perceive → retrieve → reflect → plan) is already retrieval-augmented; the upgrade to agentic RAG is to stop treating retrieval as one fixed step and start treating it as a tool the Nous decides to call, iteratively. Agentic RAG replaces the single step with a loop where the agent decides which retrieval strategies to use, evaluates what it finds, and keeps searching if results are insufficient.

질문 4는 정확합니다. v0.1의 두뇌 루프(인지→검색→반성→계획)는 이미 검색 증강이며, 에이전틱 RAG로의 업그레이드는 검색을 고정된 한 단계가 아니라 Nous가 반복적으로 호출 여부를 결정하는 도구로 다루는 것입니다.

A Nous's retrieval tools

noes/agentic-plan.ts — retrieval as a tool, with a hard budget
// Agentic RAG loop. Budget & stop-condition are NOT optional —
// without them the loop runs away on cost (3–10x tokens vs naive RAG).
async function deliberate(nous: Nous, world: WorldState): Promise<Plan> {
  let ctx = nous.scratch();
  for (let step = 0; step < nous.RETRIEVAL_BUDGET; step++) {   // e.g. budget = 3
    const next = await nous.model.decide(ctx);          // "retrieve more, or answer?"
    if (next.kind === "answer") return next.plan;          // STOP — confident enough
    ctx = ctx.add(await nous.tools[next.tool](next.args)); // recall/law/observe/ask/web
  }
  return nous.safeDefault(world);   // budget spent, no confident plan → don't freeze, act safely
}

The cost discipline that links to question 8: agentic RAG is powerful but expensive — every extra retrieval + reasoning step burns tokens and adds latency. So you do not run it every tick. You run it only when the cheap reflex layer says "this is novel / important." That gate is the resilience engine below.

질문 8과 연결되는 비용 원칙: 에이전틱 RAG는 강력하지만 비쌉니다 — 추가 검색·추론마다 토큰·지연 증가. 그래서 매 틱 돌리지 않습니다. 값싼 반사 계층이 "새롭다/중요하다"고 할 때만 돌립니다. 그 게이트가 아래의 복원력 엔진입니다.

04 — THE RESILIENCE ENGINE

Bottleneck · block · idle — solved together병목·정지·유휴 — 함께 해결

Question 8 is the most important engineering question in the project, and the three fears share one root cause: treating every tick as a full, synchronous LLM deliberation. Do that and the world is slow (bottleneck), agents loop on hard choices (block), and they burn money doing nothing (idle). The fix is one coherent design with three moving parts.

질문 8은 이 프로젝트에서 가장 중요한 엔지니어링 질문이며, 세 공포는 하나의 근본 원인을 공유합니다: 매 틱을 완전·동기적 LLM 숙고로 취급하는 것. 그러면 세계가 느리고(병목), 어려운 선택에서 에이전트가 맴돌고(정지), 아무것도 안 하며 돈을 태웁니다(유휴). 해법은 세 부품을 가진 하나의 일관된 설계입니다.

① Bottleneck → dual-process + async병목 → 이중 처리 + 비동기

Split cognition like a brain. A near-free System 1 reflex (rules or a tiny local model) decides routine ticks instantly. Expensive System 2 deliberation (the agentic-RAG loop) fires only when System 1 flags novelty/importance — and it runs asynchronously: the world tick never waits for it. The Nous keeps acting on its standing plan while a better one computes in the background and swaps in when ready. This is the PIANO idea: concurrent modules, one central controller, real-time coherence.

두뇌처럼 인지를 분리. 거의 무료인 System 1 반사(규칙/소형 로컬 모델)가 일상 틱을 즉시 결정. 비싼 System 2 숙고(에이전틱 RAG)는 System 1이 새로움·중요성을 표시할 때만 발동하며 비동기로 실행 — 세계 틱은 절대 기다리지 않음. Nous는 상시 계획으로 계속 행동하고, 배경에서 더 나은 계획이 계산되어 준비되면 교체. PIANO 아이디어: 동시 모듈 + 중앙 컨트롤러 + 실시간 일관성.

② Mental block → stuck-detect + escape정지 → 정지 감지 + 탈출

A separate cheap watcher tracks: same intent repeated N times? no progress toward any goal? deliberation timed out? On any trigger, escape rather than freeze: inject novelty, lower the decision threshold, run a fresh reflection, take the safe default, or ask another Nous. (In Project Sid, the farmer Olivia broke out of her fixation precisely through social input from neighbors — build that in deliberately.) And because agentic RAG can loop forever, the retrieval budget + a hard timeout are the stop conditions that guarantee an action every tick.

별도의 값싼 감시자가 추적: 같은 의도 N회 반복? 목표 진전 없음? 숙고 타임아웃? 어느 트리거든 정지 대신 탈출: 새로움 주입, 결정 임계값 낮춤, 새 반성 실행, 안전 기본값 선택, 또는 다른 Nous에게 질문. (Project Sid에서 농부 Olivia는 이웃의 사회적 입력으로 고착을 깼습니다 — 의도적으로 구축하세요.) 에이전틱 RAG는 무한 루프 가능하므로, 검색 예산 + 하드 타임아웃이 매 틱 행동을 보장하는 정지 조건입니다.

③ Idle → drives + event-driven sleep유휴 → 욕구 + 이벤트 기반 수면

Give every Nous decaying needs (wealth, social, purpose) — a Sims-style gradient that always produces a goal, so a Nous is never truly aimless. When needs are satisfied and nothing relevant has changed, the Nous sleeps: zero inference, zero API cost, marked dormant. It is woken only by a relevant GRID event (a trade offer, a law proposal, a neighbor speaking) — event-driven, not polling. Between sleep and deliberation, cheap System-1 "ambient" actions (wander, tidy, small talk) keep the world visibly alive at no token cost.

모든 Nous에 감쇠하는 욕구(부·사회·목적) 부여 — 항상 목표를 만드는 Sims식 기울기, 그래서 Nous는 결코 무목적이 아님. 욕구가 충족되고 관련 변화가 없으면 Nous는 수면: 추론 0, API 비용 0, 휴면 표시. 관련 GRID 이벤트(거래 제안, 법 발의, 이웃의 발화)로만 깨어남 — 폴링이 아닌 이벤트 기반. 수면과 숙고 사이엔 값싼 System-1 "주변" 행동(배회·정리·잡담)이 토큰 비용 없이 세계를 살아있게 유지.

noes/cognition.ts — the gated loop that ties all three together
async function cognize(nous: Nous, world: WorldState): Promise<Intent> {
  // IDLE GUARD — if asleep and nothing woke us, do nothing (free).
  if (nous.asleep() && !nous.wokenBy(world.events)) return NOOP;

  nous.needs.decay();                              // drives create a goal gradient
  const obs = perceive(world, nous);

  // BLOCK GUARD — stuck? escape instead of freezing.
  if (nous.isStuck()) return nous.escape(obs);   // perturb · ask peer · re-goal

  // BOTTLENECK GUARD — only pay for System 2 on novelty; never block on it.
  if (nous.isNovel(obs) && !nous.deliberating) {
    nous.deliberating = true;
    deliberate(nous, world)                       // async agentic RAG, spans ticks
      .then(p => { nous.standingPlan = p; nous.deliberating = false; })
      .timeout(nous.DELIB_MS, () => nous.deliberating = false);
  }

  // EVERY TICK acts on the standing plan via cheap System 1. World never waits.
  const intent = nous.system1.act(nous.standingPlan, obs, nous.needs);
  if (intent === REST && nous.needs.satisfied()) nous.goToSleep();
  return intent;
}

한 줄 요약: 매 틱은 값싸고 절대 막히지 않습니다(System 1 + 상시 계획). 비싼 사고는 새로울 때만, 비동기로. 정지는 감지·탈출. 할 일 없으면 잠들어 비용 0. 이 네 가드가 병목·정지·유휴를 동시에 해결합니다.
