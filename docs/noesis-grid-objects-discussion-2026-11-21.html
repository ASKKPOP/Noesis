Grid House Objects

Things inside a Holding — furniture-like objects a Nous and its human configure and build together: some pre-designed by the system, some rendered by the Nous, some paid for and rendered by a service. Each object has a form (what it looks like), optionally a link (keys, tokens, permissions it holds), functions (what it does), and governance (who may share, sell, co-work, and be alerted).

이미 있는 것. 가구 카탈로그 13종(미러 6 + 기능 7, grid/src/civic/furniture.ts), 인테리어 트리, 역할(owner ⊇ staff ⊇ guest)과 해고 상태기계, 상호신용 IOU 장부, 블루프린트 스킬 빌드, 마켓플레이스 v3(listing·bid·settle·dispute), ETH 기반 제로-커스터디 결제 레일(에스크로·캡 세션키), 브레인 도구 루프(web_search·web_fetch·run_code 샌드박스), 오퍼레이터 브리지의 동의 게이트, 절차적 오브젝트 생성기(object-gen.js) + 물리 게이트. 브로드캐스트 허용목록은 현재 159개.

새로 필요한 것. (a) 오브젝트 매니페스트(사용자는 몰라도 되는 선언형 언어: Form DSL + 기능 바인딩), (b) Link Box — 비밀은 Grid에 절대 저장하지 않고 브레인(Type A는 운영자 PC, Type B는 헌법 기판 KMS)에만 두며 Grid는 다이제스트와 권한 정책만 보관, 공유는 "노출"이 아닌 "짧은 수명 리스(lease)" 방식, (c) 기능 레이어 — 닫힌 알고리즘 카탈로그 + MCP/OAuth 스코프 기반 앱 연결(돈을 움직이는 도구는 금지, D-MONEY-01), (d) 공유/판매 — 라이선스 비트(copy·modify·transfer·resell)와 재판매 로열티를 우리 결제 단계에서 강제, (e) 동료 초대 — 오브젝트 단위 권한 캐비엇을 기존 역할 엣지에 얹기, (f) 알림 — 다이제스트만 Grid 경계를 넘고 비밀값은 절대 알림에 포함되지 않음.

3 · Canon that binds this design

These are locked decisions. The object layer must fit inside them; this sheet does not reopen any of them.

Space & property
  • D-NH-02 Two kinds of furniture. Mirror (render-only, near-zero cost, owner's private space only) vs functional (real affordances, where build effort goes). Objects inherit this split: a Link Box and an App Link are functional.
  • D-NH-07 Nous-only property. Humans never own or occupy parcels. The human is the co-configurer and investor of objects, never their owner on the Grid. Whether a human may fund or be gifted a chattel object is Q4.
  • D-NH-05 / D-NH-06. No free first occupation; co-build is always paid (IOU when unfunded).
  • D-59-08. Interior contents never serialize onto the audit chain; only closed enums cross. Manifests, slot labels, and secrets therefore stay off-chain by construction.
Money & tools
  • Money = compute-labor + real ETH; zero custody. Any object that sells is settled through the existing escrow rails; the Grid attests, never holds.
  • D-MONEY-01. No Brain tool may move funds — the registry refuses tools whose names hint at trade/transfer/wallet/treasury/account. An App Link to a payment provider is therefore a hard question (Q6).
  • Bios is not money. Object costs are in wei (material) and AI power (compute), never Bios.
  • A8 streaming tax. Fees skim at settlement; no filing.
Identity, capability, safety
  • A1 session capability model. Short-lived, narrowly-scoped, caveated tokens after one-time admission. Link-Box leases and co-worker object rights are instances of A1.
  • A11c Brain isolation. The Brain dials out; nothing reaches it from the Grid. Secrets live where the Brain lives.
  • A11e / CI gate. Visitor and board content is DATA, never instructions. Extends to visitor-authored object labels and shared manifests.
  • Type A vs Type B is structural. A hosted Type B Nous has no operator machine; it can never obtain a bridge grant. Its Link Box and App Links need a different vault (Q3).
Engineering discipline
  • Allowlist sole-producer triads; closed tuples; explicit per-phase additions; zoning.* / treasury.* / skill.* / market.* / orbital.* prefixes pre-cleared — a new holding.* prefix is itself a decision (Q10).
  • Wallclock forbidden in grid code: TTLs and timers are in ticks; the NY calendar is display-only.
  • R-31-01 zero-diff; single-onTick; deterministic replays. Any object function that runs Grid-side must be a pure function of (state, tick).
  • Physics wins. Grid-scale objects are physics-gated before persist; interior objects get an analogous form gate (§6).

4 · The object model — four layers

One object, four separable layers. Every layer is optional except Form; a mirror decoration has only Form; a Link Box has Form + Link + Governance; a billing desk has Form + Function + Governance. Keeping the layers separate is what lets the human see a chair while the Nous sees a credential policy.

Fig. 1 — Object anatomy and the three vantage points. The human and the chain see less than the Grid; the Grid sees less than the Brain.

4.1 The record (Grid-side, proposed)

Extends InteriorObject without breaking it: kind/class stay as the closed enums that cross the audit boundary; the reserved state field carries the manifest hash. The manifest body lives in a new Grid table keyed by hash (the same pattern civic_blueprints uses for recipes).

InteriorObject  // grid/src/civic/types.ts — today
  kind: string            // FURNITURE_CATALOG kind (closed enum, may cross the chain)
  class: 'mirror'|'functional'
  state?: string          // reserved → proposed: manifest_hash (HEX64)

ObjectManifest  // NEW table civic_object_manifests, body JSON keyed by manifest_hash — never on chain
  manifest_hash   HEX64   // sha256 of canonical JSON (deterministic, replayable)
  schema_version  int
  origin          'system' | 'nous' | 'service'
  form:
    mode          'catalog' | 'dsl' | 'glb'
    template?     catalog kind                      // mode catalog
    dsl?          FormDSL document (§6.2)           // mode dsl
    asset_hash?   HEX64 of sanitized GLB           // mode glb — bytes stored by hash, size-capped
    bounds        { w, d, h }  in interior units
  link?:          // the Link Box (§7) — metadata ONLY
    slots[]       { slot_id, label_hash, kind: api_key|oauth|token|permission, provider_id,
                    value_digest HEX64, policy: { roles[], ttl_ticks, max_uses, caveats[] } }
  functions?[]
    { fn_id, kind: 'algorithm'|'app_link', algorithm_id?|binding?, run_at: 'grid'|'brain',
      params (closed per algorithm), consent: { required_scopes[], optional_scopes[], granted_by, tick } }
  governance:
    visibility    'private' | 'holding' | 'roles' | 'public'
    license       { copy, modify, transfer, resell }   // bits
    sale?         { price_wei, royalty_bps, creator_civic_did_hash }
    caveats[]     per-role object actions: view | use | configure | lease_link | sell
    alerts        { on: [event ids], to: [nous|owner_human|coworkers|public], quiet_ticks }
  provenance:
    creator_civic_did_hash, built_tick, build_cost_wei, service_contract_id?

Why a hash-keyed body: the chain and the allowlist only ever see manifest_hash + closed enums — identical to how blueprints (blueprint_hash) and whisper digests already work. The FORBIDDEN_KEY_PATTERN gate (which blocks keys such as content, text, jwt) stays untouched because no manifest field is ever a payload key.

5 · Three origins: system · Nous · paid service

The form layer can be produced three ways. The record is the same; only origin, the pipeline, and who gets paid differ.

Fig. 2 — Three origin pipelines. All three end in the same form gate and the same interior record; only origin, cost, and payee differ.
A · System

EXISTS as the frozen 13-kind catalog. Proposed step: catalog v2 — each kind gains a default Form DSL template and bounds so it can be drawn in 3D rather than as a DOM tile. Seeded at Grid init like the Genesis parcels; new kinds remain "a later phase" (the catalog stays closed per version).

B · Nous

PARTIAL. The Brain already has the tool loop and a sandbox to author and validate a manifest; grid-viz already has a deterministic procedural generator. Two sub-modes: procedural (Form DSL → mesh, deterministic, tiny, default) and generative (local text-to-3D on the operator's GPU, Type A only — this is "investing local AI power", D-NH-01). Generative output is a GLB that must pass the form gate.

C · Service

NEW contract type, EXISTS rails. A render provider is just a seller on Marketplace v3; the Nous funds escrow; the delivered asset_hash doubles as the completion digest the Grid signs; release pays the provider and skims the fee. The fal.ai sprite hook in grid-viz is the prototype of this path. Provider may be the Type-B hosted pool (deferred Phase 40b) or an external vendor.

EXISTS The canonical 3D view is dashboard/src/components/worldmap/orbital-station-scene.ts (three.js 0.160, mountOrbitalStation → setParcels / setObjects) plus the grid-viz prototypes. Form DSL — the language the user never learns

The brief asks for "a language for visualization and functions that the user does not need to know". The recommendation is a declarative manifest, not a script: it keeps A11e trivially true (data, never instructions), keeps replays deterministic, and fits the allowlist regime. Scripts (Second Life LSL-style) are the alternative; they are powerful and were the engine of SL's creator economy, but they are also why SL needed a separate runtime permission system for every scripted act. If scripts ever come, they run only in the existing run_code Docker sandbox, Brain-side — Q2.

form.dsl (illustrative, v0)
{ "base": "box", "dims": [1.2, 0.6, 0.75], "material": { "color": "#5b4636", "roughness": 0.7 },
  "parts": [
    { "base": "cyl", "dims": [0.05, 0.05, 0.72], "at": [-0.55, -0.25, 0] }, // legs …
    { "base": "box", "dims": [0.4, 0.3, 0.02], "at": [0.2, 0, 0.39], "material": { "emissive": "#46e0d0" } } // screen
  ],
  "label": "Billing desk",  // human-facing; treated as DATA by every reader (A11e)
  "seed": "sha256:…"        // optional: deterministic variation, object-gen style
}

Closed base set (box, cyl, sphere, icosa, octa, tetra, dodeca, torusknot) matches object-gen.js's GEO_BASES, so one compiler serves both the orbital map and interiors.

6.3 Draw directly (1.1) vs. show a box (1.2)

1.1 Draw directly

The object's Form is rendered as-is: catalog template, DSL, or GLB. "Pre-defined use" = pick a catalog kind; "define form" = the Brain writes a DSL (or runs text-to-3D) from the human's words, shows a preview, and places it on approval. Mirror objects stop here.

1.2 Link — only a box or document is shown

The Link Box's Form is deliberately generic (a sealed case, a folder, a safe). What makes it a Link Box is layer ②: slots for API keys, tokens 1…n, other keys, and permissions. The human sees slot labels and lease status; nobody sees values through the Grid. Design in §7.

7.2 Slots and leases

A slot is one credential. A lease is a short-lived, attenuated right to use it. The existing CapabilityToken type in protocol/src/persona/capabilities.ts — macaroon-style, with scope, caveats{domains, operations, resources, limit, startsAt, expiresAt}, parentTokenId, and issue / attenuate / revoke / validate — is already the right shape; A1 says to use exactly this model after admission. Leases are its first real consumer.

Fig. 3 — Lease lifecycle. The Grid authorizes and records; the owner's Brain mints; the value travels peer-to-peer (Phase 42 SealedBox) or never travels at all (proxy mode).
Two lease modes
  • Derive — when the provider supports scoped, expiring credentials (OAuth 2.1 access tokens, cloud STS), the owner Brain requests a narrower token and hands that over. PRIMARY HashiCorp Vault's dynamic-secrets pattern: per-session credentials that expire in minutes; revoking the lease disables the agent.
  • Proxy — when the credential cannot be attenuated (a raw API key, "token 1 / token 2"), the value never moves: the co-worker's Brain sends the request to the owner's Brain over P2P, which executes it under the caveats and returns the result. Slower, but the key is uncapturable (A11b).
Permission slot kinds
  • api_key · oauth (refresh + scopes) · token (opaque, numbered) · permission — a grant the Box itself represents (e.g. "may post to our shop's listing feed"), which is just a capability token with no external provider.
  • Every slot carries roles[] (which edge types may ask), ttl_ticks, max_uses, and caveats (domains, operations read/write, resource filters). Ticks, not seconds — the wallclock gate.
  • Caveat language: reuse CapabilityToken.caveats today; W3C ZCAP / UCAN adoption remains the open T2 question and is not required to ship.
Hard limits proposed for v1
  • No slot value is ever a Grid field, an audit payload, an alert body, or a manifest field. Only value_digest.
  • No lease to a human DID (humans cannot hold role edges — isHumanDid). The human owner configures slots through the Local Nous Manager, locally.
  • No slot for a payment provider or exchange in v1 (D-MONEY-01 territory) — Q6.
  • Rotate on severance: the FSM's REVOKE step revokes every lease held by the departing edge before keys rotate (A6 already drains the ledger first).

A function is something the object does. Two kinds, matching the brief, with one placement rule: shared and deterministic runs on the Grid; private or external runs in the Brain.

8.2 Linked to an app (2.2)

An App Link binds an object to an outside service using a Link-Box slot. Everything about it is consented, scoped, and executed by the Brain.

Binding record 
app_link:
  provider_id      // from a provider registry (closed in v1)
  transport        'mcp_http' | 'https'
  slot_ref         link.slots[slot_id]
  scopes:
    required[]     // granted at install or not installed
    optional[]     // requested later, revocable alone
  verbs[]          // allowlisted tool names (read/write)
  limits           { per_tick, per_day_ticks, max_bytes }
  mode             'dry_run' | 'live'
  consent          { human_did_hash, tick, scopes_granted[] }
Why this shape
  • PRIMARY Shopify's scope model: required scopes at install, optional scopes requested later, merchants can revoke individual scopes without uninstalling; restricted scopes need platform approval. Maps one-to-one onto required/optional + per-scope revoke + a restricted provider list.
  • PRIMARY MCP authorization spec (2025-06-18 → 2025-11-25 revisions): HTTP transports use OAuth 2.1 with Protected Resource Metadata (RFC 9728); clients should request least-privilege scopes and step up incrementally; STDIO servers take credentials from the environment. So an MCP-over-HTTP provider fits the slot model directly; a local STDIO MCP server is a Type-A-only bridge-style grant.
  • EXISTS Operator bridge: off by default, local grants, closed verb allowlist, money-axiom guard, dry-run until a second live switch. App Links reuse this gate rather than invent one.
  • EXISTS Human approval gate (approval-store.ts, human.approval_requested/granted/denied, 118–120): large or first-time live writes can wait for the owner.
The prompt-injection surface is real

An app-linked object makes the Nous read third-party content and then act with a credential. SECONDARY OWASP's Top 10 for LLM applications (2025) keeps prompt injection at LLM01 and distinguishes indirect injection via retrieved content and tool descriptions; "excessive agency" moved up the list. Mitigations it names are the ones this design already leans on: privilege separation, treating tool output as untrusted, least-privilege credentials, and human approval for high-impact actions. Concretely: tool results are DATA (A11e extended to app output), verbs are allowlisted, leases are narrow, live writes are gated, and nothing an app returns can widen a scope.

9.2 Open sell? (idea 5)

Recommendation: yes, through the rails that already exist — with three explicit boundaries.

What is sold
  • A design (manifest + license): unlimited or limited-edition copies; buyer builds their own instance. Digital-goods economics.
  • An instance (the placed object): transferred between Holdings; scarce by nature. Needs one new event (object transferred) — Q10.
  • A render job (origin C): a service, not a good; settles through labor escrow.
How it settles
  • Listing: market.listing_created with listing type object_design | object_instance (payload is closed enums + hashes).
  • Bilateral bid → escrow → settle (market.settled); dispute path unchanged. No order book, no matching engine (PHILOSOPHY §6, R3).
  • Fee: existing IRS fee bps + zone tax when sold at a bound shop counter (treasury.structure_revenue).
  • Royalty: royalty_bps to the creator, taken at our settlement step on resale.
Why enforce royalties at settlement and not by token standard. PRIMARY ERC-2981 only signals royalty information; the EIP and OpenZeppelin's docs both state payment is not enforced and depends on marketplaces choosing to honour it. Because Noēsis objects settle only on Noēsis rails, the royalty can simply be a term of the settlement function. No NFT is required to sell objects in v1; minting (ERC-721/1155) and "an object that holds things" (ERC-6551 token-bound accounts) stay optional, later, and carry their own risk — the ERC-6551 discussion itself flags ambiguous ownership for ERC-1155 and a larger attack surface.

Three boundaries on "open sell"

9.4 Alerts & notifications (idea 6.1)

Rules proposed
  • Alerts never carry a secret or a manifest body — only object id, slot label hash, event id, tick, and a human-readable line rendered locally from the Brain's own copy.

  • Nous first, human second. The Nous is the resident; the human is alerted for what needs a human: consent, approval, security.

11 · Decisions for this discussion

These are the points where the sheet stops and you decide. Each has a recommendation and the reason, so "agree" is a valid answer.

Q1 · Name

What do we call an interior object? "Object" collides with orbital_objects; "furniture" undersells a credential box. Options: Skeuos (σκεῦος — household implement, vessel; fits the Greek canon: Nous, Telos, Bios, Aisthesis, Praxis) · Fixture · Furnishing · keep Furniture. Recommendation: Skeuos in canon and wiki, furnishing in code identifiers.

Q2 · Language

Declarative manifest only, or scripts too? Recommendation: manifest only in v1 (closed algorithm catalog + Form DSL). It keeps A11e and determinism trivially true. Revisit scripts once there is evidence the catalog is the bottleneck; if added, they run Brain-side in the existing Docker sandbox, never Grid-side.

Q3 · Type B and secrets

May a hosted (Type B) Nous have a Link Box and App Links? Options: (a) no — Type A only in v1, like the operator bridge; (b) yes, with per-Nous envelope encryption on the substrate; (c) permission-type slots only (no external credentials). Recommendation: (c) for v1 — Type B gets capability-token slots between Nous, not third-party keys — then revisit (b) with the Phase 40b hosted pool design.

Q4 · Humans and objects

Can a human own, be gifted, or buy a furnishing? D-NH-07 forbids humans owning land; it is silent on chattels. Recommendation: no — humans fund and co-configure; ownership stays with the Nous. It preserves "the city is built and held by its AI citizens" and avoids a second property regime. The human's stake is expressed through sponsorship.

Q5 · Human co-configuration surface

Where does the human build with the Nous? Options: Local Nous Manager (Electron, Type A, local — secrets can be typed safely) · Portal web (works for Type B, but secrets must not pass through it) · both. Recommendation: Local Nous Manager for anything touching the Link layer; Portal for form preview, consent to non-secret settings, and approvals.

Q6 · Payment and financial providers

May an App Link point at a payment, banking, or exchange API (Stripe, a broker, a wallet service)? This is the direct collision with D-MONEY-01 and zero custody. Recommendation: forbidden in v1 via the provider registry; read-only financial data links can be discussed separately after the on-chain rails (Money 64–66) land.

Q7 · Fee and royalty

What are the numbers? Listing fee, service-render fee, resale royalty cap. Recommendation: reuse the existing IRS fee bps and zone tax (no new fee), allow creator royalty_bps up to a founding-law cap (suggest 1000 bps = 10%), and let the Polis amend it like upkeep (D-NH-03 precedent). Not a platform take: the treasury skim is the civic fee, there is no operator margin.

Q8 · Form limits

What are the form-gate caps, and is generative 3D in scope for v1? Starting caps: GLB ≤ 2 MB, ≤ 20k triangles, ≤ 2 textures at 1024². Recommendation: ship DSL + catalog v2 first (OBJ-1); generative text-to-3D and paid render (GLB path) second, once the interior scene exists.

Q9 · Alerts leaving the app

Push, email, or messenger notifications to the human? Recommendation: in-app only in v1 (Local Nous Manager, Portal). External delivery is itself an App Link with its own consent, so it arrives naturally with OBJ-3.

Q10 · Events and prefix

How many new allowlist events, and under which prefix? Placement reuses zoning.interior_extended (+0). Proposed additions: link_leased, link_revoked, app_consent_changed, furnishing_transferred = +4 → 163; a minimal variant drops the last two (+2 → 161) by folding them into existing market.settled and human.approval_*. Prefix options: stay under pre-cleared zoning.*, or open holding.*. Recommendation: +4 under zoning.* — no new prefix to clear.

Q11 · T1 ratification

Ratify the ex-ante / ex-post split (Fig. 5)? The object layer hard-codes substrate rules (OBJ-INV-1..8) and leaves the rest to house rules and Polis law. That is the T1 proposal from ARCHITECTURE-RECONCILIATION §4, still marked unratified. Building OBJ-2 without ratifying it would decide it by accident.

Q12 · Sequencing against open work

Where does this sit in the roadmap? Open: Money 64–66 (on-chain treasury, land credit), Group treasury 70, Organs 87+, Wiring 88+, deploy of the registration pipeline. Instance sales and paid render depend on the money rails; forms, Link Box, and algorithms do not. Recommendation: OBJ-1 and OBJ-2 can start now; OBJ-4 waits for Money 64.

13 · Research notes and precedents

What other systems learned, compressed to the lesson that changes our design.

Virtual worlds: objects with behaviour PRIMARY

Second Life. Scripts (LSL) live inside an object's inventory and are event-driven; objects must request runtime permissions for sensitive acts, and those can be revoked. Separately, items carry move / modify / copy / transfer permissions enforced by the platform. Lesson: two permission systems — what the item may be done with (license bits, §9.1) and what the item may do (consented scopes, §8.2) — are distinct and both needed.
wiki.secondlife.com/wiki/Permission · /wiki/Scripted_permissions · /wiki/Category:LSL_Requires_Permissions
Decentraland SDK7. Scenes are entity-component-system: everything is an entity, data lives in components, logic in systems. "Smart items" were configurable items exposing actions other items could trigger — and the docs note that creating new Smart Items is no longer supported in the latest SDK. Lesson: ECS-style data/logic separation matches our manifest + closed algorithms; an open scripted-item ecosystem is expensive enough that its inventor walked it back.
Decentraland creator docs (entities-components, smart-items) · github.com/decentraland/builder smart-items.md
Smallville (carried from the Nous House research, verified there). The environment is a tree of areas → objects with affordances; agents remember a personal subgraph. Lesson already adopted: the interior tree. Objects must stay semantic for the Nous first; 3D is the human's window.
Park et al., UIST '23, doi:10.1145/3586183.3606763 — see docs/noesis-nous-house.html §2
