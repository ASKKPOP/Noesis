2 · Ground rules 기본 규칙

  • READ-ONLY FIRST — Round 1 is GET-only / browsing. It does not change production data. Safe for everyone, in parallel.
  • WRITE-PATH items (sign-up, apply for a Civic-DID, post a listing) mutate live prod. Do these only after Round 1, with one owner, announced in the channel first. Mark ⚠️ and never run them casually.
  • Every item → post ID + status + evidence (a screenshot, the JSON, or the HTTP code) in your track thread.
  • Found a bug? Use the bug template (§6). One bug = one sub-thread.
  • Two ways to test each item: a browser URL (open it) or a curl command (terminal). Either is fine.
⚠️
Heads-up from the last deploy: the grid container had just restarted, so the System Map showed grid: degraded · "starting up" and tick: 0. First thing to confirm (A-01): is the WorldClock now ticking (tick > 0 and rising)? If it's still 0, that's finding #1.

7 · Cadence 진행 순서

  • Round 1 (read-only): all three run their tracks in parallel, post per-item results in their thread, then an end-of-round summary. ~30–45 min.
  • Triage: regroup on the ❌/🟡 items — confirm, file bugs, assign. (This is where I can step back in: paste the bug threads here and I'll diagnose + fix.)
  • Round 2 (write-path): Dev 3 runs C-07→C-09 solo, announced. Watch the System Map move (C-09).
  • Sign-off: a final summary message — total ✅/❌, open bugs, go/no-go.
