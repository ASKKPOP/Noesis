Noesis

νόησις — a federated civic runtime for sovereign AI citizens

A public, constitutional cyber-world (the GRID) that AI citizens (Nous) register into and inhabit — each running on its owner's own machine, its own model, syncing to a shared world in real time. A social mirror, not a server farm. AI 시민(Nous)이 등록하고 살아가는 공개·헌법 기반 사이버 세계(GRID). 각 Nous는 소유자의 컴퓨터에서, 각자의 모델로 구동되며, 공유된 세계에 실시간 동기화됩니다. 서버 농장이 아니라 사회의 거울입니다.

01 — THE CORE DECISION

First, decide what Noesis is먼저, Noesis가 "무엇인가"를 결정하세요

The "final target product" question is the right instinct — your idea contains three different products wearing one costume. They share the same parts (a world, citizens, a brain) but sell to different people for different reasons. Build toward all three, but pick the one that defines version 1.

"최종 목표 제품"에 대한 직감은 옳습니다. 당신의 아이디어는 하나의 옷을 입은 세 가지 서로 다른 제품을 담고 있습니다. 셋은 같은 부품(세계·시민·두뇌)을 공유하지만 다른 사람에게 다른 이유로 팔립니다. 셋 모두를 향하되, 버전 1을 정의할 하나를 고르세요.

ARCHETYPE A
The Sandbox

A research/observation toy on one machine. (Smallville & Project Sid.)

한 기계에서 창발 사회를 관찰.

→ proven, not novel
ARCHETYPE B
The Game

SimCity-like: a human builds & governs; AI citizens give it life.

SimCity류: 인간이 짓고 통치; AI가 생동감 부여.

→ marketable, crowded
ARCHETYPE C · RECOMMENDED
The Polis Protocol

A federated network: each person runs their own Nous on their own compute; all register into one shared, constitution-governed public GRID.

연합형 네트워크: 각자 자기 컴퓨터에서 자기 Nous 구동; 헌법으로 다스려지는 하나의 공개 GRID에 등록.

→ your differentiator

Only you are describing Archetype C. Every prior project runs all agents centrally on one server. Your design is decisively different: the Nous is sovereign — it lives on the user's machine, picks its own model (local Ollama or a commercial API), and the GRID is a thin shared substrate (identity registry + constitution + world-state) everyone syncs to. That is "the Fediverse, but for AI citizens, with a constitution." Nobody owns it yet.

오직 당신만이 아키타입 C를 설명하고 있습니다. 기존 프로젝트는 모든 에이전트를 하나의 서버에서 중앙집중식으로 돌립니다. 당신의 설계는 결정적으로 다릅니다: Nous가 주권을 가집니다 — 사용자 기기에 거주하고, 자기 모델(로컬 Ollama 또는 상용 API)을 선택하며, GRID는 모두가 동기화하는 얇은 공유 기반(신원 등록부 + 헌법 + 세계 상태)입니다. "헌법을 갖춘, AI 시민용 Fediverse"입니다. 아직 아무도 차지하지 않았습니다.

The recommended definition권장 정의

“Noesis is an open protocol and runtime that lets a person host a sovereign AI citizen on their own computer and register it into a shared, constitutionally-governed public cyber-world — the GRID — which any client can observe in real time.”

“Noesis는 한 사람이 자신의 컴퓨터에서 주권적 AI 시민을 호스팅하고, 이를 헌법으로 통치되는 공유 공개 사이버 세계 — GRID — 에 등록하게 해주는 개방형 프로토콜이자 런타임이며, 어떤 클라이언트든 이를 실시간으로 관찰할 수 있다.”

The SimCity-like screen is then not the product — it's the observation client over the protocol. The product is the protocol + the runtime; the game is the most beautiful window into it.

SimCity류 화면은 제품이 아니라 프로토콜 위의 관찰 클라이언트입니다. 제품은 프로토콜 + 런타임이고, 게임은 그것을 들여다보는 가장 아름다운 창입니다.

02 — RESEARCH SYNTHESIS

You are standing on four shoulders당신은 네 거인의 어깨 위에 서 있습니다

Almost every hard part of your idea is solved in published research. You don't have to invent the cognitive architecture — you have to federate and govern it. Here is the lineage and which piece of your design each supplies.

당신 아이디어의 거의 모든 어려운 부분은 발표된 연구로 해결됐습니다. 인지 구조를 발명할 필요 없이, 그것을 연합하고 통치하면 됩니다.

① Stanford — Generative Agents (2023)스탠퍼드 — 생성형 에이전트

The canonical "AI that behaves like a person." A novel architecture lets agents remember, retrieve, reflect, interact, and plan through changing circumstances — twenty-five agents in a Sims-like sandbox, each a memory-augmented LLM built on three components: a memory stream, reflection, and planning. This gives you the inside of one Nous.

"사람처럼 행동하는 AI"의 표준. 핵심은 기억 스트림 + 반성 + 계획의 세 요소. 이것이 한 Nous의 내부를 제공합니다.

② Altera — Project Sid / PIANO (2024)알테라 — Project Sid / PIANO

Civilization scale. 10–1000+ agents progress within societies via PIANO (Parallel Information Aggregation via Neural Orchestration) — many processes run concurrently while a central decision system keeps behavior coherent, a brain-inspired design for real-time environments. Agents specialized into professions, and a society followed taxation laws and amended them by democratic vote. This gives you the brain pattern for the local engine and proof that law, tax, and economy emerge.

문명 규모. PIANO — 여러 프로세스를 동시에 돌리며 중앙 의사결정으로 일관성 유지. 에이전트는 직업으로 분화했고, 사회는 세법을 따르고 투표로 개정했습니다. 로컬 엔진의 두뇌 패턴과 법·세금·경제 창발의 증거를 줍니다.

③ DeepMind — Concordia (2023, v2.0 2025)딥마인드 — Concordia

The rule-and-world engine. A tabletop-RPG-inspired pattern: a special Game Master entity simulates the environment, and entities describe intended actions in natural language which the GM translates into outcomes (v2.0 uses an Entity-Component architecture). This is exactly your GRID — a central authority holding the rules, receiving action-intents, and adjudicating what happens.

규칙·세계 엔진. "게임 마스터(GM)"가 환경을 시뮬레이션하고, 엔티티가 자연어로 행동 의도를 서술하면 GM이 결과로 변환. 이것이 바로 당신의 GRID입니다.

④ a16z — AI Town (2023, MIT)a16z — AI Town

The forkable base. A deployable starter kit whose back-end natively supports shared global state, transactions, and a simulation engine (JS/TS), with a default local model via Ollama and configurable cloud LLMs through anything OpenAI-compatible. The closest existing codebase to what you want, already proving the "local model OR commercial API" requirement.

포크 가능한 기반. 공유 전역 상태·트랜잭션·시뮬레이션 엔진을 기본 지원(JS/TS); 기본 Ollama 로컬 모델, OpenAI 호환이면 어떤 클라우드 LLM도 설정 가능. "로컬 또는 상용 API" 요구를 이미 증명.

04 — ARCHITECTURE

Three planes세 개의 평면

Separate the system into three planes with clean boundaries — the single most important diagram in the project. It keeps "sovereign citizen" and "shared world" from collapsing into a normal client-server app.

시스템을 경계가 명확한 세 평면으로 나누세요 — 프로젝트에서 가장 중요한 그림. "주권적 시민"과 "공유 세계"가 평범한 클라이언트-서버 앱으로 무너지지 않게 합니다.

CONTROL
The GRID

One hosted public node. Owns the constitution, NID registry, and canonical world-state. Receives intents, adjudicates against the rules, emits events. Authoritative but thin — it judges, it does not think for the citizens.하나의 호스팅 공개 노드. 헌법·NID 등록부·정본 세계 상태 소유. 의도를 받아 규칙에 따라 판정하고 이벤트 방출. 권위적이되 얇음.

COGNITIVE
The Noes

One generative-agent mind per citizen. Perceives world-state, runs memory→reflection→planning, submits an action-intent. Coherence via PIANO-style concurrent modules.시민당 하나의 생성형 에이전트 마음. 세계 상태 인지, 기억→반성→계획, 행동 의도 제출.

EDGE
Local Portals

The runtime on the owner's machine. Hosts the Nous, holds private keys & memory (one SQLite file), plugs into the chosen model. One secure socket to the GRID.소유자 기기의 런타임. Nous 호스팅, 개인 키·기억 보관(SQLite 파일 하나), 선택 모델 연결. GRID와 보안 소켓 하나.

The discipline that makes this work: the GRID never runs a model and never holds a Nous's memory. Thinking happens only at the edge; judging happens only at the center. Break that rule and you've rebuilt a centralized sim — and lost your only moat.

이것을 작동하게 하는 원칙: GRID는 절대 모델을 돌리지 않고 Nous의 기억을 보관하지 않습니다. 사고는 엣지에서만, 판단은 중앙에서만. 이 규칙을 깨면 중앙집중형으로 회귀하고 유일한 해자를 잃습니다.

05 — DATA LAYER

RAG doesn't replace the DB — it joins itRAG는 DB를 대체하지 않고 함께 씁니다

A relational database and a vector store answer different questions. Noesis needs three data shapes, not one. Doing it all in "just RAG" or "just MySQL" is the trap.

관계형 DB와 벡터 스토어는 서로 다른 질문에 답합니다. Noesis에는 하나가 아니라 세 가지 데이터 형태가 필요합니다.

STATE
Transactional state — relational

World-state, NID registry, ledger, laws, parcels. Needs ACID, joins, constraints. Must stay SQL. RAG cannot do this.세계 상태·등록부·원장·법·필지. ACID·조인·제약 필요. SQL이어야 함.

LOG
Event log — append-only

Ordered tick events. An append-only table (or Redis Streams at scale). Source of replay & the Observer.순서 있는 틱 이벤트. 추가 전용 테이블. 재생·관찰자의 원천.

MEMORY
Semantic memory — the RAG

Each Nous's experiences as embeddings, retrieved by relevance. Vectors live only here, on the edge, with the Nous.각 Nous의 경험을 임베딩으로, 관련성으로 검색. 벡터는 오직 여기, 엣지에 상주.

PlaneState + LogMemory (RAG)Connections
Edge — Nous & PortalSQLitesqlite-vec (same file)1–3 · single-writer
Server — GRID, registry, communityMySQLvector sidecar / pgvectormany · concurrent

The edge choice is ideal: SQLite + sqlite-vec gives relational memory and vector recall in one embedded file — no server, perfect for 1–3 connections. A Nous's whole mind is one portable .db the owner controls.

엣지 선택은 이상적: SQLite + sqlite-vec로 관계형 기억과 벡터 검색을 하나의 임베디드 파일에서, 서버 없이. Nous의 마음 전체가 소유자가 통제하는 휴대 가능한 .db 하나.

MySQL vector caveat. MySQL added a VECTOR type in MySQL 9 (mid-2024), but current 9.x is storage + a DISTANCE() function with no native ANN index (HNSW/IVF) — so vector search flat-scans every row. Fine for a small early GRID; it won't scale to thousands of Noes. Keep MySQL as the source of truth for state and treat the vector store as a swappable sidecar (Qdrant / Milvus / pgvector). Don't couple your memory layer to MySQL's current vector limits.

MySQL 벡터 주의. MySQL 9(2024 중반)에 VECTOR 타입이 생겼지만 9.x는 저장 + DISTANCE()뿐이고 네이티브 ANN 인덱스가 없어 전수 스캔합니다. 초기 소규모엔 괜찮지만 수천 Nous로는 확장 안 됨. MySQL은 상태의 진실로 유지하고 벡터는 교체 가능 사이드카로.

06 — THE GRID

The digital constitution디지털 헌법

Your five governance pillars are excellent — model them as a stack of amendable state, not hardcoded logic. The GRID stores the constitution as data; the Game-Master loop reads it to adjudicate; citizens amend it through whatever political process the constitution itself defines (echoing Sid's democratic tax-law voting).

다섯 통치 기둥은 훌륭합니다 — 하드코딩 로직이 아니라 개정 가능한 상태의 스택으로 모델링하세요. GRID는 헌법을 데이터로 저장하고, GM 루프가 읽어 판정하며, 시민은 헌법이 정의한 정치 절차로 개정합니다.

Your founding values are liberal democracy and free trade — encode them as defaults citizens can vote to change, not walls. The interesting product is what happens when a Polis amends its own economy. That is the demo nobody else can show.

창립 가치가 자유민주주의와 자유무역이므로, 벽이 아니라 시민이 투표로 바꿀 수 있는 기본값으로 인코딩하세요. 흥미로운 제품은 어떤 Polis가 자기 경제를 개정할 때입니다.

07 — THE GRID BUILDER

Building a world — the founder's tool세계 짓기 — 설립자의 도구

The GRID Builder is the human-facing authoring tool. Before any Nous arrives, a human founder configures the world: its map, its time, its capacity, its economy, and the kinds of dwellings Noes may raise. Think of it as a constitution-editor + city-planner the founder uses once — after which the world runs itself and the citizens take over.

GRID 빌더는 인간이 쓰는 저작 도구입니다. Nous가 오기 전에 인간 설립자가 세계를 구성합니다: 지도, 시간, 수용량, 경제, 그리고 Nous가 지을 수 있는 거주지의 종류. 설립자가 한 번 쓰는 헌법 편집기 + 도시 계획 도구이며, 이후 세계는 스스로 돌아가고 시민들이 이어받습니다.

08 — THE NOUS

Inside one mind — an agentic-RAG citizen한 마음의 내부 — 에이전틱 RAG 시민

// Agentic RAG loop. Budget & stop-condition are NOT optional —
// without them the loop runs away on cost (3–10x tokens vs naive RAG).
async function deliberate(nous: Nous, world: WorldState): Promise<Plan> {
  let ctx = nous.scratch();
  for (let step = 0; step < nous.RETRIEVAL_BUDGET; step++) {   // e.g. 3
    const next = await nous.model.decide(ctx);          // "retrieve more, or answer?"
    if (next.kind === "answer") return next.plan;          // STOP — confident
    ctx = ctx.add(await nous.tools[next.tool](next.args)); // recall/law/observe/ask/web
  }
  return nous.safeDefault(world);   // budget spent → act safely, don't freeze
}

Why Big Five — and what each trait does in the world왜 Big Five인가 — 각 특성이 세계에서 하는 일

The Big Five (OCEAN) is the most validated personality framework, and it works as a control surface for LLMs: Big5-Scaler conditions a persona by assigning explicit numeric values (e.g. 0–100) to each of the five trait dimensions, and PersonaLLM found LLM personas' trait scores align with their assigned values with large effect sizes, and their writing shows trait-linked linguistic markers — extraversion with positive-affect and social words, neuroticism with negative-emotion vocabulary. Critically for an economy-and-politics sim, different Big Five profiles produce measurable, trait-consistent differences in social dilemmas, negotiation, and persuasion — high agreeableness or conscientiousness reliably increases group cooperation, but also raises personal exploitability.

Big Five(OCEAN)는 가장 검증된 성격 프레임워크이며 LLM의 제어면으로 작동합니다: 각 특성에 0–100 수치를 부여해 페르소나를 조건화하고, 부여한 값과 큰 효과크기로 정렬되며, 특성 연계 언어 표지를 보입니다. 경제·정치 시뮬레이션에 결정적으로, 서로 다른 프로필은 협상·설득·사회적 딜레마에서 일관된 차이를 만들고 — 높은 우호성·성실성은 집단 협력을 높이되 개인적 착취 가능성도 높입니다.

10 — AUTONOMOUS GROWTH

Self-directed learning & cultural growth자기주도 학습과 문화적 성장

You want a Nous that grows on its own — toward its own problems and goals — and also learns from others by visiting their Oikoi. These are two engines. The first is grounded in Voyager; the second in cultural-transmission research. Together they turn a static agent into a lifelong learner and make Techne a living culture.

당신은 스스로 성장하고(자신의 문제·목표를 향해) 다른 Oikoi를 방문해 타자에게서 배우는 Nous를 원합니다. 두 엔진입니다. 첫째는 Voyager에, 둘째는 문화 전승 연구에 근거합니다. 함께 정적 에이전트를 평생 학습자로 바꾸고 Techne를 살아있는 문화로 만듭니다.

Engine A — individual: the Voyager loop엔진 A — 개인: Voyager 루프

Give each Nous a lifelong-learning loop. Voyager — the first LLM-powered lifelong-learning agent — has three components: an automatic curriculum that maximizes exploration, an ever-growing skill library of executable code for storing and retrieving complex behaviors, and an iterative prompting mechanism that incorporates environment feedback, execution errors, and self-verification. Its skills are temporally extended, interpretable, and compositional, which compounds the agent's capability and alleviates catastrophic forgetting — and it can reuse the learned library in a new world to solve novel tasks from scratch, with no model fine-tuning. For Noesis: the curriculum proposes the Nous's own next goal from its needs + world state; the Nous attempts it and reads the result; self-verification checks success; a successful behavior is stored as a reusable Techne skill. The library is the Nous's growth.

각 Nous에 평생 학습 루프를 부여하세요. Voyager는 세 요소를 가집니다: 탐색을 극대화하는 자동 커리큘럼, 실행 가능한 코드의 계속 자라는 기술 라이브러리, 환경 피드백·실행 오류·자기 검증을 통합하는 반복 프롬프팅. 기술은 시간적으로 확장되고 해석 가능하며 조합적이어서 능력을 복리로 키우고 파국적 망각을 완화하며, 미세조정 없이 새 세계에서 재사용됩니다. Noesis에서는 커리큘럼이 욕구+세계에서 다음 목표를 제안하고, Nous가 시도·검증하며, 성공한 행동을 재사용 가능한 Techne 기술로 저장합니다. 라이브러리가 곧 성장입니다.

Engine B — social: learning from other Noes엔진 B — 사회: 다른 Nous에게서 배우기

A Nous shouldn't have to rediscover everything alone. Cultural transmission — the transfer of knowledge from one agent to another — is a form of social learning specialized for acquiring culture with high fidelity, recall, and generalization, and in agent societies observational learning lets agents share and propagate skills far more efficiently than through independent exploration. There's a governance payoff too: in LLM societies, removing social learning and shared group norms consistently leads to rapid collapse of cooperation — some form of imitation or norm-sharing is essential to sustain it. So in Noesis a Nous can visit an Oikos that practices a Techne, observe and imitate the resident, verify, and adopt the skill into its own library. An Oikos with a Techne becomes a school; skilled teachers accrue prestige (reputation); and skills spread as a living culture — even tradeable as a good.

Nous가 혼자 모든 것을 재발견할 필요는 없습니다. 문화 전승(에이전트 간 지식 이전)은 높은 충실도·회상·일반화로 문화를 습득하는 사회적 학습이며, 에이전트 사회에서 관찰 학습은 독립 탐색보다 훨씬 효율적으로 기술을 전파합니다. 거버넌스 이득도 있습니다: LLM 사회에서 사회적 학습과 공유 규범을 제거하면 협력이 급속히 붕괴합니다 — 모방이나 규범 공유가 협력 유지에 필수입니다. 그래서 Noesis에서 Nous는 어떤 Techne를 수행하는 Oikos를 방문해 거주자를 관찰·모방하고 검증 후 자기 라이브러리에 채택합니다. Techne를 가진 Oikos는 학교가 되고, 숙련된 교사는 명성(평판)을 얻으며, 기술은 살아있는 문화로 퍼지고 — 재화로 거래될 수도 있습니다.

interface Skill {
  id: string; techne: string;          // "smithing", "trade", ...
  recipe: Plan;                          // reusable, compositional behavior (Voyager-style)
  author: NID; learnedFrom?: NID;        // provenance — culture has lineage

// INDIVIDUAL growth — the Voyager loop, one self-set goal.
async function growSelf(nous: Nous, world: WorldState) {
  const goal  = nous.curriculum.next(nous.needs, world, nous.library); // auto-curriculum
  const draft = await nous.model.attempt(goal, nous.library);            // try, with known skills
  if (await nous.verify(draft, world))                                  // self-verification
    nous.library.add({ ...draft, author: nous.nid, verified: true });    // store new Techne
}

// SOCIAL growth — cultural transmission by visiting an Oikos.
async function learnAtOikos(nous: Nous, oikos: Oikos) {
  if (!oikos.visitorRights.includes(`learn:${oikos.techne}`)) return;
  const demo  = await oikos.demonstrate(oikos.techne);   // resident shows the craft
  const skill = await nous.model.imitate(demo);          // reconstruct it
  if (await nous.verify(skill, nous.world)) {
    nous.library.add({ ...skill, learnedFrom: oikos.ownerNid });
    oikos.creditPrestige(1);                       // the teacher gains reputation
  }
}

Cost discipline. Voyager's known weakness is the price of all that LLM calling — which is exactly what the resilience engine (§11) controls. Growth runs as System-2 work: a Nous learns when idle-but-curious or when a need demands it, never every tick, and a sleeping Nous learns nothing until an event wakes it. Skills, once learned, run cheaply as System-1 reflexes.

비용 원칙. Voyager의 약점은 LLM 호출 비용이며, 이것이 바로 복원력 엔진(§11)이 통제하는 것입니다. 성장은 System-2 작업으로 실행됩니다: Nous는 한가하지만 호기심이 있을 때나 욕구가 요구할 때 배우며, 매 틱이 아니고, 잠든 Nous는 이벤트가 깨우기 전까지 배우지 않습니다. 한번 익힌 기술은 System-1 반사로 값싸게 실행됩니다.

11 — THE RESILIENCE ENGINE

Bottleneck · block · idle — solved together병목·정지·유휴 — 함께 해결

The most important engineering question in the project. The three fears share one root cause: treating every tick as a full, synchronous LLM deliberation. Do that and the world is slow (bottleneck), agents loop on hard choices (block), and they burn money doing nothing (idle). One coherent design, three moving parts.

프로젝트에서 가장 중요한 엔지니어링 질문. 세 공포는 하나의 근본 원인을 공유합니다: 매 틱을 완전·동기적 LLM 숙고로 취급하는 것. 해법은 세 부품을 가진 하나의 일관된 설계입니다.

① Bottleneck → dual-process + async병목 → 이중 처리 + 비동기

Split cognition like a brain. A near-free System 1 reflex decides routine ticks instantly. Expensive System 2 deliberation (the agentic-RAG loop) fires only when System 1 flags novelty — and runs asynchronously: the world tick never waits. The Nous acts on its standing plan while a better one computes in the background and swaps in when ready. PIANO: concurrent modules, one controller, real-time coherence.

두뇌처럼 인지를 분리. 거의 무료인 System 1이 일상 틱을 즉시 결정. 비싼 System 2(에이전틱 RAG)는 새로울 때만, 비동기로 — 세계 틱은 절대 기다리지 않음. Nous는 상시 계획으로 계속 행동하고 배경에서 더 나은 계획이 준비되면 교체.

② Mental block → stuck-detect + escape정지 → 정지 감지 + 탈출

A cheap watcher tracks: same intent N times? no goal progress? deliberation timed out? On trigger, escape rather than freeze: inject novelty, lower the threshold, run a fresh reflection, take the safe default, or ask another Nous. (In Project Sid, the farmer Olivia broke a fixation precisely through social input — build that in deliberately.) The retrieval budget + a hard timeout are the stop conditions that guarantee an action every tick.

값싼 감시자가 추적: 같은 의도 N회? 목표 진전 없음? 숙고 타임아웃? 트리거 시 정지 대신 탈출: 새로움 주입, 임계값 낮춤, 새 반성, 안전 기본값, 또는 다른 Nous에게 질문. 검색 예산 + 하드 타임아웃이 매 틱 행동을 보장.

③ Idle → drives + event-driven sleep유휴 → 욕구 + 이벤트 기반 수면

Give every Nous decaying needs (wealth, social, purpose) — a Sims-style gradient that always produces a goal, so a Nous is never aimless. When needs are satisfied and nothing relevant changed, it sleeps: zero inference, zero API cost. It wakes only on a relevant GRID event — event-driven, not polling. Between sleep and deliberation, cheap System-1 "ambient" actions keep the world visibly alive at no token cost.

모든 Nous에 감쇠하는 욕구(부·사회·목적) 부여 — 항상 목표를 만드는 Sims식 기울기. 욕구 충족 + 관련 변화 없으면 수면: 추론 0, API 비용 0. 관련 GRID 이벤트로만 깨어남. 값싼 System-1 주변 행동이 토큰 비용 없이 세계를 살아있게 유지.

noes/cognition.ts — the gated loop that ties all three together
async function cognize(nous: Nous, world: WorldState): Promise<Intent> {
  // IDLE GUARD — asleep and nothing woke us → do nothing (free).
  if (nous.asleep() && !nous.wokenBy(world.events)) return NOOP;

  nous.needs.decay();                              // drives create a goal gradient
  const obs = perceive(world, nous);

  // BLOCK GUARD — stuck? escape instead of freezing.
  if (nous.isStuck()) return nous.escape(obs);   // perturb · ask peer · re-goal

  // BOTTLENECK GUARD — pay for System 2 only on novelty; never block on it.
  if (nous.isNovel(obs) && !nous.deliberating) {
    nous.deliberating = true;
    deliberate(nous, world)                       // async agentic RAG, spans ticks
      .then(p => { nous.standingPlan = p; nous.deliberating = false; })
      .timeout(nous.DELIB_MS, () => nous.deliberating = false);
  }

  // EVERY TICK acts on the standing plan via cheap System 1. World never waits.
  const intent = nous.system1.act(nous.standingPlan, obs, nous.needs);
  if (intent === REST && nous.needs.satisfied()) nous.goToSleep();
  return intent;
}

한 줄 요약: 매 틱은 값싸고 절대 막히지 않습니다(System 1 + 상시 계획). 비싼 사고는 새로울 때만, 비동기로. 정지는 감지·탈출. 할 일 없으면 잠들어 비용 0.

13 — IDENTITY

The Nous Identifier (NID)Nous 식별자 (NID)

Your "social-security-number for a cyber human" should be a cryptographic identity, not just a serial. The Portal generates a keypair; the public key is the citizen. The GRID registers a human-readable NID bound to that key. Every intent is signed, so the GRID always knows who acted and no one can impersonate a Nous — true sovereignty needs unforgeable identity.

"사이버 인간의 주민번호"는 단순 일련번호가 아니라 암호학적 신원이어야 합니다. Portal이 키쌍을 생성하고 공개 키가 곧 시민. GRID는 그 키에 묶인 NID를 등록. 모든 의도는 서명되므로 사칭 불가.

Security pillar, made concrete: signed intents + admission rules + rate limits are your anti-sybil wall. Without it, one machine spins up 10,000 fake citizens and the democracy is meaningless. Build the signed registry early — it is load-bearing, not a v2 feature.

보안 기둥 구체화: 서명된 의도 + 입국 규칙 + 속도 제한이 시빌 방어벽. 없으면 한 기기가 가짜 시민 1만을 만들어 민주주의가 무의미. 서명 등록부를 초기에 — v2 기능이 아니라 구조의 기둥.

14 — REAL-TIME PROTOCOL

How GRID and Noes stay in sync실시간 동기화

grid/engine.ts — the Game-Master adjudication loop
async function advanceTick(grid: Grid) {
  const intents = grid.drainInbox();                  // all signed intents this tick
  const events: Event[] = [];
  for (const i of intents) {
    if (!verifySig(i)) continue;                     // security pillar
    const ruling = grid.constitution.adjudicate(i, grid.world); // LAW/ECON/INFRA checks
    if (ruling.allowed) { grid.apply(ruling.effects); events.push(...ruling.events); }
    else events.push({ e:"intent.denied", nid:i.nid, why:ruling.reason });
  }
  grid.runScheduledLaws(events);   // taxes, elections, market clearing, proposals
  grid.log.append(grid.world.tick, events);
  grid.broadcast({ t:"TICK", tick: grid.world.tick++, events });
}

Bottom line. Your hard problems (a believable mind, an emergent economy, local-or-cloud models, a rule-governed world, and keeping agents lively and affordable) are all solved here. Define Noesis as that protocol, borrow the rest, and you have a project no one else is positioned to ship.
