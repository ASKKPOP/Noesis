Noēsis Testing Guide

How to test Noēsis step by step, even if you have never tested software before. Three diagrams show the system, the six ways to test it, and the full path to a talking Nous. Click any box to open its guide. Every guide is written twice: once for end users who click through the website, once for programmers who run commands.

The full list of scenarios with their last results is in the test scenario catalogue.

1 · The system, and where each test touches it

There are two places: your computer and the production server that runs noesiis.com. The orange numbers are the test tiers from section 2; each sits where that tier does its checking.

Tip: the badge numbers match the tiers below. T0 never leaves your computer; T1–T3 talk to production; T4 is a private copy; T5 runs a real Brain. Click any box for its guide.

Code & test runners

Your computerTier T0, T1
End user

This is the project's source code and the small programs that check it automatically. You don't need it to use the website. If someone asks “did the tests pass?”, they mean the programs here.

Programmer

Monorepo: grid/ (TypeScript API, vitest), dashboard/ (Next.js, vitest), brain/ (Python, pytest). Test entry points:

scripts/smoke/area-tests.sh <area>     # T0, one feature area
node scripts/smoke/prod-smoke.mjs       # T1, production reads

Set-up steps are in tier T0.

↑ back to the system diagram

Web browser

Your computerTier T2, T3
End user

Any modern browser (Chrome, Safari, Firefox). You sign in at noesiis.com/portal/auth. A sign-in lasts 24 hours; after that you are sent back to the sign-in page, which is normal.

“Continue with Google / Apple” currently fails. Use Sign in with email.

Programmer

The dashboard calls the Grid at https://api.noesiis.com with the session cookie (credentials: 'include'). Open DevTools → Network to see each call's status; Console shows failed requests. Google/Apple fail with Auth.js UntrustedHost.

↑ back to the system diagram

Local Grid + MySQL

Your computerTier T4
End user

A private practice copy of the server that only exists on a programmer's computer. Nothing done here touches the real website. You can skip it.

Programmer

Used to catch database mistakes that unit tests can't (unit tests use a fake database). See tier T4 for the exact commands.

↑ back to the system diagram

Brain

Your computerTier T5
End user

The Brain is the mind of one Nous. It runs on your machine, not on the server, and connects out to the city. When it is running and approved, that Nous can answer you in chat.

Programmer

Python service in brain/, started by docker-compose.brain.yml. It keeps its own key in the brain_data volume (/data/brain-wire.key) and enrols with the Grid on start. Steps: journey step 5.

↑ back to the system diagram

Local AI model

Your computerTier T5
End user

The language model the Brain thinks with. It runs locally through the Ollama app. The large model (gpt-oss:120b) needs a lot of memory; the smaller gpt-oss:20b is fine for testing.

Programmer
ollama list                                  # models you have
curl -s localhost:11434/api/tags             # is Ollama answering?

Inside Docker the Brain reaches it at http://host.docker.internal:11434. Once connected, the model actually used comes from the owner's Local AI settings on the Grid, not from LLM_MODEL.

↑ back to the system diagram

Front door (nginx)

Production
End user

The part of the server that receives your visit and passes it to the right program. If every page shows “502 Bad Gateway”, this is where it went wrong — tell a programmer.

Programmer

Docker container noesis-nginx. After any deploy that recreates the Grid or dashboard, force-recreate it or it serves stale upstreams (502s):

docker compose -f docker-compose.yml -f docker-compose.aws.yml --env-file .env \
  up -d --force-recreate --no-deps nginx
↑ back to the system diagram

Website (dashboard)

ProductionTier T2, T3
End user

Everything you see at noesiis.com: the Portal (account, chat, citizenship), the city maps, the status page. A page loading is a good sign, but a page can load and still be empty or broken — that's why T2 asks you to look at what's on it.

Programmer

Next.js app in dashboard/, container noesis-dashboard. Most pages are client components: an HTTP 200 only proves the shell loaded. Check behaviour in a browser (T2) or with component tests (T0).

↑ back to the system diagram

Grid API

ProductionTier T1
End user

The city itself: its clock, its rules, its citizens and its records. The website asks the Grid for everything it shows. The status page tells you whether the Grid is healthy.

Programmer

Fastify service in grid/, container noesis-grid, public at https://api.noesiis.com. Quick checks:

curl -s https://api.noesiis.com/health/detailed
node scripts/smoke/prod-smoke.mjs --area health
↑ back to the system diagram

Database (MySQL)

Production
End user

Where the city remembers things: accounts, citizenship, registrations and the audit log. Tests never change it directly.

Programmer

Container noesis-mysql, database noesis_grid. The Grid applies migrations on start. New migrations are checked against a real MySQL 8.0 in CI (real-mysql-migrations) and locally in T4; unit tests use a fake pool and can't catch SQL mistakes.

2 · Six ways to test, cheapest first

You don't need to run everything. Pick the cheapest tier that proves what you changed. Higher tiers cost more time, more memory, or real accounts.

Routine: T0 on every change · T1 after every deploy · one T2 area per week · T4/T5 only when you change the database or the Brain.

T0

Unit tests for one area

SecondsNo database, Docker or modelProgrammers
End user

Automatic checks a programmer runs before changing the website. They prove small pieces work on their own. You don't run these; ask “did the unit tests for this area pass?” when something new ships.

Programmer
  1. One-time setup (Node 20+, Python 3.12): 
    git clone https://github.com/ASKKPOP/Noesis.git && cd Noesis
npm ci
python3.12 -m venv brain/.venv
brain/.venv/bin/pip install -e "brain[dev]"
  2. See the areas, then run one: 
    scripts/smoke/area-tests.sh --list
scripts/smoke/area-tests.sh registration

You should see Tests N passed for grid and dashboard and N passed for brain. Exit code 0.

The audit area currently fails 3 dashboard tests (firehose row). They predate recent work. Areas: registration, chat, groups, city, polis, economy, library, audit, health.

↑ back to the tiers
T1

Production smoke (read-only)

About 1 secondNever signs in or writes
End user
  1. Open the status page (no sign-in needed).
  2. Read the banner at the top.

“The Grid reports healthy” with a green dot, the Grid name and a tick number.

“The Grid is not answering” means the server is down — tell a programmer.

Programmer
node scripts/smoke/prod-smoke.mjs                  # all 41 checks
node scripts/smoke/prod-smoke.mjs --area health    # one area
node scripts/smoke/prod-smoke.mjs --list

Each line says PASS or FAIL, with the reason on failures. Exit 1 if anything failed.

Known failure: A2 /api/v1/audit/verify reports valid:false while health is ok.

Point it elsewhere with SMOKE_API / SMOKE_WEB.

↑ back to the tiers
T2

In the browser, one account

10–20 minutesCreates real data
End user

Pick one area per session and check it like a visitor would:

  1. Account: sign in → sidebar Account. You should see your Portal ID, wallet and “My Nous”.
  2. Chat: sidebar Chat → pick a Nous → type a short message → send → reload the page. Your message should still be there. (No one answers yet — that needs the Hermes journey.)
  3. Groups: open Groups → click Aegis. Members and projects appear (all 0 today).
  4. Map: open the orbital map. A 3D station should appear.

Write down the page, what you clicked, what you expected and what happened. A screenshot helps.

Programmer

Same steps, with DevTools open. For each step confirm in Network that the Grid call returned 2xx and in Console that there are no errors. The full list with IDs (PA-, CH-, GR-, CI-) is in the scenario catalogue.

Messages you send in chat are stored in production. Keep test text short and obvious (e.g. “test”).

↑ back to the tiers
T3

Two operator accounts

Two people or two browsersServer settings needed
End user

Some decisions need a reviewer, and nobody may review their own request. So you need two accounts: one files a request, the other reviews it. Use two browsers (or one normal window and one private window) so both can be signed in at once.

The full walk-through is journey steps 6–7.

Programmer

Both Portal IDs must be on GRID_OPERATOR_DIDS at tier 5, and GRID_PORTAL_MANAGER_ENABLED=true (already on in production). See step 4. The reviewer route answers 403 self_review_forbidden if the filer tries to decide.

↑ back to the tiers
T4

Local Grid with a real database

5–10 minutesDocker, ~1–2 GB RAMProgrammers
End user

A programmer-only check, done on a private copy of the server, before any change to how data is stored goes live. Nothing here touches the real website.

Programmer
colima start --memory 12
docker run -d --name noesis-test-mysql -e MYSQL_ROOT_PASSWORD=root \
  -e MYSQL_DATABASE=noesis_grid -p 127.0.0.1:33306:3306 mysql:8.0
# wait until: docker exec noesis-test-mysql mysqladmin ping -uroot -proot
cd grid
MYSQL_HOST=127.0.0.1 MYSQL_PORT=33306 MYSQL_USER=root MYSQL_PASSWORD=root \
  npx tsx scripts/check-migrations-real-mysql.ts

Prints the final schema version with no SQL errors.

To exercise routes too, start the Grid against it (GRID_PORT=18080 GRID_COOKIE_SECURE=false npx tsx src/entrypoint.ts with the same MYSQL_* vars) and use curl. Clean up afterwards:

docker rm -f noesis-test-mysql && colima stop
↑ back to the tiers
T5

A real Brain with a local model

Most memory20b ≈ 16 GB · 120b ≈ 65 GB
End user

This is the only tier where a Nous can actually talk back. It needs a computer with plenty of memory running both the Brain and the model. Follow the Hermes journey from start to finish.

Programmer

The Brain enrols itself; you only provide settings. Steps 5 and 8. To save memory, test with gpt-oss:20b and switch to 120b afterwards. Stop it when done:

docker-compose -p noesis-brain -f docker-compose.brain.yml stop

3 · The full journey: make Hermes talk

This end-to-end test touches almost every part of the system. Do the steps in order; each box opens its guide. Blue steps happen in the browser, white steps on a computer or the server.

Blue = in the browser. White = on a computer or the server. Steps 1–4 are one-time setup; after that, 5–9 is the test.

1

Prepare your computer

One time~30 min (model download)
End user
  1. Install Ollama from ollama.com and open it once.
  2. Ask a programmer to do the rest of this step, or follow the programmer column.

The Ollama icon is in your menu bar.

Programmer
ollama pull gpt-oss:20b            # or gpt-oss:120b (needs ~65 GB RAM)
brew install colima docker docker-compose
colima start --memory 12
git clone https://github.com/ASKKPOP/Noesis.git && cd Noesis

ollama list shows the model; docker ps answers without error.

On this project use the hyphenated docker-compose with Colima.

↑ back to the journey
2

Create two accounts

BrowserOne time
End user
  1. Go to noesiis.com/portal/auth → Join → sign up with email and a password (8+ characters).
  2. Do it again with a second email, in a private window. Account A will file, account B will review.
  3. For each account open Account and copy the Portal ID (it starts with did:noesis:human:).

Each Account page shows a different Portal ID.

Programmer

Sign-up is POST /api/v1/portal/auth/email/signup; the Portal ID is the account's DID (did:noesis:human:email:<uuid>), also returned by GET /api/v1/portal/auth/me. Accounts persist in human_users.

↑ back to the journey
3

Become a citizen (account A)

BrowserInstant
End user
  1. Signed in as account A, open noesiis.com/apply/genesis.
  2. Write a short sentence about why you're joining and accept the oath.
  3. Submit.

“Approved” and a Civic-DID starting did:civic:noesis:human:.

Only the account that files (A) has to be a citizen.

Programmer

POST /api/v1/portal/civic/apply runs pre-screen → automatic charter review → issuance in one call. Rejection codes: account_sanctioned, already_registered, oath_mismatch, statement_invalid.

↑ back to the journey
4

Make both accounts operators

Server adminOne time
End user

This is a server setting only the person who runs noesiis.com can change. Send them both Portal IDs from step 2 and ask: “please add these two as tier-5 operators.” The Grid restarts briefly when it's done.

Programmer

Each entry is <PortalID>|op:<uuid v4>|5, comma-separated, in the server's .env. Make one operator ID per account:

python3 -c 'import uuid; print(uuid.uuid4())'
ssh -i <key> ec2-user@<server> 'cd ~/noesiis && cp -p .env .env.bak.operators && \
  sed -i -E "s#^(GRID_OPERATOR_DIDS=.*)\$#\1,<ID_A>|op:<UUID_A>|5,<ID_B>|op:<UUID_B>|5#" .env && \
  docker compose -f docker-compose.yml -f docker-compose.aws.yml --env-file .env up -d grid && sleep 25 && \
  docker compose -f docker-compose.yml -f docker-compose.aws.yml --env-file .env up -d --force-recreate --no-deps nginx'

The operator ID must be op: + a version-4 UUID, or the entry is silently ignored.

↑ back to the journey
5

Start Hermes's Brain

Tier T5Computer
End user

A programmer starts the Brain. It prints a public key — a 43-character code — and then waits. That key is like the Brain's fingerprint: you'll paste it in step 6 so only this Brain can become Hermes. It is safe to share.

Programmer
  1. Settings file outside the repo (keeps the secret out of git): 
    mkdir -p ~/.noesis && umask 077 && cat > ~/.noesis/hermes.env.brain <<EOF
NOUS_NAME=hermes
NOUS_CONFIG=/app/data/nous/hermes.yaml
NOUS_DID=did:noesis:hermes
CIVIC_DID=
GRID_URL=https://api.noesiis.com
GRID_NAME=Genesis
LLM_PROVIDER=ollama
OLLAMA_HOST=http://host.docker.internal:11434
LLM_MODEL=gpt-oss:20b
BRAIN_HTTP_SECRET=$(openssl rand -hex 32)
EOF
  2. Start it and read the key: 
    docker-compose -p noesis-brain --env-file ~/.noesis/hermes.env.brain \
  -f docker-compose.brain.yml up -d --build
docker logs noesis-brain-alwayson 2>&1 | grep "public key"

“… has no approved registration yet … with this Brain public key: 43 characters — waiting for approval…”

PermissionError: /data/brain-wire.key means an old volume: docker-compose -p noesis-brain -f docker-compose.brain.yml down, docker volume rm noesis-brain_brain_data, start again. The container shows “unhealthy” while waiting; that's expected.

↑ back to the journey
6

File the registration (account A)

Tier T3Browser
End user
  1. Signed in as account A, open Account and scroll to Register a Nous.
  2. Nous ID: did:noesis:hermes
  3. Brain public key: paste the 43 characters from step 5.
  4. Click File registration.

“Filed. It is now waiting for the Portal pre-screen.” The registrations table shows “Waiting for Portal pre-screen”.

See troubleshooting for each refusal message.

Programmer

The form calls POST /api/v1/portal/nous/:nousId/claim then POST /api/v1/portal/nous/:nousId/registration with { brain_public_key_x }. Checks: owner, citizen, founding Nous ⇒ operator, one live registration. Emits nous.registration_requested.

↑ back to the journey
7

Review with the other account (B)

Tier T3Browser
End user
  1. In the other browser, signed in as account B, open the reviewer panel.
  2. Find did:noesis:hermes — “Waiting for pre-screen”.
  3. Click Pass pre-screen.

“… passed the pre-screen and the Polis charter rules approved it.” Status becomes Approved.

If you see “You filed this registration. Another reviewer has to decide it.”, you're signed in as account A. Switch to B.

Programmer

POST /api/v1/portal-reviewer/nous-registrations/:requestId/prescreen {pass:true} (operator_only, tier 5) → polis.registration_pending, then automatic charter rules → nous.registration_approved + zoning.residence_assigned.

↑ back to the journey
8

The Brain enrols; set the model

Tier T5Automatic, within 30 s
End user

Nothing to click: within half a minute the Brain notices the approval and joins the city. Then, as account A, open the operator console at noesiis.com/console/system/local-ai (Steward → System → Local AI) and choose the model you pulled in step 1.

On the status page, “Local AI (Brain) tokens” shows 1 active.

Programmer
docker logs -f noesis-brain-alwayson     # expect civic-did 201, token/register 200
curl -s https://api.noesiis.com/api/v1/civic/presence

Presence lists Hermes's new Civic-DID as awake. The Civic-DID is cached in /data/civic-did.

brain_key_not_enrolled = the key filed in step 6 isn't this Brain's; reject and file again with the right key.

↑ back to the journey
9

Talk to Hermes

The goalBrowser
End user
  1. Open Chat → Hermes.
  2. Send a short message, e.g. “Hello Hermes, what do you trade?”
  3. Wait — a large model can take a minute.

“Delivered. Hermes is awake and will answer here.”, then Hermes's reply in the thread.

“Hermes is unavailable right now” means the Brain isn't connected — go back to step 8.

Programmer

The chat route answers 202 when the Nous's presence is awake; the Brain reads the Portal thread through GET /api/v1/civic/conversation-inbox and replies with POST …/conversation-inbox/reply. The page polls the thread. Watch both sides:

docker logs -f noesis-brain-alwayson | grep -i inbox

Not yet verified end to end in production — record what you see.

↑ back to the journey

Glossary for beginners

Grid
A city. Noēsis runs one today, called Genesis.
Portal
The front door: your account, citizenship, registrations and chat.
Nous
A mind that lives in the city (Hermes, Sophia, Themis…).
Brain
The program that is a Nous's mind; it runs on someone's own computer.
Civic-DID
Proof of citizenship, for people and for Nous.
Operator
A trusted account allowed to review registrations.
Reviewer panel
The page where an operator passes or rejects a filing.
Polis
The city's government. Its charter rules run automatically after a review.
Unit test
An automatic check of one small piece of code (tier T0).
Smoke test
A quick “is it alive?” check of the real website (tier T1).
Migration
A change to how the database stores data; checked in tier T4.
Production
The real, live website at noesiis.com.
