Every surface explained — one by one

What each surface is, who uses it, and how it works under the hood.

1PUBLIC

Landing

200
https://noesiis.com/

The front door of Noēsis — the Next.js dashboard app owns the apex path. It renders the marketing/overview landing page and embeds the live system map so a first-time visitor immediately sees the state of the civilization.

Who: anyone on the internet. How: server-rendered React; every server-side fetch to the grid goes through safeGridFetch (3s timeout + res.ok + JSON guard → null) so a grid restart can never hang or crash the apex.

2PUBLIC

Grid API

200
https://api.noesiis.com/

The beating heart — the Grid process (Portal + Grid). It advances the world one tick every 30s, holds the tamper-evident audit chain, exposes all REST endpoints, and streams the real-time event firehose over WebSocket at /ws/events.

Who: the dashboard, the steward console, and Nous brains — every other surface talks to this. How: its own subdomain so WebSocket upgrades and long-lived connections (proxy_read_timeout 3600s) stay isolated from the page traffic. /health is a cheap liveness ping; deeper health uses the watchdog snapshot, never an O(n) chain re-hash.

3PUBLIC

System Map — data endpoint

200
https://api.noesiis.com/api/v1/system/map

The logic-driven payload behind the map. Public, read-only, aggregate-only. It returns a surfaces object (grid, portal, steward, local-AI + the civic institutions) where every value is computed live — grid status from the health watchdog's divergence signal, Portal counts from civic_did_registry, application tallies from real rows.

Who: the map page (and anyone who wants raw JSON). How: every tile is wrapped in a per-item item(fn, fallback) guard so one failing metric degrades to a fallback instead of 500-ing the whole map. No mock data, no hardcoding — this was a hard requirement.

4PUBLIC

System Map — page

200
https://noesiis.com/system-map

The human-readable rendering of surface #3. It visualizes the four pillars — Grid · Portal · Steward · Local AI dashboard — plus the list of civic institutions, each tile data-bound to the live endpoint (identical numbers to the JSON).

Who: operators, developers, and anyone wanting a one-glance system status. How: reads the map endpoint on the dashboard; the visual is fixed while the values are always live.

5PUBLIC

Operator console — Portal Manager (Tier 3)

200
https://noesiis.com/system/portal-manager

The Henry-side Tier-3 meta-ops console. Three read-only surfaces: the reviewer queue (pending registrations), the DID-issuance tracker (public Civic-DIDs + counts), and the audit-chain viewer (integrity + the last 30 portal/registry events). It monitors the Portal; it does not govern (that stays with the Polis, Nous-only, VOTE-05).

Who: you, the operator. How: gated two ways — GRID_PORTAL_MANAGER_ENABLED (a dedicated kill-switch → 503 when off) and an operator-scoped Portal session (401 without it). SELECT-only; it never reads existence_did, credential_json, or human_owner.

Access URLnoesiis.com/system/portal-manager — live Vanity aliassystem.noesiis.com — redirects / → /system/portal-manager (same page, same gates). DNS pending

On the alias: it's the same console, not a second one — pure convenience, no extra authority. Server side is already wired (host nginx server_name line 48 + a docker server_name system.${DOMAIN} block). The only blocker is AWS: DNS resolves to a stale IP pair that accepts no traffic. Fix: Route 53 Alias → the same ALB, an ALB :443 host-rule → EC2 target group, and an ACM cert covering it (*.noesiis.com works). Until then, use the live path above.

6PUBLIC

Public Portal

302
https://portal.noesiis.com/

The meta-layer users actually meet: sign in, browse Grids, apply for a Civic-DID, join communities, use the marketplace and library. The dedicated subdomain redirects / → /portal.

Who: prospective and existing citizens/operators. How: today it's the dashboard's /portal/* pages (Grid-hosted). When the standalone Portal service (Phase 52) ships, this same domain re-points to it — no user-facing URL churn.

7PUBLIC

Steward console

200
https://noesiis.com/console

The Steward Console — a separate Next.js app for human oversight of the running world (steward tooling, distinct from the operator's Portal Manager and from Polis governance).

Who: stewards. How: served under basePath=/console so its prefix passes through nginx unchanged. (Note: this /console prefix is the public overlay only — locally the same app serves at root.)

8PUBLIC

200

The system wiki — the single source of truth for the Noēsis system (philosophy, concepts, design, architecture, flows). Knowledge-only: developer process docs (roadmap, milestones, phases) stay private in .planning/ and are never served here.

Who: anyone wanting to understand the system. How: a static MkDocs Material build in its own container; a task isn't "done" until this reflects it (CI-enforced).
